# 실시간 생성 미리보기 1차 구현 결과

작성일: 2026-11-16 (Asia/Seoul)

## 구현 범위

구성 승인 → 기존 미디어 생성·저장 → 노드별 표시 → 실제 이미지 로딩/디코딩 → 자동 품질검사·기존 출력 흐름에 미리보기 전용 표시 계층을 연결했다. 모델의 불완전한 JSON을 스트리밍하거나 표시 효과를 위해 추가 LLM 호출을 하지 않는다.

- 승인된 PageSchema의 텍스트·등록 스타일은 바로 표시하고, 준비 중인 이미지 영역만 스켈레톤으로 표시한다. 별도 고정 템플릿을 만들지 않는다.
- `page-media-preparation.mjs`의 진행 콜백에 실제 대상 노드·요청 ID를 추가했다. 기존 첫 인자인 남은 개수와 순차·재개 가능한 저장 흐름은 유지한다.
- 미디어 상태는 대기·생성 중·브라우저 로딩·준비 완료·실패로 구분한다. 등록 URL이 있다는 이유만으로 표시 준비 완료로 취급하지 않고 실제 로딩·decode 결과를 확인한다.
- 배경 이미지가 준비 중인 컨테이너는 전경 텍스트·카드를 중립 색상으로 표시해 로딩 배경과 글자가 겹쳐 안 보이는 문제를 방지한다. 준비 후 등록 스타일을 복원한다. 배경 이미지의 Reveal은 전체 이미지를 투명하게 숨기지 않는 짧은 초점 전환으로 적용한다.
- 완료 이미지는 유지하고 진행 중인 영역만 1.8초 로딩 효과를 표시한다. 새로 완성된 이미지에는 320ms Reveal을 한 번 적용한다. reduced motion에서는 효과를 재생하지 않는다.
- 초기 로드에서 이미 완료된 에셋과 탭 재마운트 후 완료 에셋은 Reveal을 재생하지 않는다. 화면 크기 전환·품질검사 후에도 동일 결과에 효과를 반복하지 않는다.
- 미디어 실패의 노드 ID를 기존 실패 작업 기록에 포함해 새로고침 후에도 대상 영역을 구분한다. 기존 기록에 ID가 없으면 해당 미디어 작업의 첫 대기 노드로 표시 호환을 유지한다.
- 격리된 iframe 안의 기존 Vue 렌더 트리를 유지한다. 미리보기 컨트롤러가 상태 속성과 전용 스타일만 관리하고 PageSchema·등록 토큰·에셋 데이터는 변경하지 않는다.
- 문서 전환 시 표시 캐시를 초기화하고, 지연된 이미지 이벤트가 현재 문서의 데이터나 상태를 덮지 않게 한다. 생성 응답에 대한 기존 문서·Revision 검증도 유지한다.
- 자동 검사 시 표시 계층과 효과를 제거하고 실제 결과를 측정한다. 검사 후에는 재생 없이 표시를 복원한다. 최종 렌더러·서버 HTML·SSR에 로딩 계층을 추가하지 않는다.
- 오른쪽 액션·별도 입력·강제 스크롤·확대·가짜 진행률은 추가하지 않는다. 진행·실패·재시도 안내는 기존 채팅을 사용한다.

## 주요 파일

- `visual-editor/src/builder/services/live-generation-preview.mjs`: 순수 영역 상태 계산 및 미리보기 전용 DOM 표시 컨트롤러.
- `CompositionPreviewCanvas.vue`: 표시 계층 생명주기, 품질검사 전후 격리.
- `CompositionReview.vue`, `AiBuilderApp.vue`: 승인 후 표시·실제 대상·실패 대상 전달.
- `page-media-preparation.mjs`: 기존 진행 콜백에 노드·요청 식별자 추가.

## 검증 결과

- Visual editor 및 Nuxt runtime 빌드 통과.
- `qa:design-preview`: 39개 계약·브라우저·PGlite 검사 통과.
- 신규 순수 상태 검사: 승인 전 미표시, 실제 작업·실패 대상, 완료 바인딩의 로딩 상태, 비율·안전 URL, snapshot 불변성.
- 신규 표시 컨트롤러 브라우저 검사: 실제 비동기 이미지 로드/decode, 대기·진행·실패, 비율에 따른 영역 높이 유지, 한 번의 Reveal, 검사 중 속성·스타일 제거, 모션 감소, 이미 완료된 다른 이미지 보존, 문서 ID 전환, 지연 로딩, 재마운트, 정리·해제 통과.
- 실제 빌더 브라우저 회귀 확장: 공급자 실패 시 해당 이미지 영역 실패 표시, 새로고침·채팅 재시도, 생성 중 표시, 완료 이미지·스타일·보더·아이콘·세 화면 품질검사 흐름 통과.
- 기존 HTML export·출력 격리 SSR, 자연어 수정·승인·자동 품질 에이전트 및 SQL 저장 회귀 통과.

실제 모델·Neon·Blob·Vercel Preview 통합 검증 및 Production 배포는 미수행이다. 로컬 fixture와 PGlite 결과를 실제 외부 서비스 검증으로 보고하지 않는다.

## 의도적으로 유지한 범위

- 작업은 기존 순차 이미지 생성 흐름을 사용한다. 병렬 생성·SSE/WebSocket·모델 토큰별 렌더링은 추가하지 않았다.
- 스켈레톤·Reveal은 PageSchema 디자인 미리보기에 적용한다. 기존 비-PageSchema 문서는 기존 렌더링을 유지한다.
- 이미지와 URL형 아이콘의 로딩을 표시한다. 문자형 등록 아이콘·이미 준비된 텍스트는 불필요하게 숨기지 않는다.
- API 응답은 검증·저장된 snapshot 단위로 적용한다. 브라우저 표시 상태 때문에 DB 마이그레이션이나 프롬프트를 새로 만들지 않았다.
- 생성 요청 자체의 성공, 실제 이미지 로딩 완료, 전체 품질검사 통과는 별개이며 출력 게이트를 완화하지 않는다.

## 후속 범위 보정

이미지 로딩 위주의 1차 구현은 요청한 전체 디자인 생성 과정을 충족하지 못했다. 후속 확정안과 실제 영역별 디자인 작업 구현·활성화 절차는 `live-generation-preview-v2-section-design.md`를 따른다. 새 흐름은 migration 093의 Admin 프롬프트와 `PAGE_SCHEMA_SECTION_DESIGN_ENABLED=true`가 필요하며, 위 1차 범위를 현재 최종 동작으로 간주하지 않는다.
