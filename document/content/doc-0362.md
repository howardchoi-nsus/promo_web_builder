## 3. 오늘 확정된 제품 기준

### 3.1 Section의 AI 기능

기존 `AI 디자인 생성` 명칭은 `AI 도우미`로 변경했다.

현재 구성:

1. `AI 도우미`
2. `AI 키비주얼 만들기`
3. 클릭 시 Accordion을 열고 디자인 요청 사항 입력
4. 위치는 Section명 하단, Section Component 목록 상단

제외한 기능:

- `AI 레이아웃 생성` 제거
- Section 속성에 중복 노출되던 `AI 키비주얼 생성` 제거

역할 구분:

- Section의 `AI 도우미`는 현재 편집 중인 Section의 키비주얼 생성 요청을 담당한다.
- Section Preset 관리의 `AI 페이지 구성 정책`은 AI가 페이지를 조립할 때 해당 Preset을 후보로 사용할 수 있는지와 용도를 정의한다.
- `AI 디자인 정책`은 AI가 Section의 배경·이미지 등 시각 결과를 생성할 수 있는 범위를 정의한다.

### 3.2 Template 저장과 활성화

사용자 혼선을 줄이기 위해 역할을 다음과 같이 정리했다.

- Live Preview의 편집 결과는 `초안 저장`만 수행한다.
- 기존 `저장 후 활성화` 버튼은 제거했다.
- 운영 사용 여부는 좌측 `활성화 템플릿` 목록의 `활성/비활성` 토글에서 지정한다.
- Visual Editor 정보 영역에도 초안 저장 후 좌측 토글에서 운영 반영한다는 안내를 표시한다.

활성화 검증은 계속 적용된다.

- 활성 Section version 필요
- 필요한 Section에는 최소 1개의 visible Component 필요
- 현재 default Template을 내리려면 다른 active default Template이 먼저 필요

### 3.3 Section Preset과 Layout Preset

제품 방향:

- 별도의 단순 Layout Editor 창을 유지하지 않는다.
- Template Layout과 Promotion Page Builder에서 사용하는 공통 Visual Editor를 Section Preset에도 사용한다.
- Preset 생성 후 Live Preview에서 시각 배치·크기·반응형 표시 상태를 수정한다.
- Preset의 활성/비활성, AI 정책, 삭제 등 관리 작업은 Section Preset 관리 화면에서 수행한다.

현재 구현 경계:

- 공통 Visual Editor에서 Component의 위치·크기·스타일·Desktop/Mobile visibility를 편집하고 Preset Layout으로 저장할 수 있다.
- Section/Component 구성원 자체의 추가·삭제는 아직 iframe 내부 Visual Editor의 저장 계약에 포함하지 않았다.
- Component 구성은 Section Preset 관리 화면에서 지정하고, 공통 Visual Editor는 저장된 구성의 Layout 편집을 담당한다.
- 향후 완전한 편집 경험이 필요하면 Preset 구조 저장 API와 Undo/Redo command를 공통 Editor에 추가해야 한다.

## 4. 주요 개발 반영 내용

### 4.1 Live Preview 상호작용 안정화

오늘 초반에는 Text, Image, CTA 선택·이동·Resize 오류를 집중 점검하고 보정했다.

주요 증상:

- 선택 해제가 간헐적으로 되지 않음
- Text가 pointer를 따라다니는 것처럼 보임
- Component 모서리 Resize 중 크기가 줄었다 늘었다 하며 번쩍임
- Image Resize가 Section 높이까지 움직임
- CTA 이동 불가 또는 위쪽 Resize가 Section을 늘림
- Text 선택과 크기 변경 충돌
- Section 높이를 빈 영역까지 충분히 줄일 수 없음

반영 원칙:

- pointer down과 실제 drag 시작을 threshold로 분리
- drag/resize 중 불필요한 reactive measurement write 억제
- fixed frame Image/CTA/Text Resize와 Section auto-height 계산 분리
- interaction 중 transform transition 제거
- native image/button drag 차단
- Text selection과 Component drag 우선순위 분리
- 빈 Section의 기본 `min-height`를 약 190px에서 50px로 조정

세부 디버깅 내용은 전일 handoff와 audit/plan 문서에 이어서 기록돼 있다.

### 4.2 Text 상단 Toolbar 정리

오른쪽 Component 설정에 있던 다음 Text 속성은 상단 Editor Toolbar에서 적용하는 방향으로 정리했다.

- Color
- Font size
- Font weight

Toolbar가 선택 상태에 따라 불필요하게 비활성화되던 조건도 함께 점검·보정했다. Text 직접 선택, line selection, Component selection의 활성 조건이 서로 충돌하지 않는지가 핵심 회귀 지점이다.

### 4.3 관리 화면 UI 보정

- `.page-tree__section`의 margin, border, background, radius 규칙 반영
- Template·Layout 관리의 우측 고정 Section 구성 패널 제거
- 선택한 Template의 Live Preview 중심으로 화면 재구성
- 빈 Section 생성 후 이름 변경 경로 보완
- Section 목록과 Preset 관리 화면의 설명·상태 표시 정리

### 4.4 Design Token 관리

Design Token 표와 등록 기능을 보완했다.

- Color token은 실제 색상 swatch와 hex 기준 결과 표시
- Font size는 실제 크기 preview 표시
- Font weight 등 표현 가능한 값은 실제 결과 형태로 표시
- Token 추가 기능 제공
- Font size 등 신규 Token 등록 지원
- 고정 `px`만 강제하지 않고 `rem`, `vh` 등 반응형 단위 입력 고려
- 값 validation과 관리 UI 계약 테스트 보강

주의:

- `vh`는 글자 크기에 직접 사용할 경우 화면 높이에 민감하므로 기본 권장값은 `rem` 또는 `clamp()`다.
- Token 값이 반응형 단위를 허용해도 기존 Layout의 고정 frame과 조합될 때 overflow가 발생할 수 있으므로 실제 Desktop/Mobile Preview 검증이 필요하다.


### 4.9 Template 활성화 검증 보완

보고된 오류:

```text
Another active default form template is required before removing this default
ACTIVE_SECTION_REQUIRED
SECTION_COMPONENT_REQUIRED
```

반영 기준:

- 현재 active default를 해제할 때 다른 active default가 없으면 차단한다.
- Template 활성화 시 Section의 active version을 확인한다.
- required Section은 visible Component가 최소 1개 있어야 한다.
- 비어 있는 required Section을 자동으로 통과시키거나 required를 임의 해제하지 않는다.

### 4.10 Section 활성화의 AI target 정규화

보고된 오류:

```text
AI_IMAGE_TARGET_REQUIRED
REQUIRED_SECTION_ITEM
```

원인:

- 과거 데이터의 `aiDesign.imageTarget: "item"`이 남아 있으나, 현재 visible item 중 AI source를 허용하는 target key가 없는 경우가 있었다.
- required Section 검증이 visible Component가 아니라 `item.isRequired`까지 요구해 현재 편집 모델과 맞지 않았다.

수정:

- `normalizeAiDesignForItems` 추가
- 삭제되거나 유효하지 않은 image target key 제거
- item target이 없고 Section background가 허용되면 `section-background`로 fallback
- 저장과 활성화 양쪽에서 동일 정규화 수행
- required Section은 최소 1개의 visible Component를 요구하도록 의미 수정
- 완전히 빈 required Section은 계속 `SECTION_COMPONENT_REQUIRED`로 차단

기존 데이터 migration 없이 저장·활성화 시 정상 형태로 수렴한다.

### 4.11 Section Preset을 공통 Visual Editor로 전환

## 5. 현재 사용 흐름

### 5.1 Template 생성·수정·활성화

1. `설정 > 템플릿, 레이아웃 관리` 진입
2. Template 생성 또는 선택
3. Live Preview에서 Section과 Component 구성·Layout 수정
4. `초안 저장`
5. 좌측 `활성화 템플릿` 목록에서 활성/비활성 토글
6. 활성화 오류가 있으면 Section active version과 visible Component 여부 확인

### 5.2 Section Preset 생성·Layout 편집·활성화

1. `설정 > Section Preset 관리` 진입
2. Section 기본 정보와 Component 구성 저장
3. 생성된 Preset을 선택해 공통 Live Preview 열기
4. Component 위치·크기·스타일과 Desktop/Mobile 표시 상태 수정
5. `Preset 저장`
6. 관리 목록에서 AI 페이지 구성/AI 디자인 정책과 활성 상태 지정

중요:

- 구조상 없는 Component를 Live Preview에서 새로 추가하는 기능은 현재 Section Preset mode에서 비활성화돼 있다.
- 먼저 관리 화면에서 구성원을 저장한 뒤 Live Preview에서 Layout을 편집한다.

### 5.3 삭제

- Template: Template 관리 목록의 삭제 기능 사용
- Section Preset: Section Preset 관리 목록의 삭제 기능 사용
- Component: `설정 > 컴포넌트 관리`의 사용자 생성 Component 삭제 기능 사용
- 사용 중인 대상은 참조를 해소하거나 다른 기본/활성 대상을 지정한 뒤 삭제한다.

## 7. 알려진 제약과 위험

### 7.1 Section Preset 구조 편집 범위

Section Preset Live Preview는 공통 renderer와 interaction engine을 사용하지만, Section/Component 추가·삭제를 iframe 내부에서 저장하는 기능까지 완료된 것은 아니다. 현재는 관리 화면에서 구성하고 Visual Editor에서 Layout을 저장한다.

### 7.2 Design Token 연결

Section Preset mode는 현재 기본 public Design Token set을 사용한다. Template별 또는 Preset별 Token set 선택이 필요하면 저장 모델과 Editor 초기화 계약을 확장해야 한다.

### 7.3 활성화와 legacy 데이터

AI target legacy 값은 저장·활성화 시 정규화한다. 운영 DB에 저장만 돼 있고 다시 저장·활성화되지 않은 데이터는 원본 JSON이 그대로 남아 있을 수 있다.

### 7.4 삭제 E2E

삭제 contract test는 추가했지만 운영 데이터에는 AI run, audit log, active/default, page document 등 다양한 참조 조합이 존재할 수 있다. Production에서 실제 삭제 전 usage 응답과 오류 메시지를 확인한다.

### 7.5 Production 검증

원격 `main`과 Production 배포는 동일 개념이 아니다. 최신 Source Commit, static asset hash, API version을 함께 확인해야 한다.

### 7.6 전체 suite의 stale assertion

전체 테스트가 green이 아니므로 다음 기능 개발 전에 위 4개 stale contract를 현행 제품 기준으로 정리하는 편이 안전하다.
