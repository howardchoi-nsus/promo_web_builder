## 3. 오늘 진행한 주요 작업

## 3.1 Step 1 자연어 Overview 기능 개선

자연어 입력은 사용자가 제목, 목적, 대상 고객, 혜택 등을 모두 정확히 알고 입력하는 기능이 아니라, 짧고 불완전한 설명을 AI가 프로모션 개요로 정리하는 기능으로 정의했다.

반영 내용:

- 기존 정형 입력값을 자연어 분석 결과에 섞지 않는 새 초안 방식 적용
- 자연어 입력 요청만으로 AI가 Overview 초안을 생성
- 각 결과 필드에 다음 출처 정보를 표시
  - 사용자 입력
  - AI 생성
  - AI 추론
  - 확인 필요
- 분석 결과에 신뢰도, 가정, 경고 및 필수 확인 항목 표시
- `분석 결과 적용` 시 Overview를 저장하고 Step 2 Template으로 자동 이동
- CTA 문구와 CTA URL을 초기 Overview 계약에서 제외
- 이전 요청 응답이 현재 입력에 뒤늦게 적용되지 않도록 request fingerprint 검증

관련 API:

```http
POST /api/promo-overview-parse
```

관련 관리자 프롬프트:

```text
promo_overview_parser
```

## 3.2 Overview v4 및 리드 텍스트 추가

기존 Overview v3에는 다음 핵심 필드만 있었다.

- `title`
- `promotionPurpose`
- `promotionPurposeOther`
- `market`
- `audience`
- `campaignTone`
- `mainOffer`

오늘 다음 필드를 공식 계약에 추가했다.

```json
{
  "leadText": ""
}
```

현재 Overview 계약:

```json
{
  "schemaVersion": 4,
  "inputMode": "structured",
  "rawNaturalLanguage": "",
  "title": "",
  "leadText": "",
  "promotionPurpose": "",
  "promotionPurposeOther": "",
  "market": "",
  "audience": "",
  "campaignTone": "",
  "mainOffer": ""
}
```

필드 의미:

- `title`: 프로모션의 대표 제목
- `leadText`: 제목을 보조하는 짧은 강조 문구
- `mainOffer`: 핵심 혜택을 설명하는 본문 성격의 문구

예시:

```text
title: 여름 신규 고객 충전 이벤트
leadText: 신규 고객을 위한 여름 한정 혜택
mainOffer: 여름 시즌 신규 고객에게 특별 충전 보너스를 제공합니다.
```

반영 내용:

- 서버 Overview JSON Schema에 `leadText` 추가
- 브라우저 Overview 정규화 모듈에 `leadText` 추가
- 기본 Wizard content에 `leadText` 추가
- 자연어 분석 결과 화면에 리드 텍스트 표시
- 정형 입력 화면에 리드 텍스트 필드 추가
- 분석 결과 적용 시 `promo.leadText`에 동기화
- Overview fingerprint 계산에 `leadText` 포함
- 템플릿 추천 검색 신호에 `leadText` 포함
- AI가 사용자가 제공하지 않은 정확한 수치·기간·조건을 리드 텍스트에 임의 생성하지 않도록 저장소 기본 프롬프트 지침 보완

주의:

- 기존 활성 `promo_overview_parser` DB 프롬프트는 저장소 기본 문구로 자동 변경되지 않는다.
- JSON Schema가 `leadText` 반환을 강제하므로 기능은 동작하지만, 생성 품질을 명확히 통제하려면 관리자 프롬프트 관리에서 활성 프롬프트의 지침을 별도 갱신하는 것이 좋다.

권장 관리자 프롬프트 지침:

```text
Generate a concise supporting lead text that complements the title without repeating it verbatim.
Do not invent exact amounts, dates, eligibility conditions, or guarantees unless the user supplied them.
```

## 3.3 Step 2 템플릿 추천 및 AI 구성 초안 흐름

Step 2에서 사용자가 템플릿 구조를 상세히 알지 못해도 Overview를 기준으로 추천과 구성 초안을 생성할 수 있도록 개선했다.

현재 흐름:

1. Step 1에서 Overview 확정
2. 활성 템플릿 추천 조회
3. `AI로 구성하고 다음` 실행
4. AI가 템플릿, 섹션 및 Overview 콘텐츠 매핑을 제안
5. 경고와 누락 입력이 없으면 추천 템플릿 자동 선택
6. 구성 초안을 현재 프로모션 세션에 자동 적용
7. Step 3 Layout & Design으로 자동 이동

검토가 필요한 경우:

- `missingInputs`가 존재
- `warnings`가 존재
- Overview fingerprint 불일치
- 템플릿 또는 섹션 버전 불일치

이 경우 Step 2에 머물고 사용자가 구성 초안을 확인한 후 직접 적용한다.

## 3.4 AI 구성 결과의 기존 사용자 콘텐츠 덮어쓰기 수정

기존 적용 로직은 템플릿 기본값 또는 빈 값만 AI 구성 결과로 변경했다.

이 때문에 이미 값이 들어 있는 컴포넌트는 AI 구성 결과가 있어도 변경되지 않았다.

수정 내용:

- 잠금되지 않은 텍스트 컴포넌트는 유효한 AI 콘텐츠 매핑이 있으면 해당 Overview 값으로 변경
- `item.isLocked === true`인 관리 잠금 콘텐츠는 계속 보호
- CTA URL은 AI가 임의 생성하지 않도록 기존 제한 유지

관련 캐시 버전:

```text
create-promo.js?v=create-promo-light-v41
```

## 3.5 `description → mainOffer` 누락 원인 및 수정

### 증상

AI 구성 초안 적용 후:

- `title`은 변경됨
- `description`은 기존 값 유지

운영 브라우저 localStorage 확인 결과:

```json
{
  "status": "applied",
  "autoApplied": true,
  "promotionIntroMappings": [
    {
      "itemKey": "title",
      "sourceOverviewPath": "title"
    }
  ]
}
```

Overview에는 새 `mainOffer`가 있었지만 구성 초안 결과에 다음 매핑이 없었다.

```json
{
  "itemKey": "description",
  "sourceOverviewPath": "mainOffer"
}
```

### 원인

- 프롬프트는 허용된 경로만 매핑하도록 제한했지만 모든 호환 텍스트 필드를 매핑하도록 강제하지 않았다.
- 서버 검증은 전달된 매핑의 유효성만 확인했다.
- 따라서 LLM이 일부 매핑을 생략해도 정상 제안으로 통과했다.

### 수정

LLM 결과 검증 후 서버가 선택된 섹션 전체의 텍스트 컴포넌트를 검사해 누락 매핑을 의미 기반으로 보완한다.

기본 매핑 규칙:

```text
title / headline / mainTitle
  → title

lead / leadText / eyebrow / kicker / subtitle / subline
  → leadText

description / copy / body / bodyText / mainOffer / offer / detail
  → mainOffer
```

보호 규칙:

- 잠금 컴포넌트는 자동 매핑하지 않는다.
- 텍스트 컴포넌트만 보완한다.
- 이미 매핑된 Item은 다시 매핑하지 않는다.
- 같은 Overview 원본은 자동 보완 과정에서 한 번만 사용한다.
- LLM이 명시한 유효 매핑은 우선 유지한다.
- LLM의 `componentVersionIds`가 일부만 포함해도 현재 세션에 적용되는 선택 섹션 전체의 호환 텍스트 Item을 기준으로 보완한다.

결과적으로 이번 사례는 다음 형태로 보완된다.

```json
[
  {
    "itemKey": "title",
    "sourceOverviewPath": "title"
  },
  {
    "itemKey": "leadText",
    "sourceOverviewPath": "leadText"
  },
  {
    "itemKey": "description",
    "sourceOverviewPath": "mainOffer"
  }
]
```

## P1 — visibility 브라우저 스모크 해결

다음 정책을 확정한 후 구현과 테스트를 일치시킨다.

- 편집기에서 숨김 placeholder를 유지할지

## 8. 알려진 주의사항

### 8.1 저장소 기본 프롬프트와 활성 DB 프롬프트

`api/_prompt-template-store.js`의 기본 프롬프트 변경은 신규 환경 또는 프롬프트가 없는 환경의 복구 기준이다.

이미 활성 프롬프트가 있는 Production DB에서는 관리자 편집 내용을 보호하기 위해 저장소 기본값으로 덮어쓰지 않는다.

따라서:

- 기능 계약과 서버 보완은 코드 배포로 반영됨
- 실제 프롬프트 문구 품질 개선은 관리자 페이지에서 새 버전을 활성화해야 함

### 8.2 기존 저장 세션

기존 Overview v3 세션에는 `leadText`가 없을 수 있다.

- 정형 입력 사용자는 리드 텍스트를 입력해야 다음 단계로 이동할 수 있다.
- 자연어 입력 사용자는 AI 분석을 다시 실행하면 Overview v4 초안을 받을 수 있다.
- 캐시가 오래된 경우 강력 새로고침 후 다시 확인한다.

### 8.3 AI 결과의 비결정성

프롬프트만으로 완전한 매핑을 보장하지 않는다.

이번 수정은 서버가 누락 매핑을 보완하므로 `title`, `leadText`, `mainOffer`의 기본 역할 매핑은 안정화됐지만, 명칭이 완전히 다른 사용자 정의 Item은 자동 인식되지 않을 수 있다.

이 경우 P2의 의미 역할 메타데이터가 필요하다.
