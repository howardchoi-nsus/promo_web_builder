- 활성화된 프로모션 폼 템플릿을 Wizard Step 2에서 조회하고 선택할 수 있도록 구성했다.
- 템플릿 선택 UI를 프로모션 개요 위로 이동하고 타일 형태로 변경했다.
- 선택한 템플릿의 Section과 Section Item을 동적 입력 필드로 렌더링한다.
- `프로모션 개요`는 템플릿과 무관한 공통 생성 요청 정보로 유지했다.
- 기존 `Message JSON` 사용자 입력 영역과 직접 의존을 제거했다.
- 템플릿별 입력값, Section Snapshot 및 Revision을 생성 payload에 포함하는 구조를 반영했다.
- Wizard 공개 API는 활성화된 템플릿과 Wizard 노출 대상 Section/Item만 반환하도록 구성했다.
- 선택 템플릿이 없거나 구성 조회가 실패한 경우 다음 단계 진행을 차단하는 fail-closed 동작을 유지했다.

### 2.2 Step 2 화면 구조 및 아코디언

- 화면 순서를 다음과 같이 정리했다.
  - `1. 프로모션 템플릿`
  - `2. 프로모션 개요`
  - `3. 콘텐츠 등록`
- 선택 템플릿의 Section Article들을 하나의 콘텐츠 등록 DIV로 래핑했다.
- 내부 Section Article의 개별 border를 제거했다.
- `Header`, `Contents CTA` 등 Section 제목에 붙던 자동 번호를 제거했다.
- 콘텐츠 등록 하위 Section을 아코디언으로 구성했다.
- 열림/닫힘 시 높이, 투명도 및 이동 애니메이션을 적용했다.
- Section의 관리자 설정값 `userReorderAllowed`를 기준으로 Wizard 사용자 순서 변경 가능 여부를 반영했다.
- 순서 변경 가능한 Section에 이동 컨트롤을 표시하고, 이동 불가 Section은 해당 위치를 유지하도록 구성했다.
- Section 이동 후 입력값이 함께 유지되도록 Section 정의와 입력 데이터의 결합 구조를 점검했다.

### 2.4 Root Landing 구현

- Root `index.html`의 `/prototype/index.html` 자동 리다이렉트를 제거했다.
- 독립적인 정적 랜딩 화면을 구성했다.
- 데스크톱에서는 3열, 모바일에서는 1열로 표시되는 반응형 진입 카드를 적용했다.
- 서비스별로 색상을 구분하되 기존 운영 도구 성격에 맞게 절제된 UI를 사용했다.
- 현재 폴더 구조는 이동하지 않고 기존 경로에 연결했다.

현재 버튼 경로:

| 버튼 | 경로 | 동작 |
| --- | --- | --- |
| Promo Wizard | `/promo-wizard.html` | 기존 redirect stub을 통해 `/prototype/promo-wizard.html` 진입 |
| Promo Builder | `/prototype/index.html` | Builder 화면 진입 |
| Admin | `/prototype/index.html?view=admin` | 동일 Vue SPA의 관리자 화면으로 직접 진입 |

### 2.5 Admin 직접 진입 디버깅

- `prototype/app.js`가 `?view=admin`을 읽어 초기 `currentView`를 `prompts`로 결정하도록 반영했다.
- Admin 직접 진입 시 관리자 템플릿, 웹훅, 폼 템플릿 및 Section CRUD 로그 데이터를 로드한다.
- Admin에서 Builder로 전환할 때 URL의 `view` 파라미터를 제거한다.
- Builder에서 Admin으로 전환할 때 `view=admin`을 URL에 반영한다.
- 화면 상태와 URL이 동기화되어 새로고침 후 다른 화면으로 되돌아가는 문제를 방지했다.

## 5. 현재 상태 및 주의사항

### 5.1 아직 폴더 분리는 하지 않음

오늘 구현한 것은 Root Landing이다. 다음 구조 변경은 아직 적용하지 않았다.

- `/wizard`
- `/builder`
- `/builder/generated`
- `/admin`
- `/shared`

현재 버튼은 기존 `/prototype` 구조를 사용한다. 폴더 이동은 계획서의 Phase 1 이후 작업이다.

### 5.2 Admin 보안 미적용

- `/prototype/index.html?view=admin`은 진입 편의를 위한 화면 선택 기능이다.
- 인증과 권한 검증 기능이 아니다.
- Admin UI를 숨겨도 관리자 API를 보호할 수 없으므로 운영 공개 전에 서버 측 인증이 필요하다.

### 5.3 Root 랜딩의 Admin 노출 정책

- 현재 Root Landing에 Admin 버튼이 노출된다.
- PoC 단계에서는 기존 Builder 상단의 관리자 버튼과 보안 수준이 동일하다.
- 운영 전에는 로그인 상태와 역할에 따라 숨기거나 내부 도구 영역을 인증 뒤에 배치해야 한다.

### 5.4 기존 경로와 테스트

- 현재 경로를 유지했기 때문에 오늘 계약 테스트는 영향받지 않았다.
- 향후 폴더 분리 시 `scripts/test-wizard-*.js`의 `prototype/` 직접 참조를 반드시 갱신해야 한다.
- 기존 redirect stub은 폴더 분리 및 `vercel.json` 리다이렉트 적용 전까지 삭제하지 않는다.
