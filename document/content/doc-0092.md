# Directus 적용 전·후 간단 비교

## 한 줄 요약

**현재 직접 만든 관리자 화면을 Directus로 바꾸고, 프로모션을 만드는 서비스는 그대로 유지한다. Directus MCP는 AI를 이용해 설정을 찾고 작성하는 관리 도우미로 사용한다.**

## 전체 구조

```text
현재
자체 관리자 → 설정 저장 → 프로모션 서비스 → 페이지 제작

변경 후
Directus → 설정 저장 → 프로모션 서비스 → 페이지 제작
    ↑
Directus MCP를 이용한 AI 관리 도우미
```

## AS-IS / TO-BE 비교

| 구분 | 현재 | Directus 적용 후 |
|---|---|---|
| 관리자 화면 | 직접 개발한 관리자 화면 | Directus 관리 화면 |
| 설정 관리 | 기능별로 직접 개발 | Directus에서 통합 관리 |
| 템플릿·컴포넌트 | 자체 화면에서 관리 | Directus에서 관리 |
| AI 프롬프트·모델 | 자체 화면에서 관리 | Directus에서 관리 |
| 이미지·파일 | 별도 저장소와 API 사용 | Directus 파일 관리 또는 기존 저장소 병행 |
| 사용자 권한 | 역할 구분이 제한적 | 작성자·검토자·관리자 권한 분리 |
| 변경 이력 | 기능별로 따로 기록 | Directus에서 통합 확인 |
| AI 관리 지원 | 사람이 직접 검색·수정 | MCP로 검색·초안·번역 지원 |
| 페이지 생성·편집 | 현재 서비스 사용 | 현재 서비스 그대로 유지 |
| 최종 출력 | 현재 출력 기능 사용 | 현재 출력 기능 그대로 유지 |

## Directus가 담당하는 것

- 템플릿과 컴포넌트 관리
- 섹션과 레이아웃 설정
- 디자인 색상과 글꼴 설정
- AI 프롬프트와 모델 설정
- 다국어 문구 관리
- 이미지와 파일 관리
- 작성·검토·승인 상태 관리
- 사용자 권한과 변경 이력 관리

## Directus MCP가 담당하는 것

운영자가 AI에게 자연어로 관리 작업을 요청할 수 있게 한다.

- “현재 사용 중인 템플릿을 보여줘.”
- “번역이 빠진 항목을 찾아줘.”
- “기존 프롬프트를 복사해 새 초안을 만들어줘.”
- “지난주 변경 내용을 요약해줘.”

MCP는 설정을 돕는 기능이다. 페이지 생성이나 GPT·Gemini 실행을 직접 담당하지 않는다.

## 기존 서비스에 남는 것

- 프로모션 내용 입력
- AI를 이용한 페이지 생성
- GPT·Gemini 실제 호출
- 미리보기와 사용자 편집
- 이미지·레이아웃 품질검사
- 작업 실패와 재시도 관리
- 최종 웹페이지 출력

## 별도 개발이 필요한 것

Directus만 설치한다고 바로 전환되지는 않는다. 다음 기능을 연결해야 한다.

- 기존 설정을 Directus로 옮기는 작업
- 서비스가 Directus 설정을 읽는 연결 기능
- 프롬프트와 모델 설정 검사
- 기존 레이아웃 편집 화면 연결
- 실행 중 설정이 바뀌지 않도록 복사해 두는 기능

## 권장 도입 순서

```text
1. Directus에 설정 구조 만들기
              ↓
2. 기존 설정 데이터 복사
              ↓
3. 기존 결과와 비교 확인
              ↓
4. 서비스의 설정 조회를 Directus로 변경
              ↓
5. MCP를 조회·초안 기능부터 적용
              ↓
6. 안정화 후 기존 관리자 화면 종료
```

## 최종 결론

- 기존 관리자 화면은 Directus로 교체할 수 있다.
- 프로모션 생성·편집·출력 서비스는 다시 만들 필요가 없다.
- Directus MCP는 관리 업무를 돕지만 서비스 실행기는 아니다.
- 중요한 설정의 승인·공개·삭제는 사람이 최종 확인해야 한다.
- 가장 현실적인 방향은 **Directus는 관리, 기존 서비스는 제작**으로 역할을 나누는 것이다.

## WordPress에서 Directus로 전환

현재는 WordPress 관리자에서 템플릿을 선택하고 내용을 입력해 프로모션 페이지를 운영한다. 앞으로는 WordPress가 담당하던 콘텐츠와 설정 관리를 Directus로 옮긴다.

```text
현재
WordPress 관리자
  └─ 콘텐츠 입력·템플릿 관리·페이지 게시

변경 후
Directus
  └─ 콘텐츠·템플릿·이미지·권한 관리
                  ↓
Promo Web Builder
  └─ AI 페이지 생성·미리보기·편집
                  ↓
최종 프로모션 페이지 공개
```

| 구분 | WordPress 사용 시 | Directus 전환 후 |
|---|---|---|
| 관리자 화면 | WordPress 관리자 | Directus Studio |
| 콘텐츠 관리 | WordPress 페이지·필드 | Directus Collection |
| 템플릿 관리 | WordPress 테마·플러그인 의존 | Promo Web Builder에서 관리 |
| 서비스 연결 | WordPress 내부 기능 중심 | Directus API로 데이터 제공 |
| 페이지 화면 | WordPress가 직접 출력 | 기존 Vue Renderer가 출력 |
| AI 관리 | 별도 개발 필요 | 기존 AI 기능 + Directus MCP 활용 |

### 변경되는 부분

- WordPress 관리자 대신 Directus를 사용한다.
- 기존 프로모션 콘텐츠와 이미지를 Directus로 옮긴다.
- Promo Web Builder가 WordPress가 아닌 Directus API에서 데이터를 가져온다.
- 사용자·작성자·검토자 권한을 Directus에서 관리한다.

### 유지되는 부분

- AI 프로모션 생성
- 템플릿과 레이아웃 구성
- 미리보기와 편집
- GPT·Gemini 연동
- 최종 웹페이지 출력

즉, **WordPress를 Directus로 단순 교체하는 것이 아니라, Directus는 콘텐츠 관리 역할을 맡고 Promo Web Builder는 페이지 제작 역할을 담당하도록 분리하는 전환**이다.
