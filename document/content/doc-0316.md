# 템플릿·섹션·컴포넌트 용어집

- 작성일: 2026-07-23
- 적용 범위: 관리자 페이지, Create Promo, Visual Editor, API·DB 설계 문서, 테스트 문서
- 문서 목적: 템플릿·섹션·컴포넌트 구조에서 사용하는 한국어·영문 용어와 각 개념의 책임을 통일한다.
- 기준 구조: 섹션은 컴포넌트를 조립하고, 컴포넌트는 콘텐츠 필드·속성·스타일 슬롯을 정의한다.
- 사용자 화면 원칙: 일반 사용자가 이해하기 쉬운 한국어를 우선 사용하고, 개발 식별자와 DB 컬럼명은 필요한 경우에만 병기한다.

## 1. 표준 계층

```text
프로모션 페이지
└─ 템플릿 (Template)
   └─ 섹션 (Section)
      └─ 배치 컴포넌트 (Component Instance)
         └─ 컴포넌트 (Component + pinned Component Version)
            ├─ 컴포넌트 필드 (Component Field)
            ├─ 컴포넌트 속성 (Component Property)
            └─ 스타일 슬롯 (Style Slot)
```

사용자 화면에서는 `배치 컴포넌트`와 `컴포넌트`를 문맥에 따라 모두 `컴포넌트`로 표시할 수 있다. 다만 개발 문서와 API 문서에서는 재사용 정의와 섹션에 배치된 사용 건을 구분하기 위해 `Component`와 `Component Instance`를 구분한다.

## 2. 핵심 용어

| 표준 한국어 | 표준 영문 | 정의 | 대표 예시 |
|---|---|---|---|
| 프로모션 페이지 | Promotion Page | Create Promo에서 사용자가 입력한 콘텐츠와 선택된 템플릿·디자인을 결합해 생성되는 최종 페이지 | 이벤트 랜딩 페이지 |
| 템플릿 | Template | 프로모션 페이지에 사용할 섹션 구성과 기본 디자인 토큰 세트를 정의하는 최상위 재사용 단위 | Default Template |
| 섹션 | Section | 페이지 안에서 하나의 목적을 수행하며 여러 컴포넌트를 조립하는 콘텐츠 영역 | Promotion Intro, Hero, Footer |
| 컴포넌트 | Component | 여러 섹션에서 재사용할 수 있는 콘텐츠·기능 단위의 논리적 정의 | Hero Title, Primary CTA, Content Image |
| 컴포넌트 버전 | Component Version | 컴포넌트의 입력 구조, 정책, 기본값, 스타일 슬롯을 특정 시점으로 고정한 버전 | Hero Title v2 |
| 배치 컴포넌트 | Component Instance | 특정 섹션에 특정 컴포넌트 버전을 배치한 사용 건 | Promotion Intro의 `title` |
| 컴포넌트 필드 | Component Field | 컴포넌트 안에서 사용자가 입력하거나 시스템이 저장하는 데이터 항목 | CTA 문구, URL, 대체 텍스트 |
| 컴포넌트 속성 | Component Property | 컴포넌트의 입력 방식, 동작, 검증 또는 노출 기준을 결정하는 설정 | 최대 글자 수, 필수 여부, 이미지 비율 |
| 콘텐츠 값 | Content Value | Create Promo에서 사용자가 컴포넌트 필드에 실제로 입력하거나 선택한 값 | `지금 참여하세요`, 이미지 URL |
| 스타일 슬롯 | Style Slot | 디자인 토큰을 연결할 수 있도록 컴포넌트 또는 섹션이 공개하는 논리적인 스타일 적용 지점 | 제목 색상, CTA 배경색, 이미지 모서리 |
| 디자인 토큰 | Design Token | 색상, 간격, 모서리, 글자 크기 등 재사용 가능한 디자인 값 | `--promo-accent`, `--promo-radius` |
| 디자인 토큰 세트 | Design Token Set | 하나의 디자인 방향을 구성하는 디자인 토큰 모음 | Rounded Style, Square Style |
| 이미지 자산 | Image Asset | 업로드, URL 또는 AI 생성을 통해 컴포넌트나 섹션에 연결되는 실제 이미지 파일 | AI 생성 Hero 이미지 |
| 배경 이미지 | Background Image | 섹션 콘텐츠 뒤에 표시되는 섹션 단위 이미지 자산 | Promotion Intro 배경 이미지 |
| 렌더 요소 | Render Element | 컴포넌트를 화면에 출력할 때 생성되는 HTML 또는 Vue 내부 요소 | `img`, `button`, `span` |

## 3. 컴포넌트 내부 용어

### 3.1 컴포넌트 필드

`컴포넌트 필드`는 사용자가 입력하거나 시스템이 저장하는 데이터 단위다. 컴포넌트의 하위 요소를 통칭해야 할 때 사용자 화면에서는 `요소`나 `아이템` 대신 `필드`를 사용한다.

| 컴포넌트 | 포함할 수 있는 표준 필드 |
|---|---|
| 제목 컴포넌트 | 텍스트 |
| 본문 컴포넌트 | 본문 텍스트 |
| CTA 컴포넌트 | 버튼 문구, 링크 URL, UTM 정보 |
| 이미지 컴포넌트 | 이미지, 대체 텍스트, 이미지 설명 |
| 로고 컴포넌트 | 로고 이미지, 대체 텍스트 |
| 배지 컴포넌트 | 배지 이미지, 대체 텍스트 |

컴포넌트 필드는 콘텐츠 데이터이며, CSS 속성이나 데이터 검증 설정을 의미하지 않는다.

### 3.2 컴포넌트 속성

`컴포넌트 속성`은 필드의 입력·검증·동작 기준이다.

예시:

- 텍스트 최대 길이
- 여러 줄 입력 허용 여부
- 필수 입력 여부
- 이미지 허용 소스
- 이미지 비율
- CTA 링크 필수 여부
- AI 이미지 생성 허용 여부

`필드`와 `속성`을 같은 의미로 사용하지 않는다. 예를 들어 `대체 텍스트`는 필드이고, `대체 텍스트 필수`는 속성이다.

### 3.3 스타일 슬롯

`스타일 슬롯`은 CSS 선택자나 HTML 요소가 아니라 디자인 토큰을 적용하기 위한 논리적 지점이다.

| 스타일 슬롯 예시 | 의미 | 연결 가능한 토큰 예시 |
|---|---|---|
| `titleColor` | 제목 색상 | 강조 색상 토큰 |
| `titleSize` | 제목 크기 | 제목 크기 토큰 |
| `bodyColor` | 본문 색상 | 본문 색상 토큰 |
| `ctaBackground` | CTA 배경색 | 강조 색상 토큰 |
| `ctaRadius` | CTA 모서리 | 모서리 토큰 |
| `imageRadius` | 이미지 모서리 | 모서리 토큰 |

관리자 사용자에게 기술 용어가 과도한 화면에서는 `스타일 슬롯` 대신 `스타일 항목`을 표시명으로 사용할 수 있다. 개발 문서와 데이터 모델에서는 `Style Slot`을 유지한다.

## 4. 컴포넌트 유형

사용자 화면에서는 `컴포넌트 유형`을 사용한다. 내부 API·DB의 `fieldKind`는 호환성을 위해 유지할 수 있다.

| 사용자 화면 | 영문 | 내부 값 | 의미 |
|---|---|---|---|
| 텍스트 | Text | `text` | 제목, 본문, 보조 문구 등 텍스트 콘텐츠 |
| 이미지 | Image | `image` | 업로드·URL·AI 생성 이미지 콘텐츠 |
| CTA | CTA | `cta` | 문구와 링크를 포함하는 행동 유도 콘텐츠 |

`text`, `image`, `cta`는 독립된 컴포넌트 이름이 아니라 컴포넌트의 유형이다. 실제 컴포넌트 이름은 `Hero Title`, `Body Text`, `Primary CTA`, `Content Image`처럼 목적이 드러나야 한다.

## 5. 정의와 배치의 구분

### 5.1 컴포넌트 정의

컴포넌트 정의는 여러 섹션에서 재사용되는 공통 계약이다.

- 컴포넌트 이름
- 컴포넌트 유형
- 입력 스키마
- 기본값
- 이미지·CTA 정책
- 스타일 슬롯
- AI 기능 허용 범위

### 5.2 배치 컴포넌트

배치 컴포넌트는 특정 섹션에서 컴포넌트 정의를 사용한 결과다.

- 배치 키
- 표시 이름
- 섹션 내 순서
- 필수 여부
- 노출 여부
- 잠금 설정
- 고정된 컴포넌트 버전

같은 컴포넌트를 한 섹션에 여러 번 배치할 수 있으므로 `컴포넌트`와 `배치 컴포넌트`는 데이터 모델에서 반드시 구분해야 한다.

예시:

```text
Content Image 컴포넌트 v1
├─ heroVisual 배치
├─ partnerVisual 배치
└─ badgeVisual 배치
```

## 6. 식별자 용어

| 사용자 화면 용어 | 내부 명칭 | 목적 |
|---|---|---|
| 컴포넌트 ID | `componentKey` | 재사용 컴포넌트를 안정적으로 식별하는 자동 생성 값 |
| 컴포넌트 배치 키 | `itemKey` | 한 섹션 안에서 배치된 컴포넌트의 역할을 식별하는 값 |
| 섹션 ID | `sectionKey` | 섹션을 식별하는 안정적인 값 |
| 템플릿 ID | `templateKey` | 템플릿을 식별하는 안정적인 값 |

화면에서는 일반 사용자가 직접 관리할 필요가 없는 자동 생성 식별자를 기본적으로 숨기거나 읽기 전용으로 제공한다. `Key`라는 단어를 단독으로 노출하지 않고 대상이 분명한 `컴포넌트 ID`, `컴포넌트 배치 키`처럼 표시한다.

### 7.4 Create Promo

Create Promo 사용자는 기술 구조를 편집하는 관리자가 아니므로 `컴포넌트`, `필드`, `배치 키`를 필요 이상으로 노출하지 않는다.

- 섹션 이름을 먼저 표시한다.
- 입력 항목은 컴포넌트의 표시 이름으로 안내한다.
- 컴포넌트 ID, 버전, 배치 키는 숨긴다.
- AI 이미지 생성 대상 선택이 필요할 때만 `이미지 항목` 또는 실제 표시 이름을 사용한다.

## 8. 사용 중단 및 대체 용어

| 사용 중단 용어 | 대체 용어 | 사유 |
|---|---|---|
| Section Items | 구성 컴포넌트 | 현재 구조는 섹션에서 Item을 직접 생성하지 않고 컴포넌트를 배치한다. |
| 섹션 아이템 | 구성 컴포넌트 | `아이템`은 의미가 모호하고 신규 컴포넌트 모델과 충돌한다. |
| 아이템 컴포넌트 | 컴포넌트 | 사용자 화면에서는 불필요하게 복합적인 표현이다. |
| Item Key | 컴포넌트 배치 키 | 재사용 컴포넌트 ID와 구분해야 한다. |
| 이미지 대상 Item | 이미지 대상 컴포넌트 | AI 이미지가 적용되는 대상을 명확하게 표현한다. |
| 필드 유형 | 컴포넌트 유형 | 관리자가 선택하는 대상은 필드가 아니라 컴포넌트 정의다. |
| Item 변경 이력 | 컴포넌트 변경 이력 | 관리자 화면의 기준 개념을 컴포넌트로 통일한다. |
| 요소 | 문맥에 따라 필드·속성·스타일 슬롯 | `요소`는 데이터, 설정, HTML을 구분하지 못한다. |

`itemKey`, `fieldKind`, `wizard_content_section_items` 등 기존 API·DB 명칭은 호환성 확보를 위해 즉시 변경하지 않을 수 있다. 다만 신규 사용자 화면, 신규 문서 및 신규 API 응답 설명에서는 표준 용어를 사용한다.

## 9. 혼동 방지 규칙

1. 섹션을 컴포넌트라고 부르지 않는다.
2. 컴포넌트 유형을 컴포넌트 이름으로 사용하지 않는다.
3. 컴포넌트 정의와 섹션에 배치된 컴포넌트를 개발 문서에서 구분한다.
4. 사용자가 입력하는 데이터는 `필드`, 동작·검증 기준은 `속성`으로 구분한다.
5. 디자인 토큰 적용 지점은 `스타일 슬롯`으로 부르고 콘텐츠 필드에 포함하지 않는다.
6. `Item`은 레거시 데이터 모델 또는 호환성 설명에서만 사용한다.
7. `Element`는 HTML·Vue 렌더 요소를 설명할 때만 사용한다.
8. 사용자 화면에서는 내부 DB 테이블명, UUID, 버전 고정 구조를 기본적으로 노출하지 않는다.

## 10. 예시 구조

```text
Default Template
└─ Promotion Intro 섹션
   ├─ Eyebrow 배치 컴포넌트
   │  └─ Remark Text 컴포넌트 v1
   │     └─ 텍스트 필드
   ├─ Title 배치 컴포넌트
   │  └─ Hero Title 컴포넌트 v1
   │     ├─ 텍스트 필드
   │     └─ titleColor/titleSize 스타일 슬롯
   ├─ Description 배치 컴포넌트
   │  └─ Body Text 컴포넌트 v1
   │     └─ 본문 텍스트 필드
   ├─ Visual 배치 컴포넌트
   │  └─ Content Image 컴포넌트 v1
   │     ├─ 이미지 필드
   │     ├─ 대체 텍스트 필드
   │     └─ imageRadius 스타일 슬롯
   └─ Primary Action 배치 컴포넌트
      └─ Primary CTA 컴포넌트 v1
         ├─ 버튼 문구 필드
         ├─ 링크 URL 필드
         ├─ UTM 필드
         └─ ctaBackground/ctaRadius 스타일 슬롯
```

## 11. i18n 메시지 키 권장 구조

```text
entity.template.*
entity.section.*
entity.component.*
entity.componentInstance.*
entity.componentField.*
entity.styleSlot.*
entity.designTokenSet.*
```

신규 메시지 키에서는 `entity.item.*`을 추가하지 않는다. 기존 `entity.item.*` 키는 화면 용어 전환 시 `entity.componentInstance.*` 또는 `entity.componentField.*`로 역할을 구분해 단계적으로 대체한다.

## 12. 문서 및 개발 적용 원칙

- 기획서와 사용자 UI는 이 문서의 표준 한국어를 사용한다.
- API·DB 문서는 표준 영문과 실제 필드명을 함께 표시한다.
- 기존 필드명을 변경해야 할 때는 호환성 마이그레이션과 API 버전 정책을 별도로 수립한다.
- 신규 기능은 `Template → Section → Component Instance → Component Field` 계층을 기준으로 설계한다.
- 용어 변경만으로 기존 저장 데이터의 의미가 바뀌어서는 안 된다.
- UI 문구 변경은 i18n 메시지로 관리하며 화면에 새 문구를 하드코딩하지 않는다.

## 13. 최종 표준

사용자와 관리자가 이해해야 하는 핵심 계층은 다음 세 단계로 단순화한다.

```text
섹션 → 컴포넌트 → 컴포넌트 필드
```

개발·데이터 모델에서는 재사용과 버전 고정을 설명하기 위해 다음 전체 계층을 사용한다.

```text
템플릿 → 섹션 버전 → 컴포넌트 인스턴스 → 고정된 컴포넌트 버전
```

이 문서를 신규 화면 문구, 기획서, API 설명, 테스트 시나리오의 기준 용어집으로 사용한다.
