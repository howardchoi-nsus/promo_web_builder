# Mouse Swarm Builder 표시 정책과 구현 계약

## 사용자 여정 — 2026-11-23 확정

최우선 목표는 콘텐츠에 맞는 다양한 레이아웃과 높은 디자인 품질이다. 사용자에게는 최소 액션과 최소 정보만 요구한다. 이 문서는 목표 정책이며 기존 승인 API·화면·프롬프트 전환은 별도 개발·검증 대상이다.

상단 단계는 `1. 요청 요약 → 2. 페이지 제작` 두 개이며, 기본 흐름은 요청 입력 → 자동 구성 → 디자인·이미지 → 자동 검사·보정 → 완성이다.

1. 고객은 자연어 요청과 선택적 참고 자료를 전달한다. 요약/와이어프레임은 확인용으로 표시하고 단계 진행을 위한 확인·승인 클릭을 요구하지 않는다.
2. 빈 캔버스에서 AI 계획 스켈레톤과 검증·저장된 실제 단위를 누적한다. 기존 문서의 새로고침·재시도에서는 완료 결과를 보존한다.
3. 전체 구조·소스·토큰·접근성 검증과 저장이 완료되면 시스템이 자동으로 디자인 단계로 전환한다. 부분 초안은 최종 결과가 아니며 출력 게이트는 열지 않는다. 사용자 승인 이력을 임의 생성하지 않는다.
4. 검증된 구조에서 영역 스타일·이미지를 준비한다. 구조 보정이 필요하면 내부 재설계·검증·저장·관련 품질/미디어 상태 갱신을 수행한다. 고객 재승인은 요구하지 않는다.
5. 효과를 제거한 실제 결과를 자동 검사·보정·재검사한다. 현재 Revision의 검사와 미디어 준비가 완료되어야 완성/출력을 제공한다.
6. 완성 후 필요할 때만 채팅·동일 문서 에디터로 수정하고 새 창 보기·다운로드를 선택한다. 편집 후에도 내부 재검증·자동 보정을 수행한다. 외부 공개 게시 권한은 자동 생성과 별개다.

오른쪽에는 단계·뷰포트 보기·실제 결과를 표시하고, 왼쪽 채팅에는 요청·꼭 필요한 질문·큰 단계 진행·완성·최종 복구 행동만 제공한다. 구성 승인·재승인·품질 승인 버튼을 요구하지 않는다. 큰 단계는 구성 중 / 디자인·이미지 적용 중 / 마무리 중 / 완성이다. 세부 작업·검사·자동 재시도·오류 코드·요청 ID는 관리자/운영 로그에 보존한다. 자동 복구 한도 후 미해결이면 완료 내용을 보존하고 쉬운 설명과 복구 행동 하나를 제공한다.

## 디자인 품질과 사용자/관리자 경계

- 레이아웃의 섹션 수·순서·중첩·컬럼·비율·이미지 관계·정보 위계·리듬·반응형을 요청에 맞게 설계한다. 특정 히어로/카드/색상 템플릿이나 무작위 변화를 강제하지 않는다. 배경형 히어로도 선택 가능한 구도다.
- 핵심 구도는 구조 단계에서 결정하고 영역 디자인은 검증된 구조의 등록 스타일을 설계한다. 구조 보정은 별도 내부 경로에서 검증하고 관련 상태를 무효화한다.
- 사용자에게 제작 승인·기술 검사를 맡기지 않는다. Admin은 정책·스킬·프롬프트·모델·토큰·실행/검사 기록과 품질 비교를 관리한다. 관리자 설정의 Draft/검증/활성화는 유지한다.
- 자동 오류 검사와 내부 디자인 판단을 구분하며 측정하지 않은 미감·시각 품질을 통과했다고 주장하지 않는다.

## 렌더링 단위

- 섹션별: 실제 동적 PageSchema의 의미 있는 영역에 연결한다. 헤더·히어로·카드 3개 같은 고정 배열을 강제하지 않는다.
- 컴포넌트별: 실제 nodeId에 연결하고 역할에 따라 text/image/button/card 등의 경계를 표시한다. 표시 단위와 모델 호출 단위를 구분한다.
- 실행은 서버의 의존성·동시성 계약을 따른다. 독립 영역 동시 최대 2개와 이미지/다음 디자인 겹침은 AGENTS.md의 생성 성능 정책 및 통합 계획서 28절을 구현·검증한 뒤 허용한다. 현재 순차 API에 표시 계층이 임의로 병렬 요청을 보내지 않는다. 커서 수는 병렬 호출 수·에이전트 수·진행률이 아니다.

## 커서 12개와 편집 효과

- 바운딩 박스 그룹과 마우스 커서 그룹에 각각 `opacity: 0.5`(불투명도 50%)를 한 번 적용한다. 라벨·핸들·캐럿은 그룹을 상속하며 중복 opacity를 주지 않는다. 공통 overlay 부모·캔버스·생성 텍스트·이미지는 흐리게 만들지 않는다.

- 기본 시각 커서 풀은 12개다. 실제 진행 대상이 있는 커서만 활동시키고 나머지는 대기 영역에 둔다. 화면에는 작업 커서와 대기 커서를 구별해 보여준다. 실제 작업이 12개라고 꾸미지 않는다.
- 커서는 범위 없는 임의 배회 대신 현재 대상 경계·텍스트 입력 지점·미디어 로딩 경계에 연결한다. 역할·노드 식별에 맞는 색상 라벨을 쓰되 실제 모델 수를 표시하지 않는다.
- 텍스트는 선택 박스, 모서리 핸들, 입력 캐럿, 필요한 경우 현재 반영된 구간 강조로 표현한다. 핸들은 장식이며 드래그·contenteditable·추가 폼을 만들지 않는다.
- 문구는 검증·저장된 콘텐츠만 노출한다. 서버 토큰 입력 위치는 실제 검증·저장된 조각 이벤트가 있을 때만 표시한다. 현재 문구 전체는 즉시 DOM에 반영하고 600ms 일회성 Mask Reveal의 실제 DOM/Range 공개 경계에 장식 캐럿을 연결한다. 이는 모델 입력이나 추가 조각 저장을 뜻하지 않는다. 문자를 교체하거나 같은 단위의 문구를 긴 순차 대기열로 지연하지 않는다.
- 임시 조각은 최종 문서와 분리된 검증된 초안 저장소가 있어야 한다. JSON 토큰 스트림, 미완성 문장, 근거 미검증 금액을 DOM에 출력하지 않는다. 전체 소스 참조와 사실 조건을 보존한다.
- 완료한 대상의 커서·박스·캐럿은 즉시 정리하고 디자인·에셋은 유지한다. 실패 대상은 멈추고 채팅에서 원인·재시도를 안내한다. 사용자 일시정지 옵션은 표시만 멈추며 서버 작업 취소를 뜻하지 않는다.
- 커서·박스는 pointer-events:none, aria-hidden=true인 별도 표시 계층으로 격리한다. 실제 마우스·키보드·선택을 방해하지 않고 스크롤·포커스·확대를 강제하지 않는다.
- 화면 밖 대상의 커서를 엉뚱한 컴포넌트에 붙이지 않는다. 대기 표시로 바꾸거나 사용자가 해당 영역으로 이동했을 때 정확히 연결한다.
- 모션 감소 설정에서는 커서 이동·깜빡임·타자·Reveal을 제거하고 즉시 상태를 표시한다. 모바일에서는 라벨 밀도를 줄이고 상태·콘텐츠 접근성을 유지한다.

## 실제 작업 상태 연결: 신규 이벤트 계약 제안

아래는 향후 구현할 앱 전용 이벤트이며 LLM 응답 필드나 현재 API 필드가 아니다.

```json
{
  "documentId": "document-reference",
  "runId": "generation-reference",
  "revision": 4,
  "sequence": 18,
  "taskId": "task-reference",
  "phase": "wireframe",
  "unit": "component",
  "nodeIds": ["headline"],
  "state": "persisted"
}
```

- phase: wireframe / design / media / quality; unit: section / component; state: queued / running / validated / persisted / failed.
- sequence는 같은 작업 스트림의 서버 순서이며, 중복·지연 이벤트는 무시한다. documentId·runId·revision·taskId·nodeIds·소유권을 서버와 클라이언트에서 대조한다.
- running은 진행 표시만 허용한다. validated만으로 결과를 공개하지 않는다. persisted 후 해당 Revision의 서버 스냅샷을 가져와 검증된 결과를 반영한다. 미디어는 이 과정에 브라우저 load/decode 성공도 필요하다.
- 텍스트 부분 반영은 별도 검증·저장된 초안 노드/조각 계약이 마련된 경우에만 추가한다. 위 이벤트에 임의 HTML·좌표·평문 콘텐츠를 붙여 우회하지 않는다.
- 부분 초안의 검증과 최종 문서 검증을 구분한다. 완성 전 필수 소스·h1 누락을 통과시키려고 현재 PageSchema 검증기를 느슨하게 만들지 않는다.
- 서버 CAS·원자 저장·멱등 작업 키를 유지한다. 이전 문서나 다른 Revision의 결과는 최신 문서를 덮지 못한다. 재연결은 저장된 상태에서 복구하고 완료 영역을 다시 생성하지 않는다.

## 스타일과 품질의 경계

출력물은 Admin 등록 토큰·활성 사용 정책만 사용한다. 스웜 커서와 편집 박스의 빌더 전용 색상·좌표는 출력 스타일이 아니며 PageSchema, 배포 DOM, HTML 다운로드, 자동 품질검사 측정에 포함하지 않는다. AI는 커서 좌표·속도·진행률·UI CSS를 생성하지 않는다.

## 텍스트·캐럿·커서 관계 보정 · 2026-11-22

현재 영역/컴포넌트 그룹 단위 생성·저장은 유지한다. 박스·비텍스트 등장, 이미지, 완료/실패, 50% 불투명도, 효과 일시정지 동작도 유지한다. 저장된 새 문구만 600ms 단발 Mask Reveal로 공개하고 실제 텍스트 Range 경계에 캐럿을 둔다. 작업 커서는 대상 변경 때 최대 220ms 이동 후 머무르며 반복 횡이동하지 않는다. 텍스트 효과 종료를 기다려 다음 API 요청이나 완료 처리를 하지 않는다. 전체 내용은 DOM에 이미 존재하고 변경·삭제하지 않는다. 중복 응답/뷰포트 전환/재부착/복원에는 재생하지 않고, 효과 정지·화면 숨김·모션 감소·QA 시 clip을 즉시 제거한다. 채팅의 1.8초 반복 Mask Reveal과는 별도 효과다.

## 전체 스켈레톤·데스크톱 우선 · 2026-11-22

계획 저장 직후 모든 계획 셸을 표시하고 콘텐츠가 준비된 단위부터 해당 자리를 채운다. 부모 완료 시 미완성 자식 셸을 보존한다. 내부 기록에는 콘텐츠 완료 개수/전체 작업 개수만 표시하며 스켈레톤을 완료율로 간주하지 않는다. 커서는 현재 작업만 가리키고 미래 셸은 정적인 준비 상태로 구분한다. 내부 소스/이미지는 준비 전 표시하지 않는다.

초기 응답에서 반응형 배치를 함께 설계하되 표시·조작은 데스크톱을 우선한다. 디자인·이미지 준비 후 데스크톱→태블릿→모바일 검사를 수행하고 필요할 때만 기존 자동 보정한다. 출력 게이트에서 화면별 검증을 생략하지 않는다. 600ms 문구 효과는 API 진행을 막지 않는다. 모델/검증 등 실측 시간과 시각적 진행을 분리한다.

## 고객 미리보기와 이미지 요구 연결 (2026-11-22)

- 오른쪽 상단은 요청 요약/페이지 제작 두 단계와 화면 크기 보기만 유지한다. Revision·렌더러·기준 폭·품질 배너·토큰 보고서를 노출하지 않으며 큰 단계 진행/완료/최종 실패 안내만 채팅에 표시하고 세부 재시도·검사 진단은 관리자/운영 로그에 기록한다.
- 초기 안전한 반응형 기본값·세 화면 자동 검사는 유지한다. 완성 후 고객의 명시적 모바일 배치 요청은 mobile override만 변경하며 데스크톱/태블릿/트리/문구/미디어/동작을 보존한다. 변경 후 고객 재승인 없이 내부 재검증·자동 검사·출력 게이트를 적용한다.
- 요청 요약의 명시적 섹션/항목 이미지 의도는 source와 연결하여 노드·생성 요청/등록 이미지 누락을 저장·내부 구조 검증·출력 전에 검사한다. 이미지가 요청되지 않은 모든 카드에 임의 이미지를 추가하지 않는다. 과거 문서에 요구 정보가 없는 경우 추정하지 않고 최신 요약으로 재생성한다.


## 성능 개선과 표시의 경계 — 2026-11-23

- 계획 스켈레톤은 AI가 요청마다 생성한다. 섹션 위치·순서·소스 배정과 공통 디자인 방향을 공유한 독립 작업만 병렬화한다. 전체 구조 검증·저장 전에는 부분 영역 디자인/이미지 단계로 조기 진입하지 않는다.
- 생성이 먼저 끝난 영역은 해당 위치에 검증·저장 후 즉시 반영한다. 앞 영역을 기다리기 위해 완료 결과를 감추지 않으며 미완료 자리는 저장된 계획 셸로 유지한다. 중첩 의존성은 보존한다.
- 동시 활동 커서는 실제 서버 작업 집합에 연결한다. 실제 작업 이벤트가 없는데 커서 수나 가짜 진행률로 병렬 처리를 연출하지 않는다. 12개 시각 풀·불투명도 50%·600ms 일회성 Reveal은 표시 규칙이며 처리 동시성/모델 수를 뜻하지 않는다.
- 완료/실패/취소/재접속 응답은 실행·영역·Revision·버전을 대조하고 중복 효과와 오래된 결과를 차단한다. 독립 이미지와 다음 디자인을 겹쳐도 미디어 load/decode 이전 완료 효과·전체 미디어 준비 전 완성·최종 검사 전 출력을 허용하지 않는다.
- 고객에게 추가 승인·검수·기술 로그를 요구하지 않는다. Admin/운영 기록에서만 단계별 실측·호출·실패·비용을 비교한다. 이 절은 확정 목표이며 런타임 병렬화·운영 성능 개선은 아직 미구현/미측정이다.
