### 2. Server-Side LLM Response Parsing

Parsing was moved out of n8n Code nodes and into Web/API.

Implemented endpoint:

```text
POST /api/promo-generation-integrated-brief-complete
```

Responsibilities:

- Accept raw LLM response from n8n.
- Extract `choices[0].message.content`.
- Parse JSON.
- Validate `integratedDesignBriefMarkdown`.
- Validate `integratedDesignBrief`.
- Validate or recover `finalImagePromptInputs.imagePromptDirection`.
- Store result in `promo_generation_integrated_briefs`.
- Update `promo_generation_runs.status`.

Important fix:

The LLM returned `### Image Prompt Direction` inside markdown but omitted `integratedDesignBrief.finalImagePromptInputs.imagePromptDirection` in JSON. Server normalization now extracts the value from markdown and fills the JSON object automatically.

## Important Test Notes

### n8n Expression Handling

Several issues were caused by n8n treating expressions as literal strings.

Correct approach:

- Prefer `Using Fields Below` over Raw JSON when sending long markdown or base64.
- Use Expression mode for object/array values.
- Avoid embedding long markdown or base64 inside Raw JSON body.

Examples:

```js
{{ $json.variables }}
```

```js
{{ $('Generate LO-FI Draft Image').item.json.data[0].b64_json }}
```

```js
{{ {
  runKey: $json.run.runKey,
  integratedDesignBriefMarkdown: $json.integratedBrief.integratedBriefMarkdown,
  sectionContentMapping: JSON.stringify(
    $json.integratedBrief.integratedBriefJson.sectionContentMapping ||
    $json.integratedBrief.integratedBriefJson.finalImagePromptInputs?.contentCoverage ||
    {},
    null,
    2
  )
} }}
```

## Current Issue

### Private Vercel Blob Blocks Browser Preview

The generated LO-FI draft image was saved and `draftImageUrl` exists, but opening it directly in the browser returns:

```text
Forbidden
```

Cause:

The current Vercel Blob Store is configured as a private store.

Attempted public configuration:

```text
BLOB_ACCESS=public
```

Result:

```text
Vercel Blob: Cannot use public access on a private store.
The store is configured with private access.
```

Conclusion:

This cannot be solved only with `BLOB_ACCESS=public` unless the Blob Store itself supports public access or a new public-capable Blob Store is connected.

Recommended next direction:

```text
Keep private Blob
-> add server image proxy API
-> Web UI displays image through proxy endpoint
```

Example target endpoint:

```text
GET /api/promo-generation-lofi-draft-image?draftId=...
```

The Web UI can then use:

```html
<img src="/api/promo-generation-lofi-draft-image?draftId=..." />
```
