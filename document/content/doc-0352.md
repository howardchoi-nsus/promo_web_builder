## 1. 인수인계 핵심 요약

오늘 작업은 크게 네 축으로 진행됐다.

1. 기존 Visual Editor P1 결함을 수정하고 로컬 안정화 검증을 완료했다.
2. 관리자가 템플릿 기본 레이아웃을 설정하고 Promo Wizard가 이를 사용하는 구조를 구현했다.
3. Promo Wizard와 분리된 독립 `Create Promo` 화면을 생성했다.
4. Create Promo를 새 4단계 흐름으로 개편하고 Step 1~3까지 구현·디버깅했다.

Create Promo의 최종 목표 흐름은 다음과 같다.

```text
Step 1. 배경색 선택
  → Step 2. CTA 버튼 스타일 선택
  → Step 3. 관리자 템플릿 선택 및 콘텐츠 등록
  → Step 4. 웹 출력
```

현재 Step 1~3은 작동한다. Step 4는 제목과 안내 카드만 있는 다음 개발 범위다.

## 2. 오늘 확정된 제품 및 아키텍처 결정

### 2.1 Admin과 Wizard의 책임 분리

- Admin은 재사용 가능한 프로모션 템플릿과 기본 레이아웃을 생성·관리한다.
- Promo Wizard와 Create Promo는 Admin에서 활성화한 템플릿을 사용한다.
- Wizard/Create Promo에서 변경한 콘텐츠와 실행별 레이아웃은 Admin 템플릿에 역반영하지 않는다.
- 사용자 변경은 전용 저장 상태와 별도 Usage Event Log로 관리한다.
- Admin 기본 레이아웃, Wizard Preview와 Web Output은 동일 `PromoPageRenderer`를 사용한다.

### 2.2 Promo Wizard와 Create Promo 분리

- 기존 Promo Wizard는 기존 생성 파이프라인을 유지한다.
- 기존 Promo Wizard의 주요 흐름은 Concept, Content, LO-FI, Final 생성이다.
- Create Promo는 Promo Wizard를 기반으로 복제했지만 상태 키와 화면 진입점을 분리했다.
- 새 4단계 Create Promo 기능은 `prototype/create-promo.*`에만 적용한다.
- Create Promo 변경으로 기존 Promo Wizard 상태나 동작을 수정하지 않는 것이 원칙이다.

### 2.3 Create Promo 스타일 우선순위

Step 3의 최종 렌더링은 다음 순서로 계산한다.

```text
Renderer Default
  → Admin Template Default Layout
  → Create Promo 실행별 레이아웃/콘텐츠 변경
  → Step 1 Background Override
  → Step 2 CTA Override
```

Step 1과 Step 2의 선택값은 Create Promo에서 최종 우선순위를 가진다.

- Step 1은 `backgroundColor`, `textColor`를 결정한다.
- Create Promo Step 3에서는 Admin의 배경 이미지를 제거하고 Step 1 배경색을 적용한다.
- Step 2는 CTA의 색상, 각진/라운드 모양, 채움/고스트 표현 방식을 결정한다.
- Admin 템플릿의 Section 높이, Item 좌표, 폰트, 정렬 등 나머지 레이아웃 속성은 유지한다.

## 3. 참고 디자인 검토 결과

참고한 Claude Design:

- `LO-FI 위저드 하이파이` 공유 디자인
- 원본은 배경색, CTA, 레이아웃, 콘텐츠, LO-FI 확인, 디자인 요청, 완성의 7단계 구조다.

Create Promo에서는 이를 다음처럼 압축하기로 했다.

| 참고 디자인 | Create Promo |
| --- | --- |
| 배경색 | Step 1 배경색 선택 |
| CTA 버튼 | Step 2 CTA 스타일 선택 |
| 레이아웃 + 콘텐츠 | Step 3 템플릿 및 콘텐츠 등록 |
| LO-FI 확인 + 디자인 요청 + 완성 | Step 4 웹 출력 |

채택한 UX 원칙:

- 큰 실시간 Preview를 먼저 보여준다.
- 선택 컨트롤은 Preview 아래에 배치한다.
- 현재 선택은 강조 테두리와 체크 표시로 구분한다.
- 이전 단계로 돌아가도 선택값을 유지한다.
- 필수 콘텐츠가 완료되지 않으면 다음 단계로 진행하지 않는다.

## 10. 다음 LLM을 위한 주의사항

1. Create Promo 변경을 Promo Wizard에 그대로 적용하지 않는다.
2. Admin Template은 기본값의 Source of Truth이며 Create Promo 변경을 Admin에 저장하지 않는다.
3. Step 1·2 Appearance는 Step 3과 Step 4의 최종 렌더링에서 우선 적용한다.
4. Step 3은 Admin Template 구조와 동일 Renderer를 재사용한다.
5. Step 4 구현 전에 Output Snapshot의 소유권과 저장 위치를 먼저 확정한다.
6. Migration 023은 사용자 확인 기준 적용 완료지만 Backfill과 운영 데이터 무결성은 별도 확인한다.
7. 현재 Production URL이 최신 HEAD를 반영한다고 가정하지 않는다.
8. Visual Editor 소스를 수정하면 `npm run build:visual-editor`로 정적 Bundle을 반드시 다시 생성한다.
9. 기존 Worktree 변경을 임의로 되돌리거나 Promo Wizard 상태 키와 Create Promo 상태 키를 합치지 않는다.
