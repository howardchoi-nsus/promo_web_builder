## 지난주 진행 내용

| 주요 Task | 포함된 진행 내용 |
| --- | --- |
| 컴포넌트 기반 템플릿 구조 전환 | 기존 템플릿-섹션 아이템 구조를 재정리하고, 재사용 가능한 컴포넌트와 컴포넌트 인스턴스를 조합하여 섹션을 구성하는 모델을 적용했다. 기본 템플릿과 컴포넌트 데이터를 초기화·재구성하는 마이그레이션 및 시드 흐름을 정비했다. |
| 템플릿·레이아웃 관리 개선 | 템플릿 목록/설정/활성화 흐름을 정리하고, 상단 섹션 추가가 실제 템플릿 구성에 반영되도록 연결했다. 템플릿 설정과 프로모션 빌더의 반영 시점 문제를 점검·보정했다. |
| 공통 편집 엔진 기반 정리 | 프로모션 빌더 Live Preview와 설정의 레이아웃 편집기가 공통 명령·스냅샷·레이아웃 엔진을 사용하도록 정리했다. 텍스트·이미지 영역의 드래그 크기 조절, 이미지 비율/자유 크기 조절, 섹션 선택 시 프리뷰 이동을 개선했다. |
| 프로모션 빌더 UI 개선 | 3단 패널(섹션 / Live Preview / 콘텐츠·속성) 구조, 패널별 독립 스크롤, 컴포넌트 아코디언, Web Output 별도 창 동작을 반영했다. 불필수 헤더·중복 UI를 제거하고 섹션/컴포넌트 속성의 위치를 정리했다. |
| 섹션 AI 이미지 생성 안정화 | 섹션 배경과 컴포넌트 이미지 생성을 구분하고, 생성 결과를 `<img>` 대신 조절 가능한 배경 자산으로 적용하도록 보정했다. 배경 정렬·contain/cover·페이드 모드·삭제 후 재생성 흐름을 개선했다. |
| AI 프롬프트·LLM 제어 관리 | 이미지 생성 프롬프트와 실행 파라미터를 관리자 LLM·프롬프트 관리에서 수정·검증·활성화할 수 있도록 확장했다. 프롬프트 변수 계약 검증, 버전/이력 관리, 이미지 크기·배경 페이드 관련 운영 설정을 보강했다. |
| 자연어 섹션 구성 | 자연어 지시로 기존 컴포넌트를 선택·배치하고 콘텐츠 및 허용된 디자인 토큰을 제안하는 기능을 추가했다. 다중 컴포넌트 정렬 제안, 충돌 자동 보정, CTA URL 명시 검증을 적용했다. |
| 디자인 토큰 관리 | 디자인 토큰을 CSV와 테이블 편집 방식으로 관리하고, 기본 토큰 세트로 GGPoker Dark 값을 반영했다. 템플릿과 토큰 선택을 분리하고, 프로모션 빌더 Step 1에서 토큰을 선택해 실제 색상·글자 크기를 적용하도록 변경했다. |
| 타이포그래피·표시 검증 | 메인 타이틀 68px, 리드 타이틀 40px, 서브타이틀 23px 토큰을 추가했다. Visual Editor에서 색상 견본 및 실제 글자 크기 견본을 확인할 수 있도록 보완했다. |
| 품질·배포 안정화 | Neon 마이그레이션과 프로덕션 배포 절차를 점검했다. AI 제안 적용 시 객체 키 순서 차이를 레이아웃 변경으로 오인하던 문제를 보정했으며, 전체 자동 테스트 66건을 통과했다. |

## 금주 진행 계획

| 우선순위 | 주요 Task | 포함된 진행 내용 (간략) | 완료 기준 |
| --- | --- | --- | --- |
| P0 | Gemini 생성 환경 복구 및 확인 | Gemini API 프로젝트의 선불 크레딧/결제 상태를 복구하고, 섹션 배경·컴포넌트 이미지 각각 1회 이상 생성한다. 현재 생성 실패의 직접 원인은 API 크레딧 소진이다. | API 응답이 `ready` 또는 생성 완료이며 이미지가 화면에 표시됨 |
| P0 | 이미지 삭제 후 재생성 회귀 검증 | 배경 이미지 삭제 → 즉시 재생성 → 적용 → Web Output 확인을 수행한다. 새 실행 식별자와 로컬 실행 상태 초기화가 정상 동작하는지 확인한다. | 동일 섹션에서 재생성 성공, 이전 실행 결과 재사용·적용 충돌 없음 |
| P0 | AI 섹션 제안 적용 회귀 검증 | 제안 생성 후 즉시 적용, 레이아웃 속성 순서만 달라진 상태에서 적용을 각각 확인한다. 실제 레이아웃/콘텐츠가 바뀐 경우에만 새 제안을 요구해야 한다. | 정상 케이스 적용 성공, 실제 변경 케이스만 409 안내 |
| P1 | 이미지 품질·표현 파라미터 검증 | 관리자 설정의 이미지 해상도, 페이드 없음/좌·우·양끝 페이드, 배경색 블렌딩 값을 바꿔 결과를 비교한다. 2K 요청 여부와 생성 결과의 실제 가로 크기도 기록한다. | 설정별 결과표 확보, 테두리·밝은 띠 재현 조건 분리 |
| P1 | 디자인 토큰의 런타임 적용 확대 | GGPoker Dark를 기본값으로 유지하고, 타이틀·리드·서브 타이틀 토큰이 Builder/Editor/Web Output에서 일관되게 적용되는지 점검한다. 컴포넌트의 색상·크기는 허용된 토큰 단계만 선택 가능하게 유지한다. | 세 화면의 색상·크기 값이 동일하고 임의 값 입력 경로 없음 |
| P1 | 선택형 컴포넌트 노출 제어 | 필수값이 아닌 컴포넌트 필드를 사용자 관점에서 표시/숨김할 수 있는 UX를 정의하고 적용한다. 숨김 상태는 프리뷰·Web Output·저장 데이터에 동일하게 반영되어야 한다. | 선택형 필드 on/off 및 출력 제외 동작 확인 |
| P1 | 편집기 기능 동등성 점검 | 프로모션 빌더 Live Preview를 기준으로 설정 레이아웃 편집기의 텍스트/이미지 드래그, 크기 조절, 속성 적용 차이를 목록화하고 공통 엔진으로 흡수한다. | 동일 입력·동일 스냅샷에서 두 진입점 결과 일치 |
| P2 | 관리자 템플릿 관리 UX 정리 | 템플릿 카드의 설정 아코디언, 활성화 토글, 수정·복제·삭제 동선을 정리하고, 섹션 CRUD 로그의 별도 조회 화면 필요성을 확정한다. | 중복된 하단 섹션 관리 UI 없이 상단 동선만으로 템플릿 구성 완료 |
| P2 | 운영 관측성 보강 | AI 생성 실패를 공급자/결제/프롬프트 계약/DB 상태로 구분해 사용자 화면과 로그에 남기는 방안을 설계한다. 재시도 가능 여부와 조치 안내를 오류 유형별로 표준화한다. | 오류 코드별 사용자 안내와 운영 로그 필드 정의 완료 |

## 진행 원칙

- P0의 생성 환경과 회귀 검증을 먼저 종료한 뒤, 이미지 품질 조정과 UI 확장을 진행한다.
- 이미지 결과 품질은 코드 변경 이전에 관리자 프롬프트·LLM 설정값으로 우선 조정하고, 플랫폼 제약으로 재현되는 문제만 코드 보정 대상으로 분리한다.
- 각 개발 단계는 자동 테스트, 브라우저 확인, 프로덕션 배포 확인 순으로 검증한다.
