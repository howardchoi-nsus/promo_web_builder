## 3. 오늘 완료한 기능

### 3.1 섹션 및 아이템 자유 배치

- 기존 Flex 기반 아이템 배치를 제거했다.
- 모든 섹션 아이템은 `position: absolute` 기반으로 독립 배치된다.
- 한 아이템을 이동해도 다른 아이템이 밀리거나 재배치되지 않는다.
- 요소 간 겹침을 허용한다.
- 드래그 중에는 DOM 위치만 갱신한다.
- 드래그 종료 시 최종 위치를 `designSpec.itemStyles`에 저장한다.
- Y 좌표는 섹션 높이 변경에 따라 따라 움직이지 않도록 픽셀값 `yPx`로 저장한다.
- X 좌표는 현재 `xPct` 비율값을 사용한다.

### 3.2 아이템 크기 처리

- `.rendered-item--text`의 `720px` 고정 폭을 제거했다.
- 텍스트와 이미지 article의 유형별 고정 폭을 제거했다.
- article은 `width: fit-content` 기준으로 콘텐츠 크기에 맞춰진다.
- 이미지 placeholder 및 설명의 남아 있던 `max-width` 제한도 제거했다.

### 3.3 텍스트 편집 및 디자인 속성

- 텍스트를 더블클릭하면 직접 편집할 수 있다.
- 빈 텍스트는 기본 Lorem Ipsum으로 편집을 시작한다.
- 글자 색상, 크기, 굵기, 정렬을 CONTENT 패널에서 변경할 수 있다.
- 아이템별 스타일은 `designSpec.itemStyles`에 저장된다.
- DESIGN 초기화는 해당 아이템의 `itemStyles` 항목을 삭제한다.
- 초기화 후에는 `DEFAULT_DESIGN_SPEC`와 Renderer 기본 CSS를 사용한다.

현재 `DEFAULT_DESIGN_SPEC`:

```js
{
  contractVersion: 1,
  specKey: "default",
  theme: {
    backgroundColor: "#f5f7fb",
    backgroundImage: "",
    backgroundImageName: "",
    textColor: "#172033",
    accentColor: "#156b5b",
    fontFamily: "Inter, Pretendard, sans-serif"
  },
  responsive: {
    contentMaxWidth: 1440,
    contentMinWidth: 1140,
    mobileBreakpoint: 720
  },
  itemStyles: {},
  sectionStyles: {}
}
```

### 3.4 섹션 높이 조절

- 모든 섹션의 기본 최소 높이는 `50px`이다.
- 섹션 하단 핸들을 드래그해 높이를 조절할 수 있다.
- 핸들 스타일:

```css
width: 54px;
height: 10px;
border-radius: 20px;
bottom: -5px;
```

- 핸들 내부의 별도 선 요소는 제거했다.
- 섹션을 줄일 때 가장 아래 아이템의 실제 하단 위치를 계산한다.
- 아이템이 섹션 밖으로 나가기 전 높이 축소가 멈춘다.
- 섹션 리사이즈 시작 시 아이템의 Y 위치를 픽셀로 고정한다.
- 잠금 아이템도 리사이즈 중 위치 고정 계산에는 포함된다.
- 리사이즈 종료 시 `event.currentTarget`이 `null`이 되어 발생하던 런타임 오류를 수정했다.

### 3.5 편집 가이드

- Live Preview 상단에 `Guides ON/OFF` 토글을 추가했다.
- ON:
  - 최대 콘텐츠 폭 점선 표시
  - 섹션 구분선 표시
  - 섹션 높이 조절 핸들 표시
- OFF:
  - 모든 가이드 및 리사이즈 핸들 숨김
- Web Output에는 가이드가 출력되지 않는다.

콘텐츠 폭:

```text
max: 1440px
min: 1140px
```

### 3.6 페이지 배경

- 전역 배경 컬러 토큰을 적용할 수 있다.
- 섹션별 개별 배경 설정은 지원하지 않는다.
- 페이지 전체 배경 이미지를 파일로 첨부할 수 있다.
- 이미지 교체 및 제거 기능을 제공한다.
- 최대 파일 크기는 3MB이다.
- Data URL을 `designSpec.theme.backgroundImage`에 저장한다.
- 배경 이미지는 다음 방식으로 렌더링된다.

```css
background-position: center;
background-size: cover;
background-repeat: no-repeat;
```

- 배경 컬러는 이미지 미설정 또는 투명 영역의 fallback으로 유지된다.
- Web Output에도 동일한 배경 이미지가 반영된다.

### 3.7 Renderer 외형

- `.promo-renderer`에 `border-radius: 15px`를 적용했다.
- 내부 콘텐츠가 모서리 밖으로 나오지 않도록 `overflow: hidden`을 적용했다.
- Web Output에는 섹션 border 및 편집 가이드가 표시되지 않는다.

### 3.8 SECTIONS 아코디언

- 기존 하단의 별도 `ITEMS` 영역을 제거했다.
- 섹션을 누르면 해당 섹션 아래에 아이템 목록이 펼쳐진다.
- 같은 섹션을 다시 누르면 닫힌다.
- 다른 섹션을 누르면 기존 섹션은 닫히고 선택 섹션만 열린다.
- 섹션을 열면 첫 번째 아이템이 자동 선택된다.
- 아이템이 없는 섹션도 오류 없이 처리한다.
- 열림 및 닫힘 애니메이션을 적용했다.

### 3.9 랜딩페이지

- Root 랜딩페이지에 네 번째 `Visual Editor` 카드를 추가했다.
- 랜딩 카드 구성:
  - Promo Wizard
  - Promo Builder
  - Admin
  - Visual Editor
- 데스크톱은 2열, 모바일은 1열이다.
- Visual Editor 링크는 `/prototype/visual-editor.html`을 사용한다.

## 5. 배포 404 이슈

### 5.1 원인

Vercel `cleanUrls: true` 환경에서 실제 파일은 다음 위치에 있다.

```text
prototype/visual-editor.html
prototype/visual-output.html
prototype/visual-editor-assets/*
```

하지만 초기 구현은 아래 root 경로를 사용했다.

```text
/visual-editor.html
/visual-editor-assets/*
/visual-output.html
```

그 결과 `/visual-editor.html`이 `/visual-editor`로 리다이렉트된 뒤 `NOT_FOUND`가 발생했다.

### 5.2 수정

모든 관련 경로를 `/prototype` 기준으로 통일했다.

```text
/prototype/visual-editor.html
/prototype/visual-output.html
/prototype/visual-editor-assets/visual-editor.css
/prototype/visual-editor-assets/visual-editor.js
```

수정 대상:

- Root 랜딩 Visual Editor 카드
- Promo Builder 상단 Visual Editor 메뉴
- Visual Editor HTML의 CSS/JS
- Visual Output HTML의 CSS/JS
- Web Output 열기
- Visual Editor로 돌아가기

### 5.3 현재 상태

- 로컬 경로와 자산은 HTTP `200 OK` 확인 완료

## 7. 현재 이슈 및 주의사항

### 7.1 실제 브라우저 수동 검수 필요

다음 항목은 코드 및 계약 테스트를 통과했지만 실제 브라우저 조작 검수가 필요하다.

- 섹션 아이템 아코디언 열림/닫힘
- CONTENT 패널과 선택 아이템 연동
- 콘텐츠 자유 드래그 시 형제 아이템 무간섭
- CTA가 섹션 리사이즈 중 고정 위치를 유지하는지
- 섹션이 CTA 하단 위치까지만 줄어드는지
- 배경 이미지 첨부, 교체, 제거
- Guides OFF 시 리사이즈 핸들까지 숨겨지는지
- Web Output에서 편집 가이드가 표시되지 않는지

### 7.2 배경 이미지 저장 방식

현재 배경 이미지는 Data URL로 Snapshot 및 localStorage에 저장한다.

주의:

- 파일은 3MB 이하로 제한했지만 브라우저 localStorage 용량에 가까워질 수 있다.
- 향후 운영 단계에서는 Vercel Blob 등의 파일 저장소로 전환하는 것이 권장된다.
- 현재 방식은 P0 로컬 및 PoC 검증용이다.

### 7.3 기본 레이아웃 데이터

현재 기본 아이템 좌표는 관리자 템플릿에서 제공하지 않는다.

- Renderer의 `defaultItemPosition()`이 초기 위치를 계산한다.
- 초기 높이는 아이템 유형별 추정값을 사용한다.
- 관리자 템플릿에 초기 디자인 좌표, 폭, 높이, 타이포그래피를 저장하는 기능은 아직 없다.

### 7.4 반응형 좌표

- Y 좌표는 픽셀값이다.
- X 좌표는 비율값이다.
- 데스크톱 편집 결과가 모바일에서 최적 배치되는 별도 responsive override는 아직 없다.
- 모바일 출력 품질을 위해 breakpoint별 좌표 스펙이 추후 필요하다.

### 7.5 Git 상태

오늘 작업은 HEAD `c0f481c`에 반영되어 `origin/main`과 일치한다.

추적되지 않은 항목:
