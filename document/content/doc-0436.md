# 실제 영역별 와이어프레임 생성 V2 적용 순서

2026-11-21 · 개발 반영 · 운영 배포·실제 LLM 연동 검증 전

## 변경점

V1의 전체 트리 생성 후 빈 문구 추가 방식 대신, 첫 호출은 가벼운 계획만 만들고 이후 각 영역/컴포넌트 그룹을 생성·검증·저장·표시한다. 최대 12개 작업 단위, 각 48노드, 전체 200노드·깊이 8·이미지 요청 8개 한도를 유지한다. 커서 수는 모델 병렬 실행 수가 아니다.

## 운영 준비

1. 수정 코드를 배포할 버전으로 준비한다. 아직 이 개발 요청으로 운영에 배포하지 않았다. 전환 대상에서 PAGE_SCHEMA_DRAFT_ENABLED가 이미 true라면 V2 설정 준비 동안 false로 두고, 코드·096·두 프롬프트 활성화를 마친 뒤 true로 전환한다. 그렇지 않으면 전환 사이의 신규 생성은 V2 설정 필요 오류로 차단된다.
2. 기존 094·095가 적용돼 있다면 **096_page_draft_units_v2.sql만 추가 실행**한다. 새 테이블은 만들지 않고 기존 초안 JSON 상태를 사용한다.
3. Admin 프롬프트 관리에서 아래 두 새 Draft를 검토한다. 기존 V1 프롬프트와 혼동하지 않는다.

| Admin 표시 이름 | 타입 | 설정 출처 |
|---|---|---|
| 페이지 제작 · 작업 계획 V2 | promo_page_manifest_planner | 기존 promo_page_outline_planner의 모델·실행·스킬 설정 |
| 페이지 제작 · 영역 구성 V2 | promo_page_region_builder | 기존 promo_page_fragment_writer의 모델·실행·스킬 설정 |

4. 두 Draft의 등록 모델·실행 Snapshot V2 이상·변수 계약·연결 스킬 호환성을 확인하고 검증·활성화한다. migration이 넣는 modelOptions.pageDraftContractVersion=2는 유지한다. 새 글로벌 스킬이나 별도 모델 등록은 필수가 아니다. 연결된 스킬이 비활성이면 활성화 또는 명시적 연결 해제가 필요하다.
5. 위 준비가 끝나면 PAGE_SCHEMA_DRAFT_ENABLED=true로 설정한다. 영역 디자인은 기존 PAGE_SCHEMA_SECTION_DESIGN_ENABLED 및 활성 프롬프트를 사용하며 별도 단계다.
6. 실제 Preview LLM·테스트 DB·Blob 여정 검증 후 Production에 반영한다. 현재 외부 연결 검증과 Vercel Ready는 미확인이다.

096은 이전 활성 프롬프트를 변경하거나 자동 활성화하지 않는다. 원본 타입의 active/draft가 없으면 해당 V2 Draft는 만들어지지 않으므로 원본 설정부터 확인한다. 이미 존재하는 신규 V2 타입은 덮어쓰지 않는다. 진행 중인 V1 초안에는 기존 타입을 유지해야 복구할 수 있다.

## 확인 포인트

- 새 페이지 요청에서 첫 응답에 전체 콘텐츠가 나오지 않고 계획된 전체 빈 영역/그룹 스켈레톤이 보인다. 아직 생성되지 않은 콘텐츠는 포함하지 않는다.
- 첫 영역을 확인할 때 다음 영역은 아직 생성 중이다. 승인된 문구만 있는 요청도 동일하다.
- 실제 작업 영역에 50% 커서/박스가 표시된다. 실패 시 진행 효과가 멈추며 완료 영역은 유지된다.
- 실패 후 새로고침해도 저장된 영역이 모델 재호출 없이 복원되고 실패한 단계부터 재시도할 수 있다.
- 마지막 영역까지 화면에 반영한 다음 전체 조립·검증을 거쳐 구성 승인 CTA가 나타난다.
- 모션 감소나 효과 일시정지, 배경 탭에서도 실제 생성·저장 흐름을 지연하지 않는다.

## 호환 범위

새 작업만 V2 타입을 사용한다. 진행 중 V1 초안은 이전 타입으로 재개한다. 이미 저장된 페이지의 전체 수정/에디터 경로와 플래그 비활성 경로는 이 누적 신규 생성과 별개이며, 지원하지 않는 스트리밍 효과로 표시하지 않는다. 최종 PageSchema·에디터·디자인·QA·HTML 출력 계약은 유지한다.
