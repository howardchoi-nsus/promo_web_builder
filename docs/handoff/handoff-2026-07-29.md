## 3.5 섹션 AI 이미지 생성 재시도·진행 상태 복구

### 기존 증상

- 생성 요청이 `409 Conflict`를 반환
- Asset Job은 `processing`이지만 이미지가 끝까지 생성되지 않음
- Provider의 `Requested entity was not found` 이후 재생성이 막힘
- 이미지를 삭제하고 다시 생성하면 높은 확률로 실패

### 보완 내용

- Asset Job 처리 시 lease token과 lease 만료시간 적용
- 처리 중인 정상 Job은 오류 대신 `202 processing` 반환
- lease가 만료된 `processing` Job은 다시 획득 가능
- 실패 Job은 `next_retry_at`, `current_attempt`, `max_attempts` 기준으로 재시도
- Provider 404를 `PROVIDER_ENTITY_NOT_FOUND`로 정규화
- 404·408·409·425·429·5xx·timeout을 재시도 가능 오류로 분류
- 처리 완료 시 lease 정보 제거
- 클라이언트는 `processing`, `waitingRetry`, `canRetry` 상태에 따라 폴링 또는 재처리
- 생성 중인 섹션 배경과 컴포넌트 필드에 진행 상태 표시

- `api/promo-section-design-asset-retry.js`
- `api/promo-section-design-assets.js`
- `prototype/create-promo.js`
- `prototype/wizard/wizard-core.js`
- Visual Editor Section AI 상태 컴포넌트

## 3.8 프롬프트 영문·한글 2열 편집기

프롬프트 본문 영역을 다음과 같이 변경했다.

```text
왼쪽: 영문 원문
오른쪽: 한글 번역
```

영문 원문:

- 초안 버전만 편집 가능
- DB의 `prompt_templates.body`에 저장
- 실제 LLM 실행에 사용
- 한글 문자가 포함되면 클라이언트 저장 차단
- API에서도 `PROMPT_BODY_ENGLISH_REQUIRED`로 저장 차단

한글 번역:

- 읽기 전용
- DB에 저장하지 않음
- 실제 실행에 사용하지 않음
- 프롬프트 선택 시 자동 생성
- 입력을 멈춘 뒤 자동 갱신
- `번역 새로고침`으로 수동 재요청 가능
- 같은 프롬프트·본문의 번역은 현재 브라우저 세션에서 캐시

복사:

- `프롬프트 본문` 제목 오른쪽에 복사 아이콘 추가
- 영문 원문 전체를 Clipboard에 복사
- Clipboard API가 없을 때 기존 브라우저 복사 방식으로 fallback

## 3.9 프롬프트 한글 번역 API

신규 API:

```http
POST /api/prompt-template-translate
Content-Type: application/json

{
  "text": "English prompt body"
}
```

특징:

- OpenAI Responses API 사용
- 한글 번역만 반환
- 줄바꿈·목록·JSON·Markdown·URL·식별자 보존 지시
- `{{placeholder}}` 목록을 번역 전후 비교
- placeholder가 변경·누락되면 결과 거부
- 최대 입력 길이 100,000자
- `Cache-Control: no-store`
- 동일 Origin 관리자 요청만 허용
- Vercel `maxDuration: 60`

필수 환경변수:

```text
OPENAI_API_KEY
```

선택 환경변수:

```text
ADMIN_PROMPT_TRANSLATION_MODEL
```

모델 선택 우선순위:

```text
ADMIN_PROMPT_TRANSLATION_MODEL
→ SECTION_LAYOUT_MODEL
→ gpt-4.1-mini
```

관련 파일:

- `api/prompt-template-translate.js`

```text
Unsupported engine: wanted node 22.x, current node v24.x
```

모든 테스트와 빌드는 통과했지만 Production Vercel Runtime은 `package.json`의 Node 22.x 기준으로 확인한다.

## 5. 알려진 제약 및 잔여 위험

### 5.1 번역 비용

- 프롬프트 번역은 OpenAI API 호출 비용을 사용한다.
- 같은 브라우저 세션에서는 프롬프트 ID와 본문 기준으로 캐시한다.
- 새 브라우저 세션에서는 다시 번역될 수 있다.
- 비용이 문제가 되면 후속으로 다음 중 하나를 결정해야 한다.
  - 자동 번역 대신 명시적 `번역 보기` 요청 방식
  - 번역 결과 DB 저장 및 원문 hash 기반 재사용
  - 서버 캐시 도입

### 5.2 영문 입력 판정 범위

- 현재 서버·클라이언트 제한은 한글 문자 포함 여부를 검사한다.
- 한국어 입력은 차단하지만 중국어·일본어 등 모든 비영문 언어를 판별하는 언어 감지는 아니다.
- 엄격한 ASCII/영어 전용 정책이 필요하면 URL, JSON, 기호와 다국어 고유명사 허용 범위를 먼저 정의해야 한다.

### 5.3 번역 보존 계약

- 현재 자동 검증은 `{{placeholder}}` 보존을 강제한다.
- 다른 템플릿 문법(`${...}`, `<%...%>` 등)은 별도 자동 검증 대상이 아니다.
- 현행 Prompt Contract는 `{{...}}`를 사용하므로 현재 범위에는 적합하다.

### 5.4 Same-Origin

- 번역 API는 요청 `Origin`과 `Host`가 일치해야 한다.
- Vercel Custom Domain과 Proxy Header가 정상 전달되는지 Production Network에서 확인해야 한다.
- 실패 시 응답 코드:

```text
PROMPT_TRANSLATION_ORIGIN_REQUIRED
```

### 5.5 키비주얼 콘텐츠 관련성

- 등록 문구를 이미지에 노출하지 않는 계약은 자동 검증했다.
- 콘텐츠 분위기가 충분히 반영되는지는 이미지 모델 결과에 대한 정성 검토가 필요하다.
- 범용 포커 이미지로 회귀하면 소스 안전 계약을 수정하기 전에 활성 `section_background_image` 프롬프트와 관리자 추가 지침을 먼저 조정한다.

### 5.6 이미지 재시도

- lease와 retry 경로는 코드·브라우저 계약 테스트가 완료됐다.
- 실제 Provider의 404, 429, timeout 상황은 운영 환경에서 최종 확인이 필요하다.
