# Promo Web Builder Handoff — 2026-07-27

## 1. 오늘 작업 목표

프로모션 빌더의 시작점을 디자인 토큰 선택이 아닌 프로모션 개요 입력으로 변경하고, 입력된 개요를 기준으로 템플릿 추천과 사용자 전용 AI 구성 초안을 제공하는 흐름을 구현했다.

최종 사용자 흐름:

```text
1. Overview
2. Template
3. Layout & Design
4. Web Output
```

핵심 원칙:

- Overview를 먼저 확정한다.
- 정형 입력과 자연어 입력은 동일한 데이터 모델을 사용한다.
- LLM 결과는 사용자 승인 전까지 실제 작업 상태에 적용하지 않는다.
- 추천은 서버 Rule Base를 우선하고 LLM은 의미 기반 순위만 보조한다.
- AI 구성 초안은 현재 프로모션 세션에만 적용하며 관리자 템플릿 원본을 변경하지 않는다.
- LLM은 서버가 제공한 템플릿·섹션·컴포넌트·필드 ID만 선택할 수 있다.
- 임의 URL, 자유 CSS/HTML 및 관리자 엔티티 생성을 허용하지 않는다.

### 2.2 표준 Promotion Overview 모델

신규 표준 모델:

```json
{
  "schemaVersion": 2,
  "inputMode": "structured",
  "rawNaturalLanguage": "",
  "title": "",
  "promotionPurpose": "",
  "promotionPurposeOther": "",
  "market": "",
  "audience": "",
  "campaignTone": "",
  "mainOffer": "",
  "primaryAction": {
    "label": "",
    "url": ""
  }
}
```

반영 사항:

- 기존 `promo`, `simpleBrief` 데이터와 표준 Overview 간 호환 모듈을 추가했다.
- 정형 입력에 핵심 혜택, CTA 문구, CTA URL을 추가했다.
- 목적·대상 고객·캠페인 톤의 허용값을 클라이언트와 서버에서 동일하게 정규화한다.
- `기타` 목적이 아닌 경우 남아 있던 기타 목적 값을 제거한다.
- CTA URL은 HTTP/HTTPS URL만 허용하고 표준 URL 형식으로 정규화한다.

주요 파일:

- `prototype/wizard/promotion-overview.js`
- `prototype/wizard/wizard-content.js`
- `api/_promo-overview-contract.js`

### 2.3 자연어 Overview 분석

신규 API:

```http
POST /api/promo-overview-parse
```

기능:

- 자유 입력 문장을 표준 Overview로 구조화한다.
- 분석 요약과 신뢰도를 표시한다.
- 누락 필드와 불확실한 필드를 별도로 표시한다.
- 사용자가 `분석 결과 적용`을 눌러야 실제 Overview에 반영한다.
- 사용자가 입력하지 않은 CTA URL을 LLM이 생성하면 서버에서 제거한다.
- 이전 요청의 늦은 응답은 request ID와 fingerprint로 폐기한다.

관리자 프롬프트 유형:


### 2.4 템플릿 추천

신규 API:

```http
POST /api/promo-template-recommendations
```

처리 순서:

1. 활성 템플릿만 조회
2. 마켓 등 필수 조건으로 Rule Base 후보 필터
3. 목적·대상·톤·태그·필수 입력으로 Rule Base 점수 계산
4. 서버 후보만 LLM에 전달
5. LLM은 후보 순위와 이유만 보조
6. LLM 실패 시 Rule Base 결과로 폴백
7. 적합 후보가 없으면 기본 템플릿과 전체 목록 제공

표시 정보:

- 추천 순위
- 점수
- 추천 이유
- 주의사항
- 추가 확인이 필요한 필드

Overview가 변경되면 기존 추천은 삭제하지 않고 stale 상태로 표시하며 추천 근거로 사용하지 않는다.

관리자 프롬프트 유형:

```text
promo_template_recommender
```

추천 메타데이터:

```json
{
  "promotionTypes": [],
  "markets": [],
  "audiences": [],
  "tones": [],
  "supportedComponentRoles": [],
  "requiredInputs": [],
  "requiredNotices": [],
  "tags": []
}
```

주요 파일:

- `api/_promo-template-recommendation-contract.js`
- `api/promo-template-recommendations.js`
- `api/_wizard-form-templates-store.js`
- `api/wizard-form-template.js`
- `api/wizard-form-templates.js`
- `api/wizard-form-templates-public.js`
- `prototype/app.js`
- `prototype/index.html`

### 2.5 AI 구성 초안

신규 API:

```http
POST /api/promo-template-composition-plan
```

기능:

- 추천 후보 또는 활성 템플릿 중 하나를 선택한다.
- 선택 템플릿에 실제 등록된 활성 섹션과 컴포넌트 버전만 사용한다.
- Overview 필드를 템플릿 컴포넌트에 매핑한다.
- 고정 위치 섹션을 누락할 수 없다.
- 컴포넌트가 속하지 않은 섹션에 배치되는 것을 차단한다.
- 자유 레이아웃 명령은 1차 구현에서 허용하지 않는다.
- 관리자 템플릿 DB 레코드를 생성하거나 수정하지 않는다.
- 사용자 승인 후 현재 프로모션 세션에만 적용한다.
- 사용자가 직접 변경한 콘텐츠는 템플릿 기본값보다 우선해 유지한다.

관리자 프롬프트 유형:

```text

```

주요 파일:

- `api/_promo-template-composition-contract.js`
- `api/promo-template-composition-plan.js`

## 4. 운영 디버깅 및 수정 사항

### 4.1 템플릿 섹션 상태 표시 불일치

증상:

- 템플릿에 포함된 모든 섹션이 목록에서는 활성으로 표시됨
- 섹션 상세을 열면 활성화 버튼이 표시되거나 템플릿 활성화 검증에서 `ACTIVE_SECTION_REQUIRED` 발생

원인:

- 목록은 동일 `sectionKey`에서 활성 버전을 우선 표시했다.
- 상세 선택은 초안 버전을 우선 선택했다.
- 템플릿 검증은 화면 표시가 아니라 membership에 연결된 실제 `section_id` 상태를 검사했다.

수정:

- 템플릿 목록은 `templateMembership.sectionId`, `sectionStatus`, `sectionVersion`을 기준으로 표시
- 목록에서 섹션 선택 시 membership에 연결된 정확한 버전을 조회
- 템플릿 활성화 실패 메시지에 섹션 이름·버전·상태 표시
- `inactive` 섹션도 API 정책에 맞게 활성화 버튼 표시

확인 결과:

- 문제 섹션 활성화 성공
- 템플릿 활성화 성공

주요 파일:

- `prototype/app.js`
- `prototype/index.html`
- `prototype/admin-assets/admin-app.js`

### 4.2 Overview fingerprint 알고리즘 불일치

증상:

```json
{
  "code": "OVERVIEW_FINGERPRINT_MISMATCH"
}
```

1차 원인:

- 브라우저는 FNV fingerprint 사용
- 서버는 SHA-256 fingerprint 사용

1차 수정:

- 서버를 브라우저와 동일한 FNV 계약으로 통일

2차 원인:

- 알고리즘 통일 후에도 브라우저와 서버의 정규화 규칙이 달랐다.
- 기타 목적 잔여값, enum 처리, CTA URL 정규화에서 차이가 발생했다.

2차 수정:

- 목적·대상·톤 허용값을 동일하게 적용
- 기타 목적 제거 조건 통일
- URL 검증 및 canonical URL 변환 통일
- 클라이언트·서버 교차 fingerprint 테스트 추가
- 브라우저 캐시 버전을 `promotion-overview-v2`로 갱신

확인 결과:

- 템플릿 추천 fingerprint 오류 해결
- 구성 초안 요청이 실제 LLM schema 검증 단계까지 진행됨

### 4.3 AI 구성 초안 strict JSON Schema 오류

증상:

```text
Invalid schema for response_format 'promo_template_composition'
layoutCommands.items.additionalProperties is required
```

원인:

- `layoutCommands`는 빈 배열만 허용하지만 `items`를 객체로 선언하면서 OpenAI strict JSON Schema 필수 조건을 누락했다.

수정:

```json
{
  "type": "object",
  "additionalProperties": false,
  "properties": {},
  "required": []
}
```

검증:

- 구성 초안 계약 테스트 통과
- Section AI Provider 계약 테스트 통과
- Create Promo 브라우저 스모크 테스트 통과

현재 중요 상태:

- 이 마지막 strict schema 수정은 실제 프로젝트 파일에는 반영되어 있다.
- 아직 Git 커밋·푸시는 되지 않았다.

## 8. 완료 기준

- AI 구성 초안 API가 strict schema 오류 없이 `200`을 반환한다.
- 서버 응답의 `overviewFingerprint`가 현재 브라우저 Overview와 일치한다.
- 구성 초안은 활성 후보 템플릿·섹션·컴포넌트만 포함한다.
- 사용자 승인 전에는 현재 프로모션 상태를 변경하지 않는다.
- 적용 후 관리자 템플릿 원본과 DB 템플릿 구성이 변경되지 않는다.
- Layout 및 Web Output에 사용자 세션 전용 구성 결과가 반영된다.
- 관련 테스트가 계속 통과한다.
