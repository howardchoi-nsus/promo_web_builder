## 3.3 Preview 직접 텍스트 입력·수정 복구

증상:

- Live Preview에서 텍스트를 직접 더블클릭해 수정하는 기능이 동작하지 않았다.

원인:

- Component drag가 `pointerdown`에서 즉시 pointer capture를 수행했다.
- 브라우저의 후속 click/dblclick target과 기본 텍스트 selection이 drag 처리에 의해 방해받았다.

수정:

1. `pointerdown`에서는 시작 좌표만 기록한다.
2. 실제 이동이 drag threshold를 넘을 때 drag를 활성화한다.
3. pointer capture와 `preventDefault()`를 drag 활성화 후로 늦춘다.
4. article capture 단계의 double-click fallback을 추가한다.
5. 편집 중에는 Component drag보다 text selection을 우선한다.
6. 여러 줄 입력을 plain string 개행으로 저장한다.
7. 편집 진입 시 기존 좌표·anchor·크기를 유지한다.

결과:

- Preview에서 직접 입력·수정 가능
- 텍스트 선택 시 좌측 상단 이동 없음
- 클릭/더블클릭과 drag가 분리됨
- Bullet/Number text의 직접 편집 가능

## 3.4 Bullet·Number와 Indent·Outdent

Toolbar에 Font Awesome icon 기반으로 다음을 추가·연결했다.

```text
fa-list-ul    Bullet
fa-list-ol    Number
fa-outdent    내어쓰기
fa-indent     들여쓰기
```

동작:

- Bullet/Number는 toggle이다.
- 같은 list type을 다시 누르면 선택 범위에서 해제한다.
- Indent/Outdent는 list가 적용된 경우에만 사용할 수 있다.
- `listIndent` 허용 범위는 정수 `0..6`이다.
- Outdent는 0에서 disabled, Indent는 6에서 disabled다.
- Renderer는 indent 단계에 따라 list padding을 계산한다.

검증 위치:

```text
visual-editor/src/layout-utils.mjs
api/_wizard-form-template-layout-store.js
api/_promo-section-design-contract.js  // top-level list style
```

## 3.5 선택 라인 단위 텍스트 서식

요구사항:

- Bold, Text Color, Bullet, Number 등은 전체 Component가 아니라 선택된 텍스트 라인만 적용·해제한다.

구현 모델:

- 콘텐츠는 기존 newline-delimited plain string 유지
- 서식은 `itemStyle.lineStyles`에 분리 저장
- 단일 Text Item scope: `$item`
- 다중 field Component scope: `fieldKey`
- 라인 index: 0-based

예:

```json
{
  "lineStyles": {
    "$item": {
      "0": {
        "fontWeight": 700,
        "listType": "bullet",
        "listIndent": 1
      },
      "1": {
        "colorToken": "--promo-color-text"
      }
    }
  }
}
```

라인에 적용되는 속성:

```text
Text Style
Font Family / Size / Weight
Bold / Italic
Font Color / Gradient
Text Background
Line Height / Letter Spacing
Bullet / Number
Indent / Outdent
```

Component 범위로 유지되는 속성:

```text
Undo / Redo command state
Section horizontal/vertical placement
Component position / size
```

## 3.6 라인 선택과 Toolbar 상태

`PromoPageRenderer.vue`가 편집 중 `selectionchange`를 관찰한다.

```text
DOM selection
→ data-text-line-index 계산
→ select-text-lines emit
→ PreviewPanel lineSelection
→ TextEditorControls
```

처리 규칙:

- caret이 있는 라인 하나를 선택 라인으로 해석
- 여러 라인 drag selection은 포함된 모든 index 전달
- Item 선택 변경 시 이전 selection 초기화
- selection이 없으면 라인 서식 컨트롤 disabled
- 선택 라인 값이 섞여 있으면 mixed state로 취급
- Toolbar 한 번의 patch는 한 번의 Undo 단위

## 3.7 라인 Renderer

라인별 서식이 있으면 `.rendered-text--lines`와 `.rendered-text-line` 구조로 렌더링한다.

지원:

- 일반 라인과 Bullet/Number 라인 혼합
- 라인별 Typography, Color/Gradient, Background
- 라인별 list marker
- CSS counter 기반 Number
- line별 indent padding

기존 전체 Component list는 lineStyles가 없을 때 semantic `ul/ol` 경로를 유지한다.

## 3.8 API·AI 경계

Client/API가 함께 검증하는 항목:

- lineStyles/object shape
- scope object
- line index `0..999`
- 허용 property
- token key pattern(`--promo-*`, `--app-*`)
- list type enum
- `listIndent 0..6`

AI 경계:

- `_promo-section-design-contract.js`는 Component-level `listType`, `listIndent`를 허용한다.
- `lineStyles`는 AI style allowlist에 넣지 않았다.
- 따라서 AI가 임의 라인별 Rich Text를 만들 수 없고, 라인 서식은 사용자 명시 편집 결과로만 저장된다.

문서 검토 중 확인한 Validator 보완점:

- lineStyles 내부 raw typography 값의 type/range를 별도로 제한하지 않는다.
- lineStyles의 `fontStyle`, `textDecoration` enum을 별도로 검증하지 않는다.
- token key는 pattern만 확인하며 실제 등록·활성 token 여부는 확인하지 않는다.
- Content Layer에서도 현재 `--app-*` pattern이 통과해 통합 정책의 Layer A/B 분리보다 넓다.

정상 Toolbar는 관리된 option만 emit하고 AI는 lineStyles를 만들 수 없지만, API 직접 입력까지 정책에 맞추려면 후속 contract hardening이 필요하다. 이번 문서 작업에서는 소스 수정 범위로 확대하지 않았다.

## 6. 알려진 제약 및 이슈

### 6.1 line index와 콘텐츠 변경

`lineStyles`는 line index 기반이다. 중간에 줄을 삽입·삭제하면 뒤쪽 스타일의 의미가 한 줄씩 어긋날 수 있다.

후속 권장:

- 콘텐츠 확정 시 line diff를 계산해 lineStyles index remap
- 장기적으로 안정적인 lineId를 갖는 versioned text document 검토

### 6.2 문자 일부 서식 미지원

현재 최소 단위는 라인이다. 한 라인 안 일부 단어만 Bold/Color를 적용하는 inline range model은 없다. 이를 추가하려면 별도 schema, sanitization, clipboard, IME, selection mapping 설계가 필요하다.

### 6.3 혼합 List의 semantic HTML

lineStyles 기반 혼합 list는 div line + CSS marker/counter로 렌더링된다. 시각 동작은 완료됐지만 screen reader를 위한 연속 list grouping과 semantic `ul/ol/li` 변환은 후속 개선 대상이다.

### 6.4 실제 API save/reopen

브라우저 기능 확인과 local fixture 복원은 완료했다. 실제 API 저장 후 재진입, 동시에 열린 편집기의 `DOCUMENT_REVISION_MISMATCH`, 충돌 rebase까지 포함한 E2E는 미실시다.

### 6.5 Desktop/Mobile

- Text lineStyles의 viewport별 override 조합을 실제 저장·재진입으로 충분히 확인하지 않았다.
- Motion은 현재 Desktop/Mobile 공통 적용이다.
- viewport별 Motion이 필요하면 별도의 `motionSpec.responsive` 계약이 필요하다.

### 6.6 정적 Preview의 API 제한

`127.0.0.1:4176`은 정적 서버이므로 `/api/promo-section-structure-*` 호출은 404다. API 통합 오류로 오인하지 말고 Vercel Dev 또는 배포 환경에서 확인한다.

### 6.7 Production 미확인

이 handoff 작성 시 Vercel Deployment와 운영 DB는 확인하지 않았다. 원격 main 반영과 Production Ready는 별개다.

### 6.8 lineStyles Validator 정책 격차

현재 구현은 shape, property allowlist, token pattern, list enum/indent를 검사한다. raw typography value, line enum, 실제 token registry, Content Layer의 `--app-*` 차단은 아직 정책 수준만큼 강제하지 않는다.
