## 3. 현재 시스템 방향과 핵심 계약

기존의 “Template 선택 후 일부 내용 변경” 방식에서 다음 Registry Composition 구조로 전환 중이다.

```text
자연어 요구사항
→ Overview/Intent 구조화
→ active Composition Shell 조회
→ Registry Section/Component/Layout/Resource 후보 결정
→ Contract v3 CompositionSpec 생성 및 검증
→ 사용자 Proposal 확인·승인
→ 결정적 Compiler로 Builder Document 생성
→ 공통 Visual Editor/Renderer로 수정·저장
→ HTML/Vue/React Export
```

중요 원칙:

- LLM은 임의 HTML/CSS/JavaScript를 작성하지 않는다.
- LLM은 활성 Registry와 allowlist 안에서 Section, Component, Layout, Token, Motion을 선택한다.
- 약관 등 공통 콘텐츠는 LLM 생성물이 아니라 versioned Resource reference를 사용한다.
- 생성 결과는 pinned version과 fingerprint를 저장해 재현성과 충돌 검증을 유지한다.
- 디자인 값은 raw CSS 하드코딩이 아니라 Design Token semantic binding으로 해석한다.
- Proposal은 자동 적용하지 않고 사용자가 구조를 확인한 후 적용한다.
- 기존 Template Mode는 Feature Flag 비활성 또는 Shell 부재 시 fallback으로 유지한다.

### 5.3 Seed 004에서 해결한 오류

오류 1:

```text
ERROR: there is no unique or exclusion constraint matching the ON CONFLICT specification
SQLSTATE 42P10
```

원인 A:

- 기존 DB에서 `wizard_item_components.system_seed_code`에 일반 Unique index가 없었음
- 새 Migration의 `CREATE TABLE IF NOT EXISTS`만으로 기존 테이블 제약이 보강되지 않은 schema drift

운영 DB에서 수동 보완한 index:

```sql
CREATE UNIQUE INDEX IF NOT EXISTS
  wizard_item_components_system_seed_code_seed_uidx
ON public.wizard_item_components (system_seed_code);
```

원인 B:

- Migration 038 이후 `promo_design_token_values` PK가 `(token_set_version_id, token_key, value_index)`로 변경됨
- 기존 Seed 004는 구형 2열 conflict target `(token_set_version_id, token_key)`를 사용했음

소스 수정:

- insert에 `value_index`, `value_light`, `value_dark`, `active_theme` 명시
- 기본 scalar token은 `value_index=0`
- `ON CONFLICT (token_set_version_id, token_key, value_index)` 사용
- 구형 2열 target 재도입 방지 테스트 추가

`--app-hero-bg-image`가 같은 version/token 조합으로 두 행씩 보인 것은 오류가 아니다. `value_index=0,1`인 정상 list-valued gradient layer이므로 삭제하면 안 된다.

오류 2:

```text
ERROR: syntax error at or near "ROLLBACK"
EXPLAIN (FORMAT JSON, COSTS, BUFFERS, VERBOSE) ROLLBACK
```

원인:

- Neon SQL Editor에서 트랜잭션 Seed를 Run이 아니라 Explain으로 실행했음

대응:

- Seed 전체를 선택하고 `Run`으로 실행한다.
- `BEGIN/COMMIT/ROLLBACK`이 포함된 Seed는 Explain 대상으로 실행하지 않는다.

## 6. Prompt 운영 주의사항

Prompt는 DB의 versioned 운영 데이터다. 저장소 기본 Prompt 변경은 이미 존재하는 active Prompt를 자동으로 덮어쓰지 않는다.

코드 기본 Prompt에 반영된 정책:

- `promo_overview_parser`: 짧고 행동 중심인 CTA, 최대 20자
- `promo_template_composer`: CTA는 `ctaLabel`에만 매핑
- `promo_page_composer`: 비어 있지 않은 `ctaLabel`만 CTA에 바인딩
- `section_composition_planner`: CTA output 최대 20자

서버 Schema와 Validator가 잘못된 결과를 차단하므로 최종 저장 안전성은 있다. 그러나 운영 active Prompt가 과거 본문이면 LLM 응답이 처음부터 계약에 맞지 않아 repair 또는 실패가 늘 수 있다.

새 PC에서 관리자 Prompt를 확인하는 순서:

1. 각 Prompt 유형의 현재 active version과 hash를 확인한다.
2. 저장소 기본 규칙과 운영 customization을 합친 새 draft를 만든다.
3. Validation을 통과시킨다.
4. active로 전환한다.
5. 실제 generation run snapshot에서 사용된 version/hash를 확인한다.

Hero key visual 지시문은 관리 Prompt가 아니라 Registry Hero visual의 `instance_config.assetPromptText`에 있다. API 소스에 창작 문구를 다시 하드코딩하지 않는다.

## 10. 운영 및 장애 대응

### 10.1 AI Composition 장애

- `AI_COMPOSITION_MODE_V3`를 비활성화한다.
- 기존 Template Mode fallback을 유지한다.
- Proposal 사용자 승인 절차는 유지한다.
- fallback 이벤트와 Shell 조회 실패를 구분한다.

### 10.2 Export 장애

- `PROMO_BUILDER_EXPORT_ENABLED=false`
- 또는 `PROMO_BUILDER_EXPORT_ROLLOUT_PERCENT=0`
- 기존 Visual Editor/Web Output 경로는 유지한다.

### 10.3 Revision 충돌

- 자동 merge 또는 강제 덮어쓰기 금지
- 최신 Builder Document reload
- 사용자의 자연어/수동 변경을 최신 revision 기준으로 다시 적용
- 오류 코드와 base/current revision을 로그에 남김

### 10.4 Seed 문제

- 실행 전 DB와 schema를 먼저 출력해 대상 확인
- Seed 004 후 Seed 005 순서 유지
- `--app-hero-bg-image`의 `value_index=0,1` 정상 행을 삭제하지 않음
- archived Registry/Shell version을 임의로 되살리지 않음
- 이미 생성된 Builder Document는 pinned snapshot이므로 Seed 재실행만으로 자동 갱신되지 않음

### 10.5 기존 문서와 CTA

- 과거 문서에 20자를 넘는 CTA가 있어도 단순 조회는 가능할 수 있다.
- 해당 문서를 다시 저장하거나 CTA를 재생성하면 신규 정책에 의해 거부될 수 있다.
- 기존 Hero 문서 역시 Seed 갱신으로 자동 변하지 않으므로 새 문서를 생성하거나 Preset을 명시적으로 다시 적용한다.

## 14. 다음 작업자에게 남기는 핵심 메모

현재 코드와 DB 준비는 Vertical Slice를 실행할 수 있는 단계다. 다음 우선순위는 추가 기능 개발이 아니라 실제 생성 E2E로 계약이 끝까지 연결되는지 증명하는 것이다.

특히 아래 세 가지를 먼저 확인한다.

1. 실제 AI 생성에서 Overview `ctaLabel`과 Contract v3 Proposal이 정상인가?
2. 실제 이미지 Provider 결과가 일반 풀사이즈 이미지가 아니라 4:3 Hero key visual인가?
3. 편집한 geometry와 Preset content가 저장 후 새로고침에서도 유지되는가?

문제가 발생하면 UI 화면만 수정하지 말고 다음 증거를 함께 수집한다.

- generation run ID, proposal ID, document ID/revision
- request/response의 contract version과 오류 코드
- active Shell/Section/Component/Layout/Resource/Prompt version ID
- Asset Job의 role, aspect ratio, prompt snapshot
- 저장 전 snapshot, 저장 응답, reload 후 snapshot

이 증거가 있어야 LLM, Registry, Compiler, 저장소, Renderer 중 어느 계층의 문제인지 정확히 분리할 수 있다.
