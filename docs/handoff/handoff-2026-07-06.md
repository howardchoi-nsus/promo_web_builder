## 오늘 확인한 주요 오류

### 1. finalImagePromptInputs.imagePromptDirection 누락

발생 오류:

```text
finalImagePromptInputs.imagePromptDirection is required
```

원인:

- LLM이 Markdown의 `### Image Prompt Direction`에는 내용을 작성했지만, JSON의 `integratedDesignBrief.finalImagePromptInputs.imagePromptDirection` 필드는 비워 반환할 수 있음.
- 기존 검증 코드는 JSON 필드만 필수로 검사했기 때문에 실패했다.

대응 방향:

- JSON 필드에 없으면 Markdown의 `## Final Image Prompt Inputs > ### Image Prompt Direction`에서 fallback으로 가져오도록 정리.
- 단, 이는 임시 대응이며, 근본적으로는 Markdown과 JSON을 동시에 LLM에게 만들게 하는 구조를 줄여야 한다.

### 2. Negative Prompt / Visual QA Checklist 누락

발생 오류:

```text
Integrated design brief missing sections: ## Negative Prompt, ## Visual QA Checklist
```

원인:

- 통합브리프 프롬프트에는 두 항목이 필수로 남아 있음.
- 그러나 최근 검증 방향에서는 두 항목을 필수 검증에서 제외하고, 없으면 기본값으로 보완하는 방식이 더 적절하다고 판단했다.
- n8n Cloud에 이전 검증 코드가 남아 있으면 계속 해당 오류가 발생할 수 있다.

대응 방향:

- `requiredHeadings`에서 `## Negative Prompt`, `## Visual QA Checklist` 제거.
- Negative Prompt는 없으면 기본값을 사용.
- Visual QA Checklist는 운영 검증용 warning 또는 후속 디버그 정보로 분리하는 편이 안정적이다.

### 3. brief is not defined

발생 오류:

```text
brief is not defined
```

원인:

- 전체 Code 노드 교체가 아니라 일부 코드만 붙여넣으면서 `brief` 변수가 선언되기 전에 사용된 것으로 판단.

대응 방향:

- 부분 교체보다 `Parse Validate Integrated Design Brief` 노드 전체 코드를 일관된 버전으로 교체하는 것이 안전하다.
- 단, 오늘은 workflow 구조 문제 검토가 목적이므로 소스코드 수정은 진행하지 않았다.

### 4. Failed to parse integrated design brief JSON

발생 오류:

```text
Expected ',' or '}' after property value in JSON
Failed to parse integrated design brief JSON
```

원인:

- LLM 응답 자체가 JSON 형식으로 깨진 상태.
- 현재 구조에서는 LLM이 긴 `integratedDesignBriefMarkdown`를 JSON string 안에 담아 반환해야 한다.
- Markdown 안에는 따옴표, 줄바꿈, YAML frontmatter, markdown table, fenced code block, JSON block 등이 포함되어 있어 escaping 실패 가능성이 높다.

판단:

- 이 오류는 단순 검증 로직 문제가 아니라 workflow 설계 리스크다.
- 긴 Markdown 문서를 LLM이 JSON 문자열로 직접 반환하는 구조를 유지하면 유사 오류가 반복될 가능성이 높다.

## 현재 구조의 핵심 문제

### 1. LLM 역할이 너무 많음

현재 통합브리프 생성 LLM은 아래 역할을 한 번에 수행한다.

```text
Design MD 해석
Promotion Info 해석
섹션별 컨텐츠 매핑
지역/유저 성향 반영
충돌 해결
통합브리프 Markdown 작성
이미지 프롬프트 입력값 작성
검증용 필드 작성
```

이로 인해 모델이 반환하는 구조가 매번 조금씩 달라지고, JSON 필드 누락이나 Markdown 파싱 오류가 발생한다.

### 2. Markdown과 JSON을 동시에 요구함

현재 LLM 응답 구조는 아래와 같다.

```json
{
  "integratedDesignBriefMarkdown": "complete markdown document string",
  "integratedDesignBrief": {
    "finalImagePromptInputs": {}
  }
}
```

문제:

- 같은 정보를 Markdown과 JSON에 중복 작성해야 한다.
- Markdown에는 있는데 JSON에는 없는 값이 생길 수 있다.
- JSON에는 있는데 Markdown에는 없는 값이 생길 수 있다.
- 긴 Markdown 문자열이 JSON escaping 문제를 일으킨다.

### 3. 검증 정책이 운영 실패를 쉽게 만든다

현재 검증 노드는 heading 누락, frontmatter 누락, 일부 mapping 불일치 등에서 workflow를 바로 실패시킨다.

운영 관점에서는 아래처럼 나눠야 한다.

```text
Fatal Error:
- LLM 응답이 JSON으로 파싱 불가능
- 통합브리프 데이터 자체가 없음
- 이미지 프롬프트를 만들 최소 정보가 없음

Warning:
- Negative Prompt 없음
- Visual QA Checklist 없음
- 일부 section mapping 설명 부족
- MD compliance 일부 항목 부족
- 섹션명 alias 불일치
```

## 오늘 논의한 개념 정리

### Design MD의 역할

Design MD에서 가져올 것은 디자인 참고 문서 전체가 아니라 **디자인 토큰 정보**다.

포함 대상:

```json
{
  "colors": {},
  "typography": {},
  "layoutPhilosophy": "",
  "spacingRhythm": "",
  "componentStyle": "",
  "shapeAndRadius": "",
  "depthAndEffects": "",
  "visualMood": "",
  "dos": [],
  "donts": []
}
```

중요한 점:

- Design MD는 최종 화면의 copy를 결정하는 소스가 아니다.
- Design MD는 색상/폰트뿐 아니라 레이아웃, spacing, component, radius, depth, visual mood를 제어하는 토큰 소스다.
- 통합브리프에서는 Design MD를 다시 읽으라고 하지 말고, 추출된 토큰과 적용 규칙을 명시해야 한다.

### Promotion Info의 역할

Promotion Info는 단순 문구 입력값이 아니라 프로모션 전략과 컨텐츠의 기준이다.

포함 대상:

```text
프로모션 정의
- 어떤 프로모션인지
- 누구에게 어떤 행동을 유도하는지
- 핵심 혜택이 무엇인지
- 신규/기존/리텐션 등 대상
- 전환 목표

프로모션 컨텐츠
- Header / Hero / Step / CTA / Footer 등 섹션별 문구
- 섹션 on/off
- 필수 노출 문구
- legal / terms / 18+ 정보

지역 / 유저 성향
- 선택 지역
- 해당 지역 유저의 선호 톤
- 신뢰감, 명확성, 보상 강조, 긴급성 등
- 피해야 할 과도한 현지화 요소
```

### 지역 정보의 사용 방식

Promotion Info에 프로모션 지역을 등록하는 목적은 단순히 화면에 지역명을 노출하기 위해서가 아니다.

목적:

```text
선택한 지역의 유저 성향을 디자인 방향에 반영
```

예시:

```text
지역: Germany
반영 방향:
- 신뢰성
- 명확한 조건
- 과장 없는 혜택 표현
- 안정적인 서비스 느낌
- 약관/조건 접근성 강조
```

피해야 할 방향:

```text
국기, 지도, 지역명, 고정관념 이미지를 강제로 노출
문화적 상징을 과하게 사용
지역명을 visible copy로 임의 삽입
```

최종 이미지 프롬프트에는 아래 관점으로 반영하는 것이 적절하다.

```text
Reflect the selected market context through tone, hierarchy, trust cues, content density, and visual emphasis.
Do not force flags, maps, stereotypes, or visible market labels unless explicitly provided as user-facing copy.
```

### CTA의 의미

오늘 CTA의 의미도 정리했다.

CTA는 단순 버튼만 뜻하지 않고, 사용자 행동을 유도하는 목적과 UI 표현 전체를 의미한다.

구분:

```text
CTA Intent = 유도하려는 행동
CTA Copy = 버튼/링크에 표시될 문구
CTA Component = 버튼, 링크, 카드, 배너 등 UI 표현
CTA Placement = Hero, Content CTA, Footer 등 위치
```

예시:

```json
{
  "ctaIntent": "신규 유저 가입 및 첫 입금 유도",
  "ctaCopy": "Join Now",
  "ctaComponent": "primary button",
  "ctaPlacement": ["Hero Banner", "Content CTA"]
}
```

## 미해결 이슈

### 1. 통합브리프 생성 구조 개편 필요

현재처럼 LLM이 긴 Markdown을 JSON string으로 직접 반환하는 방식은 계속 파싱 오류를 만들 가능성이 높다.

개선 필요:

- LLM은 구조화된 Integrated Brief Data만 반환
- Markdown은 Code 노드에서 조립
- imagePrompt도 구조화 데이터 기준으로 생성

### 2. 통합브리프 Markdown 생성 책임 정리 필요

선택지:

```text
A. LLM이 Markdown 직접 작성
B. Code 노드가 Markdown 조립
```

오늘 판단은 B가 더 안정적이다.

이유:

- JSON parse 안정성 향상
- Markdown 형식 일관성 확보
- 필수 섹션 누락 방지
- 모델 변경 시에도 결과 구조 유지

### 3. 검증 정책 재정의 필요

현재는 작은 형식 차이도 workflow 실패로 이어질 수 있다.

정리 필요:

- fatal error 기준
- warning 기준
- fallback 가능한 필드 목록
- 운영자 디버그 UI에 표시할 항목

### 4. Design Token 추출/준비 단계 명확화 필요

Design MD에서 추출된 값을 통합브리프에 바로 넣을지, 별도 workflow/API에서 tokenized data로 준비할지 결정해야 한다.

검토 필요:

- 현재 DB에 저장된 `designConcept`, `promptContext` 활용 범위
- 별도 `designTokens` 구조 생성 여부
- layout/component/radius/depth 등 비색상 토큰의 품질 검증

### 5. Promotion Info 구조 보강 필요

프로모션 정의, 컨텐츠, 지역/유저 성향을 명확히 분리해야 한다.

추가 검토 대상:

- 현재 B섹션 입력 구조에 `promotionStrategy` 개념을 둘지
- 지역별 유저 성향을 수동 입력, preset, LLM 추론 중 어떤 방식으로 만들지
- 지역 정보가 visible copy에 영향을 주는 범위
- 법적/약관 문구의 보존 범위

### 6. n8n Cloud workflow와 repo workflow 동기화 필요

오늘 여러 오류는 n8n Cloud에 붙여넣은 Code 노드와 repo의 workflow 코드가 다르거나, 부분 교체 과정에서 생긴 문제도 포함한다.

필요 작업:

- n8n Cloud workflow export 기준으로 repo workflow와 diff 확인
- 실제 운영 노드명 suffix `...1` 반영 여부 확인
- Code 노드는 부분 수정보다 전체 교체 방식 권장
