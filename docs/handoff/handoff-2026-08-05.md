## 4.3 최신 Seed 재실행 및 Seed 004 호환성 수정

운영 DB에서 최신 Seed를 다음 순서로 재실행했고 사용자가 모두 성공했다고 확인했다.

```text
db/seeds/004_seed_item_components_design_tokens_and_default_template.sql
→ db/seeds/005_seed_registry_composition_vertical_slice.sql
```

Seed 004 재실행 중 두 가지 DB 호환성 문제가 확인됐다.

1. 기존 환경의 `wizard_item_components.system_seed_code`에 일반 Unique index가 없어 수동으로 보완했다.
2. Migration 038 이후 `promo_design_token_values`의 Primary Key는 `(token_set_version_id, token_key, value_index)`인데 Seed 004는 이전 2열 충돌 키를 사용하고 있었다.

`--app-hero-bg-image`의 `value_index=0,1` 행은 정상적인 list-valued 배경 레이어이므로 삭제하지 않았다. Seed 004 소스를 현재 계약에 맞춰 다음과 같이 수정했다.

- `value_index=0` 명시
- `value_light`, `value_dark`, `active_theme` 저장
- `ON CONFLICT (token_set_version_id, token_key, value_index)` 사용
- 구형 2열 충돌 키가 다시 들어오지 않도록 계약 테스트 추가

소스 수정 후 `test-section-component-separation-contract.js`와 `test-full-theme-design-token-contract.js`가 통과했다. 이 후속 소스 수정과 Handoff 문서는 아직 별도 커밋이 필요하다.

## 5. Prompt 관리 주의사항

관리자 Prompt는 versioned 데이터이며 저장소 기본 Prompt 변경으로 기존 active Prompt를 자동 덮어쓰지 않는다.

오늘 저장소 기본 Prompt에 추가된 CTA 규칙:

- `promo_overview_parser`: 짧고 행동 중심인 CTA 생성, 최대 20자
- `promo_template_composer`: CTA는 `ctaLabel`에만 매핑
- `promo_page_composer`: 비어 있지 않은 `ctaLabel`만 CTA에 바인딩
- `section_composition_planner`: CTA output schema 최대 20자

서버 schema와 Validator가 잘못된 결과를 차단하므로 안전 정책은 적용된다. 다만 기존 운영 active Prompt가 이전 본문이면 첫 생성 성공률과 CTA 품질이 낮아질 수 있다.

권장 운영 작업:

1. 관리자 Prompt 화면에서 위 Prompt 유형의 새 draft를 만든다.
2. 저장소 기본 문구와 현재 운영 customization을 병합한다.
3. Validation 후 active version으로 전환한다.
4. 실행 snapshot에서 사용된 Prompt version/hash를 확인한다.

Hero 창작 지시문은 API 소스에 하드코딩하지 않았으며 Registry Hero visual의 `instance_config.assetPromptText`에서 관리한다.

## 7. 알려진 위험 및 운영상 주의사항

### 7.1 기존 active Prompt

코드 기본 Prompt는 업데이트됐지만 기존 active 관리자 Prompt는 자동 변경되지 않는다. 잘못된 CTA binding은 서버가 차단하지만 LLM repair 비율이 증가할 수 있다.

### 7.2 Seed 재실행 전후 결과 차이

최신 Seed를 적용하지 않으면 코드에는 Hero key visual 역할이 있어도 DB의 기존 Hero instance에는 `assetPromptText`, 4:3 비율, Split Hero geometry가 없을 수 있다.

### 7.3 기존 Builder Document

이미 생성된 Builder Document는 pinned snapshot이므로 Seed 재실행만으로 기존 문서의 Hero Layout이 자동 변경되지 않는다. 새 문서를 생성하거나 명시적으로 Preset/Layout을 다시 적용해야 한다.

### 7.4 CTA 기존 데이터

기존 저장 문서에 20자를 초과하는 CTA가 있더라도 단순 조회는 유지한다. 해당 문서를 수정·저장하거나 AI가 CTA를 다시 생성하는 시점에는 신규 서버 정책으로 거부될 수 있다.

### 7.5 이미지와 키비주얼의 구분

키비주얼도 최종 산출물은 이미지 Asset이지만 다음 계약으로 일반 이미지와 구분한다.

- 창작 역할: `hero-key-visual`
- 배치 대상: Hero `visual` Component
- 배치 방식: bounded component, section full background 금지
- 생성 비율: 4:3
- DOM text: 이미지 내부 생성 금지

### 7.6 Feature Flag

- AI Composition v3 진입은 관련 Feature Flag 상태에 의존한다.
- Export는 `PROMO_BUILDER_EXPORT_ENABLED`와 rollout percent에 의존한다.
- Shell이 없으면 Template Mode fallback이 동작하므로 fallback 발생 이벤트를 확인해야 한다.

## 9. 롤백 및 장애 대응

### AI Composition 장애

- AI Composition 관련 Feature Flag를 비활성화한다.
- 기존 Template Mode fallback을 유지한다.
- Proposal은 적용 전에 사용자 승인하도록 유지한다.

### Export 장애

- `PROMO_BUILDER_EXPORT_ENABLED=false`
- 또는 rollout percent를 `0`으로 설정한다.
- 기존 Visual Editor/Web Output 경로는 유지한다.

- Seed는 기존 active v1을 갱신하므로 실행 전 대상 DB를 확인한다.
- 이미 생성된 문서는 pinned snapshot을 유지하므로 자동 변경되지 않는다.
- 운영 Registry version을 임의 삭제하거나 archived version을 되살리지 않는다.

### Revision 충돌

- 자동 덮어쓰기 금지
- 최신 Builder Document를 다시 로드
- 자연어 또는 수동 변경을 최신 revision 기준으로 재적용
