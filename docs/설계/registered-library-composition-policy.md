# 등록 컴포넌트·디자인 토큰 기반 구성

## 적용 범위

신규 V3 구성 요청에서 컴포넌트 라이브러리를 조회합니다. 기존 저장 결과는 버전 스냅샷을 유지합니다.

- 활성 컴포넌트의 활성 버전만 사용합니다. 연결된 일반 인스턴스는 최신 활성 버전으로 해석합니다.
- 잠긴 컴포넌트, 콘텐츠 편집 금지 섹션, `instanceConfig.versionPolicy: "pinned"`는 버전을 자동 갱신하지 않습니다. 비활성 버전은 후보에서 제외됩니다.
- 연결되지 않은 컴포넌트도 유효한 RenderSpec이 있고 배치 정책(허용/제외 섹션 역할·부모 역량)에 맞으면 요청 한정 인스턴스로 후보에 추가합니다. 원본 섹션을 DB에서 수정하지 않습니다.
- 레이아웃 선택이 잠긴 섹션에는 새 인스턴스를 자동 추가하지 않습니다.
- 최대 60개 후보 범위에서 콘텐츠 적합도와 컴포넌트 키로 정렬합니다. 등록했다고 무조건 사용하지 않으며, 프롬프트가 후보 중 적합한 컴포넌트를 선택합니다.
- 기존 결과의 섹션 추가/교체 작업에서 라이브러리의 모든 선택 후보를 강제로 표시하지 않습니다.

## 토큰 정책

단일 `design-system` 라이브러리로 새로 생성한 문서는 `registered-only` 정책과 해당 토큰 값·카탈로그를 고정 저장합니다.

- 비어 있거나 미완성인 토큰과 합성 타이포그래피 객체는 CSS 스칼라 후보로 제공하지 않습니다.
- 구성 컴파일 시 토큰 참조의 존재와 속성 호환성을 검사합니다. 원시 시각 스타일은 등록된 호환 값과 정확히 일치할 때만 유지합니다.
- 등록되지 않은 레이아웃 시각 값은 생략하고 진단 정보를 남깁니다. RenderSpec이 호환되지 않는 필수 컴포넌트는 명시적 오류로 처리하며, 선택 컴포넌트는 후보에서 제외합니다.
- 문서 수정 저장에서도 정책을 검사해 임의 값과 잘못된 RenderSpec을 거부합니다.
- 렌더러도 동일한 정제 규칙을 적용합니다. 등록되지 않은 런타임 테마 대체값, 강제 모바일 글자 크기와 간격 대체값은 사용하지 않습니다.
- 요소 좌표·너비·열 수·순서 등 구조적 배치 정보는 시각 토큰과 구분합니다. 애플리케이션의 기본 CSS와 브라우저 기본값 전체를 교체하는 변경은 아닙니다.

## 프롬프트 활성화

교체 본문: `docs/prompts/design-token-update/promo-page-composer.txt`

필수 변수는 `overviewJson`, `candidateSnapshotJson`, `constraintsJson` 세 개를 유지합니다.
마이그레이션 084는 현재 활성 프롬프트와 모델·안전 설정을 보존한 별도 Draft를 만들고 이력을 기록합니다. 실제 DB에는 아직 실행하지 않았습니다. 관리자에서 본문을 교체하거나 084 실행 후 생성된 Draft를 검증·활성화해야 적용됩니다. 코드 배포만으로 기존 활성 본문이 바뀌지는 않습니다.

## 검증

- `scripts/test-registered-library-composition.mjs`: 최신 버전·신규 후보·역할 제한·잠금·고정 ID, 컴파일 결과, 미등록 값의 저장 거부 및 잘못된 RenderSpec 차단.
- `scripts/test-component-render-spec-renderer-browser.mjs`: Desktop/Mobile 출력 및 등록 토큰 유지·미등록 스타일 제외.
- 마이그레이션 084는 로컬 PostgreSQL 호환 환경에서 재실행·필수 변수·모델/안전 설정 보존·Draft 이력을 검증했습니다.

기존 `test-promo-registry-composition-compiler.js:205`의 좌표 기대값(`10`) 검사는 현재 flow recipe가 좌표를 제거해 실패합니다. 수정 전 HEAD의 컴파일러·계약 모듈로도 동일 실패를 재현했으며 이번 변경과 분리했습니다. 신규 통합 테스트는 실제 새 컴파일 경로와 정책 검증을 통과합니다.
