# 레이아웃 다양화·GGPoker 이미지 지침 1차 적용

작성: 2026-11-25 (한국시간) · 상태: 개발·85개 로컬 회귀 통과 · 운영 프롬프트 미활성화/배포 전

## 확정 범위

사용자는 토큰 자유화를 다음 단계로 보류하고 레이아웃 다양성과 이미지 품질 개선을 요청했다. 등록 토큰 필수 사용, PageSchema·렌더러·셸 고정·영역 생성·저장·이미지 보존·자동 검사/진행을 유지한다. 이전 에디터 UI 재연결, 임의 CSS/스타일 값 허용, 고정 템플릿 추가, 새 고객 승인/선택 화면은 이번 범위가 아니다.

현재 OpenAI 이미지 생성은 images/generations의 텍스트 prompt, Gemini는 interactions의 text input을 사용한다. 이 경로에서 실제 사진 참조 입력은 전달하지 않는다. 이번 GGPoker 참고는 **서술형 아트디렉션**이며 사이트나 사진을 분석한 결과가 아니다. 실제 참고 이미지가 필요하면 승인 에셋·공급자 입력 계약·접근 권한을 별도로 구현/검증해야 한다.

| 섹션 배경 이미지 | GGPoker 참고 소재/조명/마감 품질, 실제 제목/CTA 영역과 크롭에 맞춘 배경 구도 지침 |

변경된 서버 파일은 `_page-image-prompt-context.js`와 `_page-schema-media-service.js`다. 입력 맥락은 영어 생성 지시문을 하드코딩하는 대체 프롬프트가 아니다. 시각 판단 기준은 아래 Admin 본문이 소유한다. 모델·온도·화질/해상도 옵션·호출 횟수·공급자 요청 형식은 변경하지 않는다. 레거시 이미지 경로도 같은 등록 본문을 사용할 수 있으나 새 referenceInput 메타데이터 저장은 PageSchema 미디어 경로에 해당한다.

## GGPoker 참고의 실제 의미

- 주어진 캠페인에 맞는 소재·비율·초점을 사용하고, 사진 또는 고급3D 표현의 자연스러운 비례·재질·절제된 하이라이트·접지 그림자·입체감을 요구한다.
- 고객 요청과 이미지 의도가 포커 소재일 때 카드/칩/테이블 등을 사용한다. 다른 브랜드/상품에 포커 오브젝트나 GGPoker 로고를 자동 삽입하지 않는다.
- 카드마다 같은 히어로 장면을 복제하지 않고 내용에 맞는 스케일과 시점을 선택한다. 동등한 비교 항목의 일관성은 유지한다. 다양성 때문에 이미지나 혜택을 추가하지 않는다.
- 등록 페이지 팔레트와 캠페인 방향을 따르며 모든 이미지를 레드/골드로 고정하지 않는다. 사진의 자연스러운 음영을 허용하는 것은 미등록 웹 CSS 허용이 아니다.
- 제목·CTA·금액·법적 문구·워터마크·미등록 로고를 이미지에 합성하지 않는다. 배경은 현재 텍스트 관계를 위한 안전 영역을 고려하고 fadeMode를 유지한다.
- 참조 사진이 없으면 referenceImageCount=0, websiteInspected=false, mode=written-art-direction으로 기록한다. 지침이 공급자에 전달됐다는 사실과 실제 미감/브랜드 유사성이 개선됐다는 평가를 구분한다.

## 102 적용·검증·활성화

1. [102 SQL](../../../db/migrations/102_layout_and_image_prompt_guidance.sql) 전체를 기존 운영 Neon SQL Editor에서 실행한다. 스키마 변경이 아닌 Draft 본문 데이터 업데이트이며 전체가 한 트랜잭션이다.
2. 현재 활성 계보의 Draft가 없으면 활성 설정을 복제하고, 있으면 그 Draft의 맞춤 본문 뒤에 추가한다. 활성 본문/상태·필수/선택 변수·모델/온도/출력 한도·modelOptions·정책/스킬 연결은 보존한다. 수정 이력을 남긴다. 과거 두 프롬프트 SQL 또는 전체 MD로 적용한 동일 구도 지침은 중복 추가하지 않는다.
3. 이미 검증된 다른 후보·V2 계약 누락·없는 활성 타입·잘못된 계보·서로 다른 보정 마커는 전체 중단/복원한다. 실패한 파일을 일부만 재실행하지 않는다. 결과를 보고 Admin에서 기존 후보를 먼저 처리한다.
4. Admin에서 해당 Draft5종의 최종 조립 지시문과 기존 설정을 확인하고 검증한다. 이미 적용된 두 레이아웃 프롬프트는 새 버전을 불필요하게 만들지 않는다. 완성된 본문이 이미 활성 상태면 결과에 그렇게 표시된다.
5. 테스트 문서에서 명시한 구도와 이미지 방향·출력 예산·처리 시간·이미지 연결·전체 화면 QA를 실제 생성으로 비교한 뒤 신규 작업 사이에 활성화한다. 이 비교는 유료 호출을 발생시킬 수 있으며 로컬 대역 검사와 구분한다. 진행 중인 작업의 프롬프트 버전을 바꾸지 않는다.
6. 이미 완성된 이미지는 자동 재생성하지 않는다. 새 요청/명시적 이미지 재생성에 적용한다. 악화 시 기존 활성 프롬프트로 롤백하며 기존 문서는 보존한다.

**코드 배포만으로102 SQL이나 Admin 검증/활성화가 실행되지 않는다.** 직접 운영 접속은 현재 클라우드 네트워크 허용 범위의 제약을 받는다. SQL·모델/프롬프트 활성화·Vercel Ready 여부를 각각 확인한다. 신규 환경변수나 사용자 선택 UI는 필요하지 않다.

SQL 재생성 명령: `node scripts/build-layout-image-guidance-pack.mjs`, 무변경 일치 검사: `node scripts/build-layout-image-guidance-pack.mjs --check`. 기존 두 프롬프트 추가 SQL과 이번 manifest/본문을 입력으로 사용하며 이전 마이그레이션을 수정하지 않는다.
