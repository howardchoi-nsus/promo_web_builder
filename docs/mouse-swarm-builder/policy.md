# Mouse Swarm Builder 표시 정책과 구현 계약

## 사용자 여정

상단 단계는 `1. 요청 요약 → 2. 페이지 제작` 두 개다. 아래 과정은 페이지 제작 내부 상태이며 독립된 상단 단계로 나누지 않는다. 완성 후 채팅의 ‘에디터에서 수정’으로 같은 문서를 편집한다.

1. 요청 요약에서 채팅의 페이지 미리보기 생성을 실행한다.
2. 새 생성 작업에는 빈 캔버스에서 시작한다. 작업 중인 섹션·컴포넌트 자리만 표시하며 완성된 와이어프레임을 미리 노출하지 않는다. 기존 문서의 새로고침·재시도·부분 수정에서는 검증·저장된 결과를 지우지 않는다.
3. 서버가 검증·저장한 와이어프레임 단위만 추가한다. 모든 필수 구조·소스·접근성 검사를 통과한 페이지에서만 채팅의 구성 승인을 제공한다. 부분 초안에는 승인·출력 기능을 열지 않는다.
4. 구성 승인 후 같은 트리·배치를 유지하며 스타일 패치 저장, 미디어 준비·디코딩 완료에 따라 디자인으로 전환한다.
5. 표시 효과를 제거한 결과를 자동 검사·보정·재검사한다. 현재 Revision 검사를 통과하면 기존 출력·새 창 보기와 에디터 진입을 활성화한다.
6. 완성 후 편집은 동일 PageSchema·토큰을 사용하는 에디터에서 진행한다. 저장 후 품질 상태를 무효화하고 재검사한다. 구조 변경은 채팅의 구성 재승인으로 연결한다. 에디터 편집 도구와 아래 비대화형 스웜 효과를 구분한다.

요청·질문·생성·승인·재시도 버튼은 왼쪽 채팅에만 둔다. 오른쪽은 결과와 비대화형 작업 시각화만 표시한다.

## 렌더링 단위

- 섹션별: 실제 동적 PageSchema의 의미 있는 영역에 연결한다. 헤더·히어로·카드 3개 같은 고정 배열을 강제하지 않는다.
- 컴포넌트별: 실제 nodeId에 연결하고 역할에 따라 text/image/button/card 등의 경계를 표시한다. 표시 단위와 모델 호출 단위를 구분한다.
- 현재 서버가 순차 group 실행을 요구하면 그대로 따른다. 커서 수는 병렬 호출 수·에이전트 수·진행률이 아니다.

## 커서 12개와 편집 효과

- 바운딩 박스 그룹과 마우스 커서 그룹에 각각 `opacity: 0.5`(불투명도 50%)를 한 번 적용한다. 라벨·핸들·캐럿은 그룹을 상속하며 중복 opacity를 주지 않는다. 공통 overlay 부모·캔버스·생성 텍스트·이미지는 흐리게 만들지 않는다.

- 기본 시각 커서 풀은 12개다. 실제 진행 대상이 있는 커서만 활동시키고 나머지는 대기 영역에 둔다. 화면에는 작업 커서와 대기 커서를 구별해 보여준다. 실제 작업이 12개라고 꾸미지 않는다.
- 커서는 범위 없는 임의 배회 대신 현재 대상 경계·텍스트 입력 지점·미디어 로딩 경계에 연결한다. 역할·노드 식별에 맞는 색상 라벨을 쓰되 실제 모델 수를 표시하지 않는다.
- 텍스트는 선택 박스, 모서리 핸들, 입력 캐럿, 필요한 경우 현재 반영된 구간 강조로 표현한다. 핸들은 장식이며 드래그·contenteditable·추가 폼을 만들지 않는다.
- 문구는 검증·저장된 콘텐츠만 노출한다. 서버 토큰 입력 위치는 실제 검증·저장된 조각 이벤트가 있을 때만 표시한다. 현재 문구 전체는 즉시 DOM에 반영하고 360ms 일회성 Mask Reveal의 실제 DOM/Range 공개 경계에 장식 캐럿을 연결한다. 이는 모델 입력이나 추가 조각 저장을 뜻하지 않는다. 문자를 교체하거나 같은 단위의 문구를 긴 순차 대기열로 지연하지 않는다.
- 임시 조각은 최종 문서와 분리된 검증된 초안 저장소가 있어야 한다. JSON 토큰 스트림, 미완성 문장, 근거 미검증 금액을 DOM에 출력하지 않는다. 전체 소스 참조와 사실 조건을 보존한다.
- 완료한 대상의 커서·박스·캐럿은 즉시 정리하고 디자인·에셋은 유지한다. 실패 대상은 멈추고 채팅에서 원인·재시도를 안내한다. 사용자 일시정지 옵션은 표시만 멈추며 서버 작업 취소를 뜻하지 않는다.
- 커서·박스는 pointer-events:none, aria-hidden=true인 별도 표시 계층으로 격리한다. 실제 마우스·키보드·선택을 방해하지 않고 스크롤·포커스·확대를 강제하지 않는다.
- 화면 밖 대상의 커서를 엉뚱한 컴포넌트에 붙이지 않는다. 대기 표시로 바꾸거나 사용자가 해당 영역으로 이동했을 때 정확히 연결한다.
- 모션 감소 설정에서는 커서 이동·깜빡임·타자·Reveal을 제거하고 즉시 상태를 표시한다. 모바일에서는 라벨 밀도를 줄이고 상태·콘텐츠 접근성을 유지한다.

## 실제 작업 상태 연결: 신규 이벤트 계약 제안

아래는 향후 구현할 앱 전용 이벤트이며 LLM 응답 필드나 현재 API 필드가 아니다.

```json
{
  "documentId": "document-reference",
  "runId": "generation-reference",
  "revision": 4,
  "sequence": 18,
  "taskId": "task-reference",
  "phase": "wireframe",
  "unit": "component",
  "nodeIds": ["headline"],
  "state": "persisted"
}
```

- phase: wireframe / design / media / quality; unit: section / component; state: queued / running / validated / persisted / failed.
- sequence는 같은 작업 스트림의 서버 순서이며, 중복·지연 이벤트는 무시한다. documentId·runId·revision·taskId·nodeIds·소유권을 서버와 클라이언트에서 대조한다.
- running은 진행 표시만 허용한다. validated만으로 결과를 공개하지 않는다. persisted 후 해당 Revision의 서버 스냅샷을 가져와 검증된 결과를 반영한다. 미디어는 이 과정에 브라우저 load/decode 성공도 필요하다.
- 텍스트 부분 반영은 별도 검증·저장된 초안 노드/조각 계약이 마련된 경우에만 추가한다. 위 이벤트에 임의 HTML·좌표·평문 콘텐츠를 붙여 우회하지 않는다.
- 부분 초안의 검증과 최종 문서 검증을 구분한다. 완성 전 필수 소스·h1 누락을 통과시키려고 현재 PageSchema 검증기를 느슨하게 만들지 않는다.
- 서버 CAS·원자 저장·멱등 작업 키를 유지한다. 이전 문서나 다른 Revision의 결과는 최신 문서를 덮지 못한다. 재연결은 저장된 상태에서 복구하고 완료 영역을 다시 생성하지 않는다.

## 스타일과 품질의 경계

출력물은 Admin 등록 토큰·활성 사용 정책만 사용한다. 스웜 커서와 편집 박스의 빌더 전용 색상·좌표는 출력 스타일이 아니며 PageSchema, 배포 DOM, HTML 다운로드, 자동 품질검사 측정에 포함하지 않는다. AI는 커서 좌표·속도·진행률·UI CSS를 생성하지 않는다.

## 수용 기준

| 사례 | 기대 결과 |
|---|---|
| 새 생성 시작 | 결과 캔버스에 완성된 와이어프레임이 없음 |
| 구조 작업 진행 | 실제 대상 자리와 진행 표시, 불완전 JSON 미출력 |
| 초안 누적 | 검증·저장된 단위만 추가, 최종 조립까지 승인 비활성 |
| 구성 승인 | 채팅에서만 실행, 승인 구조 보존 |
| 섹션/컴포넌트 보기 | 같은 결과·실제 nodeId를 사용, 추가 LLM 호출 없음 |
| 12개 커서 | 활성/대기 구분, 실제 작업 수를 허위 표시하지 않음 |
| 텍스트 적용 | 박스·핸들·캐럿이 해당 텍스트에 정렬, 근거 문구 보존 |
| 전체 응답만 지원 | 완료 텍스트 즉시 DOM 반영 + 360ms 비차단 Mask Reveal, 타자 대기열 없음 |
| 늦은 응답/다른 문서 | 최신 문서를 덮지 않음 |
| 실패/재시도/재접속 | 완료 영역·이미지 보존, 실패 작업만 재개 |
| 축소 모션/모바일/스크롤 | 효과 억제·정확한 위치·입력 비차단 |
| 자동 품질검사/출력 | 표시 계층 제외, 현재 Revision 게이트 유지 |

## 텍스트·캐럿·커서 관계 보정 · 2026-11-22

현재 영역/컴포넌트 그룹 단위 생성·저장은 유지한다. 박스·비텍스트 등장, 이미지, 완료/실패, 50% 불투명도, 효과 일시정지 동작도 유지한다. 저장된 새 문구만 360ms 단발 Mask Reveal로 공개하고 실제 텍스트 Range 경계에 캐럿을 둔다. 작업 커서는 대상 변경 때 최대 220ms 이동 후 머무르며 반복 횡이동하지 않는다. 텍스트 효과 종료를 기다려 다음 API 요청이나 완료 처리를 하지 않는다. 전체 내용은 DOM에 이미 존재하고 변경·삭제하지 않는다. 중복 응답/뷰포트 전환/재부착/복원에는 재생하지 않고, 효과 정지·화면 숨김·모션 감소·QA 시 clip을 즉시 제거한다. 채팅의 1.8초 반복 Mask Reveal과는 별도 효과다.
