# Handoff - 2026-07-04

## 오늘 진행 요약

오늘은 B섹션 프로모션 빌더의 섹션/아이템 입력 UX, 생성 중 상태 표시, n8n 연동 이슈, 이미지 결과 품질 이슈를 집중적으로 정리했다.

큰 흐름은 다음과 같다.

```text
1. B섹션 프로모션 입력 구조 단순화
2. Template 4 섹션/아이템 사용 여부 및 이미지 생성 대상 제어 UX 반영

5. 생성 결과 이미지 후처리/가이드 제거 검토
6. 생성 중 UI 개선
7. 디자인 토큰 반영 실패 이슈 분석
```

현재 가장 중요한 남은 이슈는 **선택한 Design MD 토큰이 최종 이미지 결과물에 충분히 반영되지 않는 문제**다. 원인은 토큰이 프론트에서 누락되는 것이 아니라, n8n의 Integrated Design Brief 생성 단계에서 구체적인 디자인 DNA가 일반화되고 희석되는 것이다.

## 오늘 반영한 주요 변경

### 1. B섹션 프로모션 입력 구조 정리

```text
프로모션 제목
```

불필요한 입력 항목은 제거하는 방향으로 정리했고, Section Input Log에는 자동 구성된 Template 4 섹션 입력값이 기록되도록 유지했다.

### 2. Template 4 섹션/아이템 구성 UX 반영

PDF 기준 Template 4 섹션 구조를 B섹션에 반영했다.

섹션 구성:

```text
Header
Hero Banner
Step Bar
Content CTA
Image Text Row
Title and Description
Footer
```

UX 규칙:

- 섹션은 사용/미사용 토글로 제어
- 섹션을 사용하면 하위 섹션 아이템이 열린다
- 필수 아이템은 섹션 사용 중 숨길 수 없다
- 이미지 생성 가능한 아이템만 AI 이미지 생성 토글을 노출
- 이미지 생성 불가능한 아이템에는 이미지 관련 UI를 보여주지 않음

Step Bar와 Image Text Row는 반복 세트 구조로 정리했다.

```text
Step Bar:
- title / description / cta button이 한 세트
- 각 아이템은 개별 사용/미사용 가능
- 세트는 여러 개 추가 가능

Image Text Row:
- image / title / description이 한 세트
- 1 row 최대 3개까지 배치되는 규칙은 생성 규칙으로 유지
- UI 입력은 반복 세트로 추가 가능
```

### 3. B섹션 아이템 row UI 개선

프로모션 빌더 모달 내 섹션 아이템 row를 다음 순서로 정리했다.

```text
사용/미사용 토글
30px 간격
아이템 제목 영역 width 150px
입력 필드
AI 이미지 생성 토글
```

관련 변경:

- 드롭다운 `AI / 이미지 등록 / 미사용` 구조는 제거
- 현재 UI는 `AI 이미지 생성` 토글만 사용
- 토글 ON이면 `generate`
- 토글 OFF이면 `none`
- 이미지 생성 대상이 아닌 아이템에는 토글 미노출
- 토글 라벨 정렬 문제 보정
- 오래된 체크박스 함수 제거
- 기존 저장 데이터에서 이미지 생성 기본값이 화면과 실제 payload에서 다르게 해석될 수 있던 문제 수정

주요 파일:

```text

prototype/styles.css
```

## n8n 관련 오늘 대응

### 1. Integrated Design Brief 검증 오류 대응

오늘 여러 n8n 오류를 확인하고 수정 방향을 정리했다.

발생 오류:

```text
Integrated design brief missing Template 4 mappings
Integrated design brief frontmatter type must be integrated_design_brief
Integrated design brief section label guard missing
Integrated design brief missing sections: ## Negative Prompt, ## Visual QA Checklist
```

대응:

- frontmatter type을 `integrated_design_brief`로 강제
- `sourceDocuments`에 `design_prompt`, `section_input_log` 포함
- Template 4 canonical headings 강제
- `Negative Prompt`, `Visual QA Checklist` 누락 시 보강
- label guard 문구 추가
- 섹션명이 이미지에 직접 렌더링되지 않도록 guard 강화

### 2. Gemini 이미지 생성 연동 이슈

Gemini 이미지 생성 관련 오류를 확인했다.

발생 오류:

```text
response_format.mime_type image/png not supported
Model 'gpt-image-1' not found
```

정리한 방향:

- 이미지 응답 포맷은 `image/jpeg` 기준으로 수정
- Gemini 이미지 모델 기준으로 `gemini-3-pro-image-preview` 또는 실제 사용 가능한 Gemini image 모델명을 써야 함
- 사용자 의도는 `gemini 3.1 flash image`였으나, 실제 API 지원 모델명 확인이 필요

### 3. Store UI Design Result 코드 정리

이미지 생성 응답 저장 코드에서 다음 케이스를 처리하도록 검토했다.

- URL 이미지
- base64 이미지
- Gemini inlineData
- n8n binary image
- JPEG/PNG/WebP mime detection
- 생성 이미지 저장 후 `designUrl`, `imageUrl`, `promptGroupId`, storage key 반환

### 4. n8n 장시간 실행 이슈

현재 웹에서 약 2분 20초 후 생성 실패가 표시되는 현상을 확인했다.

원인:

- 웹은 `/api/generate-ui-design`를 호출
- API는 n8n Webhook 최종 응답까지 대기
- n8n Webhook은 `responseNode` 방식이라 워크플로우 마지막까지 끝나야 응답
- n8n 내부 LLM/이미지 생성 노드는 각각 최대 300초 대기
- 웹/API 연결이 먼저 끊기면 프론트는 실패 처리
- n8n은 뒤에서 계속 생성 중일 수 있음

현재 코드상 실패 처리:

```text
n8n 응답 실패
-> 서버 저장 결과를 약 6초만 확인
-> 결과가 없으면 n8n_failed 처리
```

권장 구조:

```text
Workflow A: Request Receiver
- 요청 수신
- payload 검증
- 즉시 accepted 응답
- Worker workflow 실행

Workflow B: Design Worker
- Integrated Brief 생성
- Image Prompt 생성
- Gemini 이미지 생성
- 결과 저장
```

프론트는 `runKey`로 `/api/promo-design-assets`를 폴링해서 완료 여부를 확인하는 구조가 맞다.

### 원인 분석

문제는 프론트 payload에서 디자인 토큰이 누락된 것이 아니다.

`design prompt` 문서에는 선택 MD 토큰이 비교적 잘 들어있다.

예:

```text

#f68d1f
#ecab37
#7a8aba
#9fbee7

#c0d5e6
#21242e
Fixed-width canvas ~780-830px
dual nav bars

```

하지만 `integrated design brief`로 넘어가면서 핵심 토큰이 일반화된다.

예:

```text
Standard header styling
Standard CTA styling
Premium, clean, regulation-aware
Rounded corners for CTA buttons
Flat design
```

즉 현재 손실 지점은 다음이다.

```text

-> design prompt 문서까지는 정상
-> integrated design brief 생성 단계에서 요약/일반화
-> final image prompt는 integrated brief만 사용
-> 최종 이미지에서 선택 MD 스타일이 약하게 반영
```

### 추가 충돌 요인

현재 `#000000 full-bleed background` 규칙이 너무 강하게 들어가 있다.

이 규칙은 회색 외곽/아트보드 문제를 해결하기 위해 추가했지만, Nintendo 2001의 밝은 chrome/periwinkle surface를 억제하는 부작용이 있다.

권장 표현:

```text

Inside the webpage container, selected MD surfaces are allowed and required:
periwinkle, pale-sky, white/chrome panels, carbon nav slabs, amber utility chips.
```

정확한 원인은:

```text

Style conflict는 Design Prompt MD가 이긴다.
Template은 구조 fallback이다.
Promo input은 콘텐츠 source다.
```

### 5. n8n 비동기 구조 전환

2분 20초 전후 웹 실패 표시 문제를 근본 해결하려면 n8n을 request/worker 구조로 분리해야 한다.

우선순위:

```text
1. 프론트 실패 처리 완화 및 장시간 polling
2. n8n accepted 즉시 응답 구조
3. worker workflow 분리
4. 생성 완료 후 DB 저장 결과 기반 C섹션 업데이트
```
