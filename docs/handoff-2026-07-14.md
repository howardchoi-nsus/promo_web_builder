# Handoff 2026-07-14

## Summary

Implemented the PRD (`docs/wizard-content-section-admin-management-prd-2026-07-14.md`) for admin-managed Wizard Step 2 content sections: DB schema, CRUD API, Admin Page UI, and dynamic Wizard rendering. Prior to this, `prototype/promo-wizard.js` hardcoded the 7 Step 2 sections (Header/Hero Banner/Step Bar/Content CTA/Image Text Row/Title and Description/Footer). They are now defined in the database and editable from the Admin Page.

## Completed

1. Database (`db/migrations/016_wizard_content_sections.sql`)
   - `wizard_content_sections`: draft/active/inactive/archived versioned rows, same pattern as `prompt_templates`. One active version per `section_key` enforced by a partial unique index.
   - `wizard_content_section_items`: child rows per section version. Supports `field_kind` (`text`/`image`/`cta`), `text_type` (`title`/`remark`/`multi`), image source options (`file`/`url`/`ai`) + alt-text/aspect-ratio/max-size constraints, CTA UTM fields (source/medium/campaign/content/term), and a lock mechanism (`is_locked` + `locked_value`) for admin-fixed content.
   - `wizard_content_section_histories`: change log for draft/activate/archive actions.
   - Seed data migrates the existing 7 hardcoded sections as version 1 / active, so behavior is unchanged until an admin publishes a new draft. Header/Footer logo & badge fields were kept as text (matching current behavior) rather than image, to avoid an unnecessary regression; only Content CTA's and Image Text Row's `image` items are true image fields.

2. API (`api/`)
   - `_wizard-content-sections-store.js`: shared DB helpers (row mappers, clone-as-draft, history recording).
   - `wizard-content-sections.js`: `GET` (admin list, or `?scope=public` for the Wizard-facing read with nested items), `POST` (create new section, or clone an existing one into a new draft via `{ id }`).
   - `wizard-content-section.js`: `GET` single section + items + history, `PATCH` update (draft-only).
   - `wizard-content-section-activate.js`, `wizard-content-section-archive.js`: version lifecycle actions (mirrors `prompt-template-activate.js`/`-archive.js`).
   - `wizard-content-section-items.js`: item CRUD, restricted to sections currently in `draft` status.
   - All new `api/*.js` files passed `node --check`.

3. Admin Page (`prototype/index.html` + `app.js`)
   - New "C. Wizard Content Sections 관리" subsection added below the existing A/B (Worker Webhook / Prompt) panels.
   - Section list (grouped by `sectionKey`, shows version/status), section field editor (name/description/required/order-change/visibility, draft-only), "새 초안 만들기"/"활성화"/"보관(삭제)" actions, and a nested item editor supporting all field kinds (text/image/cta), lock toggle with JSON locked-value input, and image source checkboxes.

4. Wizard (`prototype/promo-wizard.js` + `.css`)
   - `defaultSectionInputs()` (hardcoded) replaced by `defaultSectionInputsFromDefinitions()` + `mergeSectionInputs()`, driven by definitions fetched from `/api/wizard-content-sections?scope=public`.
   - `renderContentStep()` now renders sections 4+ from `wizardSectionDefinitions` instead of 7 fixed blocks; added loading/error states.
   - New field renderers: `createDynamicSectionField`, `createCtaSectionField`, `createImageSectionField`, `createLockedSectionField` (locked items render read-only).
   - `contentErrors()` / `dynamicCoverageRows()` now scan admin-defined `isRequired` items instead of a fixed 11-row checklist.
   - `buildWizardPayload()` updated to the new key names (`heroBanner.button.label` instead of `heroBanner.cta.label`, `stepBar.title` instead of `stepBar.0.title`, etc.) and now sends `sectionConfig.sections` with real `name`/`description` per section, so `api/_promo-markdown-builders.js`'s `canonicalSectionName()`/`sectionRole()` fallback maps are no longer load-bearing for Wizard-originated payloads (no backend file was changed).

## Codex Hardening Update

### Applied

1. Legacy Step 2 content preservation
   - Added section input schema version 2.
   - Added a one-time localStorage backup before migration.
   - Migrates legacy Header/Hero/CTA keys to the admin-managed canonical keys.
   - Preserves legacy Step Bar/Image Text Row arrays in `legacyItems` while the repeatable-group UI remains pending.

2. Wizard fail-closed behavior
   - Step 2 cannot proceed while section definitions are loading, failed, or empty.
   - Added a configuration retry action.
   - `buildWizardPayload()` independently rejects generation without a ready configuration.
   - Public configuration revision is included in the run payload snapshot.

3. Validation completion
   - Required CTA items now require label and link.
   - Required image items validate value and required alt text.
   - Locked items are no longer assumed valid when their fixed value is missing.
   - Server validates typed locked values, supported image sources, AI prompt text, and positive image size.
   - File image sources are temporarily disabled until Blob upload is implemented.
   - Admin CTA UTM settings are appended to generated section and primary CTA URLs.

4. Atomic lifecycle
   - Migration adds PostgreSQL functions for atomic draft cloning and activation.
   - Draft versions use `max(version) + 1` under an advisory transaction lock.
   - Item cloning and lifecycle history are part of the same database transaction.
   - Active sections cannot be archived directly in either UI or API.

5. Contract coverage
   - Added `scripts/test-wizard-content-sections-contract.js`.
   - Added package script `test:wizard-content-sections-contract`.
