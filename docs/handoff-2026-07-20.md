## 2. 완료된 개발 내용

### 2.1 관리자 기본 레이아웃 반영 안정화

- 활성 템플릿의 `templateKey`, `version`, `layoutRevision`을 기준으로 Create Promo 레이아웃을 조회한다.
- Admin에서 저장한 최신 기본 레이아웃과 Create Promo 캐시의 identity를 비교한다.
- revision 또는 template identity가 변경되면 이전 캐시를 무효화한다.
- Create Promo 실행 중 사용자 변경과 Admin 기본 레이아웃의 우선순위를 분리했다.
- 관련 계획서: `docs/create-promo-admin-layout-reflection-fix-development-plan-2026-07-20.md`

### 2.2 Step 3 화면 구조 개편

- Step 3 명칭을 `콘텐츠 등록`으로 정리했다.
- 하위 흐름을 프로모션 개요, 템플릿 선택, 템플릿 레이아웃으로 분리했다.
- 템플릿 레이아웃에서는 Live Preview를 위에 배치했다.
- Wizard Layout의 Sections 및 Content 영역을 Live Preview 아래로 이동했다.
- 기존 숨겨진 부모 DOM이 아니라 실제 사용자에게 보이는 Visual Editor iframe을 기준으로 기능을 연결했다.

### 2.3 Backend 직접 제어형 섹션 AI 디자인

- n8n 없이 Backend가 LLM 및 이미지 모델을 직접 호출한다.
- 섹션 콘텐츠 snapshot을 기준으로 비동기 design run을 생성한다.
- 레이아웃 생성, 검증, 이미지 생성, 결과 저장 및 적용 단계를 분리했다.
- DB migration `025_promo_section_design_runs.sql`과 Section AI API를 추가했다.
- 주요 API:
  - `api/promo-section-design-runs.js`
  - `api/promo-section-design-process.js`
  - `api/promo-section-design-apply.js`
  - `api/promo-section-design-image.js`
- Gemini 이미지 provider adapter를 추가했다.
- Gemini 요청에서 지원되지 않았던 `generation_config.responseModalities` 및 `responseFormat` 전달 문제를 제거했다.
- 권장 서버 환경 변수:

```text
SECTION_IMAGE_PROVIDER=gemini
SECTION_IMAGE_MODEL=gemini-3.1-flash-image
GEMINI_API_KEY=<server-only secret>
```

### 2.4 섹션별 AI 디자인 UI

- Create Promo의 실제 Visual Editor 섹션마다 `AI 디자인` 버튼을 표시한다.
- 콘텐츠가 없는 섹션은 버튼을 비활성화한다.
- 처리 중에는 `AI 생성 중`, 준비 완료 후에는 `AI 적용`, 적용 완료 후에는 `AI 재생성` 상태를 표시한다.
- iframe과 부모 Create Promo 사이를 `postMessage`로 연결했다.
- AI 실행 상태를 iframe snapshot에 함께 전달한다.
- 메시지는 현재 Wizard Layout iframe에서 온 경우만 처리한다.

### 2.5 생성 이미지 적용 방식 수정

- AI 생성 이미지를 이미지 아이템의 `<figure><img>`로 삽입하지 않는다.
- 선택한 섹션의 `sectionStyles[sectionKey].backgroundImage`로 적용한다.
- 이미지 항목 유무와 관계없이 AI 생성 결과는 섹션 배경으로 통일했다.
- 페이지 전체 배경 이미지는 사용하지 않으며 전체 배경은 `background-color`만 사용한다.
- 기본 섹션 배경 속성:

```json
{
  "backgroundSize": "contain",
  "backgroundPosition": "right center",
  "backgroundRepeat": "no-repeat"
}
```

- 과거 버전에서 이미지 아이템에 저장된 AI URL도 renderer에서 숨기고 섹션 배경으로 호환 렌더링한다.
- 상대 API 이미지 URL(`/api/...`)도 유효 이미지 URL로 처리한다.

### 2.6 배경 및 이미지 편집 기능

- 각 섹션에서 적용된 AI 배경을 삭제할 수 있다.
- 과거 이미지 필드 기반 AI 결과도 배경 삭제 대상으로 인식한다.
- 일반 콘텐츠 이미지에는 `이미지 삭제` 버튼을 제공한다.
- 잠긴 이미지 아이템은 삭제할 수 없다.
- 배경 이미지가 있는 섹션에서는 다음 가로 정렬을 선택할 수 있다.
  - 왼쪽: `left center`
  - 중앙: `center center`
  - 오른쪽: `right center`
- 선택값은 섹션 layout style에 저장되고 Live Preview에 즉시 반영된다.

### 2.7 텍스트 줄바꿈

- 일반 단일 텍스트 필드도 textarea로 변경했다.
- Enter 키로 문장 중간에 개행을 넣어 2줄 이상 구성할 수 있다.
- Visual Editor 미리보기에서 직접 편집할 때도 `innerText`를 이용해 개행을 보존한다.
- renderer의 `white-space: pre-wrap`을 통해 저장된 개행을 화면에 표시한다.
- CTA 입력은 기존 단일 label 구조를 유지한다.

### P0. 최신 Vercel 배포 및 실화면 확인

### P0. Gemini 실호출 E2E

- provider 계약 테스트는 통과했지만 실제 Gemini API를 이용한 생성 성공 여부는 별도 확인이 필요하다.
- Vercel Production 환경 변수에 `SECTION_IMAGE_PROVIDER`, `SECTION_IMAGE_MODEL`, `GEMINI_API_KEY`가 설정되어야 한다.
- 생성 → polling → 적용 → 이미지 proxy 조회까지 한 흐름으로 확인해야 한다.

### P0. DB 자격 증명 교체

- 오늘 대화에 Neon DB 접속 문자열과 비밀번호가 노출되었다.
- 기존 Neon role password를 교체하고 Vercel 환경 변수의 DB URL을 새 값으로 갱신하는 것을 권장한다.
- 해당 비밀값을 Handoff 문서나 Git 저장소에는 기록하지 않았다.

### P1. 기존 데이터 호환 확인

- 과거 `<figure>` 방식으로 저장된 AI 이미지가 섹션 배경으로 표시되고 삭제되는지 production 데이터로 확인해야 한다.
- 사용자 등록 이미지와 AI 생성 이미지를 구분하여, AI 배경 삭제 시 사용자 이미지가 제거되지 않는지 확인해야 한다.

### P1. UI 상태 및 오류 UX

- 생성 실패 시 섹션 버튼 근처에 오류 원인과 재시도 안내를 더 명확하게 표시할 필요가 있다.
- 생성 시간이 긴 경우 polling 중 화면 재렌더링과 iframe 재생성에 따른 상태 깜빡임을 확인해야 한다.
- 모바일 너비에서 섹션 이름, AI 버튼, 배경 삭제 버튼의 줄바꿈 및 겹침을 확인해야 한다.

### P1. 배경 이미지 표현 범위

- 현재 크기는 `contain`, 반복은 `no-repeat`으로 고정되어 있다.
- 가로 정렬만 사용자 편집이 가능하다.
- 추후 요구가 있으면 세로 정렬, `cover/contain`, overlay 및 배경 투명도 제어를 별도 기능으로 추가한다.

### P2. 테스트 보강

- 실제 브라우저에서 Enter 개행 저장 후 새로고침 복원 테스트가 필요하다.
- 배경 정렬값 저장 후 Step 이동 및 재진입 복원 테스트가 필요하다.
- 섹션별 AI 버튼의 생성 중/적용 가능/재생성 상태를 브라우저 자동화 테스트로 추가할 수 있다.
