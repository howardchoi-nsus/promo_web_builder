# Handoff 2026-07-12

Date: 2026-07-12  
Status: Final Design layout fidelity 운영 반영 완료, Admin 실행 설정 연동 및 Wizard UI 개선은 저장소 반영, 일부 운영 E2E 확인 필요
Scope: n8n 3단계 Worker, Admin LLM 설정, LO-FI → Final 이미지 편집, 실패 처리, 운영 검증, Promo Wizard UI

## Executive Summary

오늘은 `Integrated Brief → LO-FI Draft → Final Design` 3단계 n8n 흐름을 점검하고, LO-FI와 Final 결과가 크게 달라지던 핵심 원인을 해결했다.

핵심 원인은 운영 Final Worker가 Confirm된 LO-FI 이미지를 입력으로 사용하지 않고 OpenAI `/v1/images/generations`로 새 이미지를 생성하던 구조였다. 이를 Confirmed LO-FI binary를 전달하는 `/v1/images/edits` multipart 호출로 변경하고 `input_fidelity=high`를 적용했다.

백업 Worker에서 실패·성공 경로를 검증한 뒤 운영 `Promo Final Design Worker`에 동일 구조를 게시했다. 운영 실행 `1181`이 성공했으며 DB의 `ready`, `final_design_ready`, 이미지 URL 저장, `referenceMode=image_edit`를 확인했다. LO-FI와 Final 이미지를 직접 비교한 결과 주요 영역의 순서와 상대 위치가 유지됐다.

OpenAI API 키는 사용자 결정에 따라 n8n HTTP Request 노드에 유지했다. 저장소의 export fixture에는 실제 키를 포함하지 않는다.

## 1. 주요 결론

### 1.1 LO-FI와 Final 차이의 직접 원인

변경 전 Final Worker:

```text
Prompt only
→ POST /v1/images/generations
→ LO-FI 이미지 입력 없음
→ 새로운 레이아웃 생성
```

변경 후 Final Worker:

```text
Confirmed LO-FI proxy URL
→ LO-FI binary 다운로드
→ POST /v1/images/edits (multipart/form-data)
→ input_fidelity=high
→ Final 이미지 저장
```

`confirmedDraftId`만 프롬프트에 포함하는 것으로는 레이아웃을 보존할 수 없다. 실제 이미지 파일을 image edit 입력으로 전달해야 한다.

### 1.2 Admin에서 LLM을 바꾸는 의미

Admin의 provider/model 설정은 Worker가 실행 snapshot을 읽어 실제 API 호출에 반영할 때만 의미가 있다. 오늘 반영한 Worker 계약은 payload의 다음 값을 사용한다.

- `execution.provider`
- `execution.model`
- `execution.modelOptions`
- `confirmedDraft.draftImageProxyUrl`
- `layoutFidelityPolicy`

Final 검증값:

```text
provider: openai
model: gpt-image-1
inputFidelity: high
referenceMode: image_edit
```

### 3.3 Final prompt 32,000자 초과 Hotfix

추가 실사용 실행에서 Final prompt가 39,675자로 증가해 OpenAI의 32,000자 제한 오류가 발생했다.

오류:

```text
Invalid 'prompt': string too long.
Expected maximum length 32000, got 39675.
```

조치:

- 운영 Final Worker의 OpenAI `prompt` 입력을 최대 30,000자로 제한했다.
- 동일 실패 실행을 Copy to editor로 재실행했다.
- n8n 실행 `1185`가 약 72초, 5MB로 성공했고 모든 노드가 완료됐다.
- 서버 측 정식 해결로 `api/_final-design-prompt-budget.js`를 추가했다.
- `/api/prompts-render`와 execution snapshot 양쪽에서 앞 72%와 뒤 28%의 핵심 문맥을 보존하며 30,000자 이하로 압축한다.
- 회귀 테스트에서 43,000자 이상의 합성 입력을 30,000자 이하로 줄이고 앞·뒤 내용과 layout policy 보존을 확인했다.

서버 측 수정 로컬 커밋:

- `c07ed07 Guard final design prompt length`

배포 주의:

- 로컬 GitHub HTTPS 인증이 없어 push가 실패했다.
- 연결된 GitHub 앱도 저장소 쓰기 권한이 없어 403을 반환했다.
- 따라서 현재 운영 장애는 n8n Hotfix로 해소됐지만, 서버 측 커밋 `c07ed07`은 GitHub 인증 후 push하여 Vercel에 배포해야 한다.

## 6. 보안 결정

사용자 결정:

- n8n의 OpenAI API 키는 현재 상태로 유지한다.

- 키 값을 문서, 로그, 응답에 기록하지 않음
- 저장소의 Final Worker fixture는 `Bearer __RETAIN_EXISTING_N8N_KEY__` placeholder 사용
- 실제 키가 Git에 추가되지 않았는지 secret scan 수행

남은 위험:

- n8n export 또는 MCP 조회 시 평문 키가 노출될 수 있다.
- 공유·다운로드·로그 보관 시 workflow JSON을 민감정보로 취급해야 한다.
- n8n/OpenAI Credential 등록 버그가 해결되면 Credential 참조 전환을 재검토한다.

### 11.3 Admin 연동 관련 남은 이슈

Claude 검토 문서에서 다음 두 항목이 남았다.

1. `api/_prompt-template-store.js`의 `DEFAULT_MODEL_SETTINGS.lofi_draft`에 `quality`와 `size` 기본 필드가 없다.
   - 현재 LO-FI Worker는 `quality=medium`, `size=1024x1536` fallback을 사용한다.
   - Admin에서 LO-FI 품질/크기를 실제 조정하게 하려면 기본 스키마와 UI 입력 필드를 추가해야 한다.
2. Final Design에는 prompt budget 압축이 있지만 LO-FI에는 동일한 압축이 없다.
   - LO-FI에도 길이 제한을 적용할지 결정하거나, 관련 문서를 “LO-FI는 압축 대상이 아님”으로 명확히 정정해야 한다.

## 13. 현재 Git/배포 상태

handoff 갱신 직전 상태:

```text
branch: main
tracking: origin/main
local ahead: 1 commit
unpushed commit: 7f681c5 Upgrade concept thumbnails with campaign artwork
working tree: handoff 문서 갱신 전 clean
```

이 문서 갱신 커밋까지 생성하면 로컬 ahead 수는 증가한다. 다음 담당자는 `git log origin/main..main`으로 정확한 미게시 커밋을 확인한 뒤 GitHub 인증을 복구하고 push해야 한다.

주의:

- 과거 이 세션에서 GitHub HTTPS 인증 문제와 GitHub 앱 403이 발생했다.
- push 성공 여부를 추정하지 말고 `git status --short --branch`와 원격 로그로 확인한다.
- Vercel이 GitHub 자동 배포를 사용한다면 push 전까지 최신 Wizard 썸네일은 운영에 나타나지 않는다.

## 14. 이어서 수행할 Task/Mission

### Mission A — 저장소 동기화와 배포 확인 (P0)

완료 기준:

1. `git log origin/main..main`의 커밋을 검토한다.
2. GitHub 인증을 복구하고 push한다.
3. Vercel 배포 성공 여부를 확인한다.
4. 운영 `promo-wizard.html`에서 다크모드, 캐러셀, 340px 카드, 고품질 썸네일을 확인한다.
5. 브라우저 console/network 오류가 없는지 확인한다.

### Mission B — Wizard Step 1 운영 E2E (P0)

필수 케이스:

1. Design MD 목록 로드
2. 검색 전/후 캐러셀 버튼 상태
3. 첫 카드에서 이전 버튼 disabled
4. 마지막 카드에서 다음 버튼 disabled
5. 카드 선택 후 강조와 localStorage 저장
6. 새로고침 후 선택 복원 및 선택 카드 자동 노출
7. 모바일 폭에서 버튼 숨김과 터치 스와이프
8. 긴 브랜드명/요약/태그 overflow
9. style 분류 누락 시 `unclassified.jpg`
10. 실제 thumbnail URL 실패 시 분류별 이미지 fallback

### Mission C — Final Design Gemini 운영 전환 검증 (P0)

1. 운영 n8n Workflow의 Published version을 export해 저장소 fixture와 대조한다.
2. OpenAI 실행 1건과 Gemini 실행 1건을 동일 입력으로 수행한다.
3. callback, DB status, final image URL, provider/model snapshot을 확인한다.
4. 실패 시 `failed` 상태와 error message 저장을 확인한다.
5. provider별 비용·지연·레이아웃 보존 품질을 기록한다.
6. 성공한 n8n execution ID와 run/finalDesign ID를 이 문서에 추가한다.

### Mission D — Admin LO-FI 옵션 완성 (P1)

1. `DEFAULT_MODEL_SETTINGS.lofi_draft`에 quality/size를 추가한다.
2. Admin UI에서 LO-FI quality/size를 수정·저장할 수 있게 한다.
3. execution snapshot과 Worker payload에서 값이 유지되는지 계약 테스트를 추가한다.
4. n8n LO-FI Worker가 fallback이 아닌 snapshot 값을 사용했는지 실행 데이터로 확인한다.

### Mission E — 브랜드 스타일 fidelity (P1, 별도 트랙)

레이아웃 fidelity와 혼동하지 않는다. Integrated Brief가 Design MD의 typography/color/radius/spacing/imagery 규칙을 일반화시키는 문제를 별도 계획으로 다룬다.

완료 기준 후보:

- Design MD style DNA 필수 구조 정의
- Integrated Brief에 원본 스타일 근거 보존
- Final prompt에 브랜드 규칙 전달
- LO-FI layout reference와 brand style reference 분리
- 대표 브랜드별 시각 회귀 비교

### Mission F — 보안 및 유지보수 (P1)

- n8n API 키는 사용자 결정에 따라 당분간 유지한다.
- Workflow export에 실제 키가 포함되지 않도록 계속 검사한다.
- n8n Credential의 OpenAI 등록 오류가 해결되면 Credential 참조 전환을 재검토한다.
- 사용하지 않는 백업 Workflow와 QA label guard 실패 JSON 3종의 유지/보관/삭제 정책을 결정한다.
