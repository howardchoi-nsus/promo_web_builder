# 단일 디자인 토큰 라이브러리

관리자는 공통 Dark 라이브러리 하나를 관리한다. 기존 세트는 과거 버전 참조를 위해 보존하고 생성/복제 API는 409를 반환한다. 첫 저장 전에는 기존 기본 세트로 페이지 생성을 유지하며, 첫 저장 후 공통 라이브러리를 신규 생성 후보로 사용한다. 기존 결과물의 고정 스냅샷은 바꾸지 않는다.

## 배포 순서

1. 기존 데이터 백업 후 대상 DB에 `db/migrations/082_single_design_token_library.sql`을 적용한다. 기존 마이그레이션 001–081이 적용된 DB를 전제로 한다.
2. 관리자/에디터 빌드와 API를 배포한다. 이 문서 작성 환경에는 DB 자격 증명이 없어 운영 마이그레이션을 실행하지 않았다.
3. 관리자 > 디자인 토큰에서 첨부 CSV 기반 기본 651개를 검토한 뒤 저장한다. 기본 데이터는 `data/design-tokens/dark-library.json`이다. GET은 초기 데이터를 보여줄 뿐 저장하지 않는다.
4. 카테고리별 편집, 전체 CSV 다운로드/업로드, 버전 복원을 확인한다. 신규 페이지 생성에서 `design-system`의 현재 버전이 선택되는지 확인한다.

## CSV 계약

UTF-8(BOM 허용), 컬럼은 `카테고리,토큰 유형,토큰명,값,참조 토큰`이다. 다운로드는 현재 탭/검색과 관계없이 전체 항목을 포함한다. 참조는 다른 토큰명을 입력하고 값은 비운다. Typography는 JSON 속성 객체다. 미완성 항목은 두 칸이 모두 비어 있거나 필수 Typography 속성이 빠질 수 있다.

지원 유형: color, dimension, number, fontFamily, fontWeight, shadow, typography.

업로드는 먼저 클라이언트에서 검증하고 교체 미리보기를 표시한다. '편집 목록에 반영' 후에도 저장 전까지 DB에는 반영되지 않는다. CSV는 전체 교체 방식이며, 이전 저장은 버전 이력에서 새 버전으로 복원할 수 있다.

651개 중 35개는 원본에서 필요한 값이 빠져 적용 대상에서 제외된다(기본 Typography 역할22 + Link2 + 특수 Dark Shadow8 + 프로필 미선택 Grid 참조3). 빈값을 0으로 바꾸지 않는다. CSV에 없는 Typography 변수4개는 임의 추가하지 않았다. Breakpoint 수치가 있더라도 자동 전환 규칙은 이번 변경에 포함하지 않는다.

## 저장 및 호환

`/api/design-token-library`는 관리자 세션을 요구한다. POST는 기준 버전과 전체 그래프를 검증한다. DB 함수는 잠금 및 기준 버전 확인 후 정의/값/이력/활성 버전을 한 트랜잭션으로 저장한다. 저장 중 실패하면 전체 롤백하며 오래된 편집 버전은 409로 거부한다.

단일 라이브러리 내부는 원래 값/참조를 metadata.libraryToken에 보존하고, 기존 생성 경로가 읽는 token_value에는 해석된 값을 저장한다. 미완성 항목과 Typography 복합 JSON은 CSS 변수 맵에 넣지 않는다. 완성된 Typography 복합 레시피는 관리·CSV 대상으로 보관하며, DOM의 텍스트 스타일에 자동 클래스 바인딩하는 기능은 이번 범위가 아니다.

기존 --app/--promo 토큰도 계속 읽을 수 있다. 새 네임스페이스를 레이아웃 검증과 렌더러가 지원한다. 주요 배경/텍스트/브랜드 색/반경/Shadow/서체에는 명시적 호환 매핑을 둔다. 모든 컴포넌트 상태와 그리드가 자동으로 적용된다는 뜻은 아니다. AI는 검증된 명시적 역할 매핑 토큰만 선택 가능하며 원본 단위·미완성 후보를 선택하지 않는다.

- `node scripts/test-admin-design-token-browser.mjs`: 실제 Vue 컴포넌트와 요청 mock으로 편집/카테고리 추가/전체 다운로드/가져오기 미리보기/교체 저장 검증. 시스템 Chromium 또는 `CHROMIUM_EXECUTABLE_PATH` 사용.
- 기존 디자인 토큰 관리 계약, 토큰 런타임, 컴포넌트 RenderSpec 및 레이아웃 동작 테스트.
- PostgreSQL 호환 PGlite에서 migration 재적용, 651개 저장, 기존 세트 보존, 활성 버전 유일성, 오래된 기준 거부, 실패 트랜잭션 롤백을 검증했다. 실제 운영 DB 연결 검증과는 구분한다.
- 기존 `test-promo-registry-composition-compiler.js:205`의 xPct 기대값 실패는 수정 전 HEAD 의존 모듈로도 동일하게 재현된다. 이번 토큰 변경과 무관한 기존 실패로 남겼다.
