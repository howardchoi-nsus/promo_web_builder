# 실시간 생성 미리보기 보정 — 실제 영역 디자인 생성

## 요청과 기존 구현의 차이

기존 구현은 이미 준비된 텍스트·스타일을 한 번에 표시하고 이미지 로딩만 순차적으로 보여줬다. 요청한 영상의 ‘와이어프레임이 섹션·컴포넌트 디자인으로 완성되는 과정’을 충족하지 못했다.

이번 보정은 표시 효과만 늘리는 대신 실제 영역 디자인 단계를 추가한다.

승인된 와이어프레임 → 영역별 등록 토큰 디자인 모델 실행 → 서버 검증·DB 저장 → 해당 영역 디자인 반영 → 해당 영역 이미지 준비 → 다음 영역 → 자동 품질검사 → 출력

## 구현

- 승인 시 서버가 승인 구조에서 디자인 작업 그룹을 만든다. 고정 헤더·히어로·혜택 목록을 만들지 않는다. 기존 섹션 경계를 우선 사용하고, 섹션 경계가 없는 문서는 컨테이너·그리드·카드 단위를 사용한다.
- 모든 노드는 정확히 한 그룹에 속한다. 페이지 기본 스타일을 먼저 처리하고, 과도한 호출을 방지하기 위해 최대 12개 작업 그룹으로 묶는다. 실제 섹션 수·트리는 변경하지 않는다.
- 새 Admin 프롬프트 `promo_page_section_designer` / ‘AI 영역 디자인’이 현재 페이지·대상 노드·등록 후보를 받아 실제 스타일 결과를 만든다. Admin 목록에는 구성 승인 후 자동 실행하는 디자인 단계로 표시한다.
- 모델은 해당 그룹의 등록 스타일·간격·오버레이만 변경할 수 있다. 레이아웃·트리·노드·텍스트·사실·소스·에셋·URL·동작·미디어 요청 변경은 차단한다. 불필요한 변경을 강제하지 않으며 적절한 기존 선택은 유지할 수 있다.
- 역할 호환·보더 조합·스키마 검증 후 결과와 완료 그룹을 문서 Revision 및 generation job 완료와 함께 원자적으로 저장한다. 실패·잘못된 응답·동시 수정에서는 이전 결과를 보존한다.
- 작업 프롬프트·모델·스킬 설정이 도중에 바뀌면 혼합하지 않고 중단한다. 완료된 디자인 기록과 현재 토큰 진단을 저장한다.
- 완료되지 않은 노드는 중립 와이어프레임으로 유지하고, 진행 중인 작업 그룹에만 강조를 표시한다. 저장된 결과가 도착한 노드의 디자인만 드러낸다. 미완성 JSON이나 타이머 기반 가짜 진행은 렌더링하지 않는다.
- 각 그룹의 스타일 완료 후 해당 그룹에 속한 이미지부터 준비한다. 완료 스타일·이미지는 새로고침과 재시도에서 건너뛴다. 기존 미디어 순차 처리·재개·문서 전환 방어를 유지한다.
- 표시 효과는 미리보기 계층으로 격리한다. 모션 감소 설정·출력/SSR 격리·현재 Revision 품질검사를 유지한다. 영역 디자인이 남아 있으면 품질검토·출력을 통과시키지 않는다.
- 기존 승인 완료 문서는 강제로 새 모델 작업을 실행하지 않는다. 새 기능 활성화 후 생성·승인한 구성부터 적용한다.

## 새 설정과 도입 순서

이전 이미지 표시 개선과 달리 이번 수정은 새 모델 작업이므로 **migration 093과 프롬프트 활성화가 필요하다.**

1. 코드를 배포한다. 기존 서비스를 중단하지 않도록 `PAGE_SCHEMA_SECTION_DESIGN_ENABLED`는 기본 false로 둔다.
2. 대상 DB에 `db/migrations/093_page_section_design_prompt.sql`을 실행한다. 활성 PageSchema planner의 등록 모델·실행 설정을 복사한 Draft를 만든다. 스킬 연결은 자동 복사하지 않는다. 재실행해도 중복 생성하지 않는다.
3. Admin → 프롬프트 관리 → ‘AI 영역 디자인’에서 모델·지침을 확인하고 검증·활성화한다. 실제 통합 검증과 로컬 mock 검증은 구분한다.
4. 적용 대상 Vercel 환경에 `PAGE_SCHEMA_SECTION_DESIGN_ENABLED=true`를 설정하고 다시 배포한다.
5. 새 페이지 미리보기를 생성하고 구성을 승인해 영역별 실제 디자인을 확인한다. 이미 완성된 예전 문서를 열기만 해서는 새 과정을 재생하지 않는다.

모델 호출 수와 생성 시간이 기존 이미지 로딩 표시보다 늘어난다. 모델·토큰 예산·실행 시간은 Admin 등록 설정을 사용하며, 이번 코드에 특정 모델을 고정하지 않는다.

기능을 중단해야 하면 플래그를 false로 내려 새 작업을 막는다. 진행 중 문서의 완료 결과는 보존하고, 미완료 작업은 다시 활성화한 뒤 이어가거나 새 구성을 생성한다. 미완료 문서를 완료한 것으로 바꾸거나 구형 출력 경로로 우회하지 않는다.

## 검증 범위

- 계약/서비스: 그룹 분할과 노드 전체 포함, 등록 역할·그룹 범위 제한, 중복/임의 CSS/내용·배치 변경 거절, 완료 재사용, 설정 변경 중단, Revision 방어, 실행 중 202, 프롬프트 누락 안내, 순차 디자인→미디어, 출력 차단.
- PGlite: migration 093 재실행·Draft·모델 상속, 실제 프롬프트 조립, JSONB 저장·재조회, 작업/문서 원자적 완료, 캐시, 잘못된 응답 롤백·재시도, 중단 후 이어가기, 뒤늦은 응답이 최신 수정을 덮지 않음.
- 실제 빌더 브라우저(mock provider): 승인한 와이어프레임 → 실제 모델 결과의 토큰 색상 변경 → 완료 영역 유지 → 다음 영역 공급자 실패 → 새로고침 → 재시도 → 완료 영역/이미지 중복 생성 없음 → 자동 품질검사 통과.
- 기존 로딩·Reveal·모션 감소·HTML/SSR 격리·토큰·미디어·자동 품질검토·Admin 계약 회귀를 함께 실행한다.

실제 LLM·Neon·Blob·Vercel Preview 통합과 Production 배포는 이번 개발의 완료로 간주하지 않는다. 실행 결과는 최종 검증 후 추가 기록한다.

## 최종 로컬 검증 결과

- Admin·Visual editor·Nuxt runtime 빌드 통과.
- `qa:design-preview` 42개 계약·브라우저·PGlite 검사 통과.
- Worker 프롬프트 계약, 검증된 후보 실행 snapshot, Admin 프롬프트 생명주기 계약도 각각 통과.
- 이미지 공급자 실패와 디자인 공급자 실패를 연속 재현하고 각각 새로고침·재시도했다. 이미 완료된 스타일 모델 호출·이미지 생성은 반복하지 않았다.
- 같은 실행의 과거 실패 행마다 복구 버튼이 중복되던 문제를 수정해 현재 실패 행에만 표시한다.
- 품질검사 중 준비 완료된 결과가 검사 종료 후 다시 숨겨졌다 나타나지 않도록 표시 캐시를 보정했다.
- SQL 왕복에서 새로고침 요청이 이전 Revision을 읽은 직후 기존 모델 작업이 완료되는 경합도 검증했다. 저장된 완료 결과를 재조회해 반환하고 모델 호출을 반복하지 않는다.
- 새 실행은 별도 작업 ID를 사용하며 문서 전환 뒤 이전 작업의 오류가 새 문서 상태를 덮지 않도록 했다.
- 기능이 꺼져 있을 때 새 디자인 버전을 명시한 승인은 오류로 안내한다. 요청한 기능을 이미지 전용 방식으로 조용히 낮춰 처리하지 않는다.

모델 공급자 응답은 fixture로 검증했고 SQL은 PGlite를 사용했다. 실제 LLM·Neon·Blob·Vercel Preview 통합 및 Production 배포는 미수행이다. 운영 활성화 전 migration 093·프롬프트 검증/활성화·환경변수 설정을 확인해야 한다.
