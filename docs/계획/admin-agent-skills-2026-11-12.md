# Admin 공통 스킬 등록과 프롬프트별 연결

## 구성

- Admin → **스킬 관리** (`/prototype?view=admin&tab=agent-skills`): 스킬 키·이름·설명·출처·MD·사용 가능 여부를 관리한다. `.md` 업로드 또는 직접 입력, 불변 버전 추가, 저장 버전 MD 다운로드, 글로벌 활성/비활성 전환을 제공한다.
- Admin → **프롬프트 관리 → 해당 프롬프트 → 연결된 스킬**: 사용할 버전과 적용 순서를 선택한다. 연결 해제·재정렬·저장 MD 확인을 제공한다. 기존 프롬프트의 신규 버전 생성·검증·활성화·롤백 절차에 함께 저장된다.
- 글로벌 등록은 자동 적용을 뜻하지 않는다. 새 MD 버전을 저장해도 기존 프롬프트의 연결은 바뀌지 않는다. 특정 프롬프트의 버전 선택을 바꾸어야 새 버전이 적용된다.
- 이 기능은 MD 지침 연결이다. Taste Skill의 Node 스크립트, 브라우저 검사, 이미지·CSS·HTML 자산, Stop hook 또는 외부 참고 문서를 자동 설치하거나 실행하지 않는다. 특정 외부 스킬을 기본으로 등록하거나 활성화하지 않았다.

## 운영 적용 순서

1. `db/migrations/091_admin_agent_skills.sql`을 대상 DB에 적용한다. 새 스킬·버전 테이블과 버전 변경/삭제 방지 트리거를 생성한다. 반복 적용할 수 있으며 기존 프롬프트를 수정하지 않는다.
2. 코드 배포 후 Admin에서 MD를 검토하고 등록한다. 원문은 텍스트로만 미리보기하며 HTML이나 스크립트를 실행하지 않는다.
3. 필요한 프롬프트에서 특정 스킬 버전을 연결하고 기존 저장·검증·활성화 절차를 진행한다. 예: `promo_page_schema_planner`에 검토한 디자인 지침을 연결한다.
4. Preview에서 실제 생성과 실행 스냅샷의 `skillSnapshots` 및 `renderedPromptHash`를 확인한다. 버전 고정·비활성 오류·출력 계약 준수도 확인한다.

## 데이터와 실행

- `promo_agent_skills`: 공통 키, 이름, 설명, 글로벌 활성 여부, 최신 버전, 변경자·시간.
- `promo_agent_skill_versions`: 불변 MD, 버전 번호, 당시 이름·출처, SHA-256, 변경 기록·작성자.
- `prompt_templates.model_options.skillBindings`: 순서가 있는 `{skillVersionId}` 배열. 기존 prompt history/version lifecycle이 연결 내역을 보존한다.
- 공통 `createPromptExecutionSnapshot` 경로와 `/api/prompts-render`에서 연결 버전을 해석하여 실제 LLM 프롬프트에 포함한다. MD의 `{{…}}`는 템플릿 변수로 확장하지 않는다.
- 실행 스냅샷·worker 메타·PageSchema/미디어 실행 기록에 사용한 스킬 ID·버전·내용 해시를 남긴다. 이미 만들어진 실행 스냅샷의 렌더링된 프롬프트는 그대로 유지한다. 템플릿 원문을 읽는 레거시 외부 클라이언트는 공통 실행/렌더 경로를 사용해야 하며 원문 GET 자체를 실행 조합으로 바꾸지 않았다.
- 연결이 없으면 스킬 테이블을 조회하지 않는다. 091 미적용 상태에서도 기존 무연결 실행은 스킬 기능 때문에 차단되지 않는다.
- 연결 버전 없음, 글로벌 비활성, 해시 불일치, 예산 초과는 구체적인 오류로 처리한다. 조용히 생략하거나 최신 버전으로 바꾸지 않는다. 글로벌 비활성화는 이미 연결된 프롬프트의 **새 실행**도 차단하므로 연결 해제 또는 재활성화가 필요하다.

## 제한과 정책

- MD 하나는 UTF-8 60,000 bytes 이하, 프롬프트당 최대 네 버전, 합계 80,000 bytes 이하.
- 스킬을 포함한 전체 프롬프트는 250,000 bytes 이하여야 하며, 기존 final-design의 30,000자 제한도 유지한다. 개별 모델의 실제 context 제한을 자동 보장하는 수치는 아니다.
- 등록소 읽기·쓰기 모두 관리자 인증을 요구한다. 생성 런타임은 서버 내부에서만 등록소를 읽는다.
- 기본 정책·서버 보안·출력 스키마·허용 컴포넌트·등록 디자인 토큰·사실 정보 제약이 스킬보다 우선한다. 그 범위에서 고객의 구체적 요청이 일반적인 디자인 선호보다 우선한다. 스킬 프롬프트 지침만으로 보안을 보장한다고 간주하지 않으며 기존 서버 검증을 유지한다.
- 외부 URL은 출처 메타데이터다. 서버가 URL을 자동으로 가져오거나 MD의 파일 경로·명령을 실행하지 않는다.

## 확인 결과

- Admin 빌드 성공.
- 범위 한정 계약·API·PGlite·브라우저·기존 출력 검사 27개 통과.
- 별도 Admin 프롬프트 브라우저 검사: 실제 프롬프트 편집 UI에서 스킬 연결 → 기존 저장·검증·활성화 payload 보존 확인.
- Worker 프롬프트 계약, 후보 프롬프트 실행, 프롬프트 lifecycle, 하드코딩 프롬프트 방지 검사 통과.
- PGlite에서 091 반복 적용, 불변 버전, stale revision 거절, 중복 키, 비활성 차단, 관리자 인증, 예산 제한, literal MD와 실행 기록을 확인했다.
- 운영 Neon의 091 적용, 실제 LLM 공급자 호출 및 Vercel Preview/Production 배포는 미실행이다. 전체 저장소 테스트 통과나 실제 배포 완료를 의미하지 않는다.
