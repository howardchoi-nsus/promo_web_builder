# 섹션 이미지 프롬프트 운영 안정화 검토안

- 문서 상태: 임시 초안
- 작성일: 2026-07-24
- 적용 대상: 프로모션 빌더 섹션 배경 이미지 및 컴포넌트 이미지 생성

## 1. 작성 배경

프로모션 빌더의 기본 기능이 안정화된 이후, 관리자가 이미지 생성 프롬프트를 반복적으로 수정하면서 생성 결과의 분위기와 품질을 조정할 예정이다.

현재 프롬프트는 단순한 안내 문구가 아니라 다음 실행 조건을 함께 포함한다.

- 서버가 전달하는 변수
- 이미지 생성 provider와 model
- 응답 형식
- 모델 옵션
- 이미지 생성 제약 조건
- 관리자 추가 지침

따라서 프롬프트를 일반 문구처럼 즉시 수정·적용하면 변수 불일치만으로도 이미지 생성 기능 전체가 중단될 수 있다.

실제로 `section_background_image` 프롬프트에 서버가 제공하지 않는 `brandPalette`, `aspectRatio` 변수가 추가되면서 프롬프트 렌더링 단계에서 HTTP 409가 발생했다. 이 요청은 이미지 provider 호출 전에 중단되었다.

## 2. 기본 의견

프롬프트는 일반 텍스트가 아니라 **버전과 실행 계약을 가진 운영 설정**으로 관리해야 한다.

프롬프트 품질을 세부적으로 조정하기 전에 다음 기반을 먼저 마련하는 것이 안전하다.

1. 프롬프트 유형별 변수 계약
2. 초안과 운영 버전 분리
3. 활성화 전 자동 검증
4. 시스템 제약과 자연어 지침 분리
5. 프롬프트 블록 조립
6. 대표 테스트 사례와 결과 비교
7. 실행 이력과 즉시 롤백

## 3. 프롬프트 변수 계약

프롬프트 유형별로 서버가 제공할 수 있는 변수를 스키마로 정의한다.

섹션 배경 이미지의 목표 변수 예시는 다음과 같다.

| 구분 | 변수 예시 | 용도 |
| --- | --- | --- |
| 콘텐츠 | `sectionName`, `contentJson` | 섹션의 의미와 등록 콘텐츠 전달 |
| 디자인 | `backgroundColor`, `fadeMode`, `aspectRatio` | 배경색, 페이드, 출력 비율 전달 |
| 브랜드 | `brandPalette`, `adminGuidance` | 브랜드 색상과 관리자 지침 전달 |
| 배치 | `safeArea`, `focalPosition` | 텍스트 안전 영역과 주요 피사체 위치 전달 |
| 출력 | `imageSize`, `backgroundSize` | 해상도와 `contain`/`cover` 등의 출력 조건 전달 |

관리자 페이지에서는 등록된 변수만 선택하거나 삽입할 수 있게 한다. 직접 `{{variableName}}` 형식으로 입력한 미등록 변수는 저장 또는 활성화 단계에서 차단해야 한다.

변수 추가는 프롬프트 본문만 변경하는 작업이 아니다. 다음 항목을 함께 변경해야 한다.

- 변수 스키마
- 서버의 변수 생성 로직
- 기본값 및 허용값
- 관리자 입력 UI
- 실행 스냅샷
- 계약 테스트

## 4. 프롬프트 생명주기

프롬프트 상태는 최소한 다음과 같이 구분한다.

| 상태 | 의미 |
| --- | --- |
| 초안 | 자유롭게 수정할 수 있으나 운영에서는 사용하지 않음 |
| 검증 완료 | 변수·모델·응답 형식 검증과 시험 실행을 통과함 |
| 활성 | 프로모션 빌더의 실제 생성 요청에 사용함 |
| 보관 | 이전 버전으로 유지하며 필요할 때 롤백할 수 있음 |

활성 프롬프트를 직접 덮어쓰지 않는다. 활성 프롬프트를 수정하면 새로운 초안 버전을 만들고 검증 및 승인 후 활성화한다.

한 프롬프트 유형에는 운영 활성 버전이 하나만 존재하도록 DB 제약과 서버 검증을 적용한다.

## 5. 저장 검증과 활성화 검증

### 5.1 저장 단계

초안 저장 단계에서는 편집을 허용하되 다음 문제를 즉시 표시한다.

- 알 수 없는 변수
- 중복 변수
- 필수 변수와 선택 변수의 충돌
- 지원하지 않는 provider 또는 model
- 잘못된 응답 형식
- 허용 범위를 벗어난 모델 옵션

### 5.2 활성화 단계

활성화 전에는 다음 조건을 모두 통과해야 한다.

- 미등록·미치환 변수가 없음
- 모든 필수 변수가 테스트 입력으로 렌더링됨
- provider와 model 조합이 허용됨
- 이미지 프롬프트의 응답 형식이 `image`임
- 페이드와 정렬 값이 시스템의 허용값과 일치함
- 프롬프트 길이가 provider 제한 이내임
- 금지 표현 및 이미지 안전 정책을 위반하지 않음
- 대표 콘텐츠를 사용한 시험 요청이 성공함

관리자 화면에는 최종 렌더링 프롬프트 미리보기와 검증 결과를 표시한다.

## 6. 프롬프트와 시스템 제약 분리

정확성이 필요한 값은 자연어 프롬프트에만 의존하지 않는다.

### 6.1 코드가 통제할 항목

- 이미지 비율과 해상도
- 페이드 허용값
- 배경색 형식
- 생성 대상이 섹션 배경인지 컴포넌트 필드인지
- 이미지 배치 위치
- 재시도 및 제한 시간

### 6.2 프롬프트가 통제할 항목

- 시각적 분위기
- 소재와 표현 방식
- 강조 대상
- 시각적 밀도
- 브랜드 감성
- 네거티브 이미지 지침

### 6.3 렌더러 또는 후처리가 통제할 항목

- 실제 페이드 방향과 색상
- 섹션 배경색과의 블렌딩
- `contain` 또는 `cover`
- 배경 위치
- 모서리와 마스크
- 출력 영역 크기

이미지 모델은 정확한 CSS 렌더러가 아니므로 페이드 색상과 위치처럼 일관성이 필요한 결과는 렌더러에서도 보장해야 한다.

## 7. 프롬프트 조립 구조

하나의 긴 본문을 직접 관리하는 방식보다 검증된 블록을 조립하는 방식을 권장한다.

권장 블록은 다음과 같다.

1. 공통 이미지 생성 원칙
2. 선택한 브랜드 및 디자인 토큰 지침
3. 섹션 또는 컴포넌트 콘텐츠
4. 레이아웃과 텍스트 안전 영역
5. 배경색과 페이드 지침
6. 관리자 추가 지침
7. 네거티브 프롬프트
8. 출력 규격

시스템 필수 블록은 관리자가 삭제할 수 없게 하고, 관리자는 허용된 블록의 내용과 순서만 조정하도록 구성한다.

## 8. 테스트 및 결과 비교

프롬프트 변경은 일반 코드 테스트만으로 품질을 보장할 수 없다. 다음 대표 사례를 고정 테스트 세트로 관리한다.

- 텍스트 중심 Hero
- 이미지 중심 Hero
- 밝은 배경과 어두운 배경
- 콘텐츠가 짧은 섹션과 긴 섹션
- 페이드 없음·왼쪽·오른쪽·양끝
- 텍스트 안전 영역이 왼쪽·중앙·오른쪽인 경우
- 로고나 브랜드 표현이 포함된 콘텐츠
- 이미지 안전 정책에 민감할 수 있는 콘텐츠

기존 활성 버전과 새 초안 버전으로 같은 입력을 생성하고 다음 항목을 비교한다.

- 생성 성공률
- 텍스트 영역 가독성
- 배경색 일치도
- 브랜드 적합성
- 피사체 위치와 크기
- 불필요한 문자·로고 생성 여부
- 사용자가 결과를 채택한 비율

## 9. 실행 이력과 롤백

각 이미지 생성 실행에 다음 정보를 보존한다.

- 프롬프트 ID와 버전
- 최종 렌더링된 프롬프트
- 전달 변수 스냅샷 또는 민감정보를 제거한 해시
- provider와 model
- 모델 옵션
- 생성 결과와 자산 ID
- 실패 단계와 오류 코드
- 재시도 횟수
- 사용자 채택·삭제·재생성 결과

활성화 이후 실패율이나 품질 문제가 기준을 초과하면 이전 활성 버전으로 즉시 롤백할 수 있어야 한다.

## 10. 단계별 적용안

### P0. 변수 계약 및 활성화 방어

- 프롬프트 유형별 변수 스키마 정의
- 미등록 변수 저장 또는 활성화 차단
- 필수 변수 누락 검증
- provider/model/response format 검증
- 페이드 등 열거값 통일
- 렌더링 미리보기 제공

### P1. 버전과 롤백

- 활성 프롬프트 직접 수정 제거
- 수정 시 새 초안 버전 생성
- 검증 완료·활성·보관 상태 도입
- 활성 버전 단일성 보장
- 이전 버전 즉시 롤백

### P2. 프롬프트 조립 구조

- 공통·브랜드·콘텐츠·배치·네거티브·출력 블록 분리
- 필수 시스템 블록 잠금
- 관리자 변경 가능 범위 정의

### P3. 시험 생성과 결과 비교

- 대표 테스트 데이터 세트 구축
- 활성 버전과 초안 버전 비교 생성
- 관리자 비교·승인 화면
- 실패 및 품질 평가 기록

### P4. 단계적 운영 적용

- 제한된 사용자 또는 실행 비율에 먼저 적용
- 실패율과 채택률 모니터링
- 기준 초과 시 자동 중지 또는 롤백

### P5. 프롬프트 품질 최적화

- 평가 결과를 기반으로 프롬프트 조정
- 콘텐츠 유형별 프롬프트 변형 검토
- 모델별 최적 프롬프트 분리
- 자동 추천은 승인 기반으로 제한

## 11. 현재 확인된 즉시 조치 항목

현재 운영 중인 `section_background_image` 프롬프트에는 서버에서 전달하지 않는 다음 변수가 포함되어 있다.

- `brandPalette`
- `aspectRatio`

이 변수들은 소스의 변수 공급 로직을 확장하기 전까지 미치환 변수로 판정되어 이미지 생성 요청을 중단시킨다.

또한 프롬프트에 기술된 페이드 값과 시스템 허용값이 일치하지 않는다.

- 프롬프트 표현: `bottom`, `top`, `left`, `radial`
- 현재 시스템 값: `none`, `left`, `right`, `both`

단기 복구 시에는 미지원 변수를 고정 문구로 변경하고 페이드 표현을 현재 열거값에 맞춘다. 정식 개발 단계에서는 변수 계약부터 확장한 후 프롬프트에서 사용한다.

## 12. 결론

프롬프트 튜닝보다 먼저 **안전하게 실험하고 검증하고 되돌릴 수 있는 운영 구조**를 구축해야 한다.

이번 HTTP 409 오류는 개별 프롬프트 작성 실수만이 아니라 프롬프트 변수 계약, 버전 관리, 활성화 검증이 충분히 분리되지 않았다는 구조적 신호다.

P0와 P1을 우선 적용한 뒤 생성 결과의 세부 품질 조정을 시작하는 것이 적절하다.
