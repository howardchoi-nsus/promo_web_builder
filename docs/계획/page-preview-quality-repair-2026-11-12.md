# 페이지 폭·가독성·자동 품질 보정

## 확인한 원인

- 첨부한 Desktop Grid와 Overview 원본 PDF는 1920px·1440px 모두 좌우 각각 360px을 지정한다. CSV와 저장소의 `data/design-tokens/dark-library.json`도 같은 값이다. 1440 토큰의 1920 참조를 잘못된 데이터로 간주하거나 임의로 수정하지 않았다.
- 기존 PageSchema 데스크톱 미리보기는 1280px 고정 폭을 사용했다. 좌우 360px을 빼면 콘텐츠는 560px이다. 원본 1440px 기준의 콘텐츠 폭은 720px, 컬럼 폭은 `(720 - 11 × 24) / 12 = 38px`이다.
- 기존 검사는 이미지와 글자의 대비, 불투명 카드의 이미지 가림을 확인하지 않았고 PageSchema 자동 보정도 수행하지 않았다.
- 보더 색상과 `--border-width-sm/md/lg/xl`은 원본 목록에 있지만 border-style 유형의 선 종류 토큰은 없다. migration 090은 유형을 허용할 뿐 선 종류 토큰을 등록하지 않는다. 운영 Admin에서 이후 추가했는지는 별도 확인 대상이다.

## 구현

1. PageSchema 미리보기 폭을 등록된 화면별 `--grid-reference-…-width`에서 읽는다. 현재 원본 기준 Desktop 1440px, Tablet 768px, Mobile 375px이다. 패널에서는 축소 표시하며 기준 폭을 안내한다. 기존 레거시 렌더러의 기준 폭은 변경하지 않았다.
2. AI에 reference width, margin, gutter, columns, content width, column width를 함께 전달한다. 확정 여백을 임의로 줄이는 대신 사용 가능한 폭에 맞는 컬럼 수와 이미지 배치를 설계하도록 안내한다. 활성 DB 프롬프트 자체를 새 버전으로 교체한 작업은 아니다.
3. 렌더러가 실제 문구의 대비, 이미지 뒤 배경·등록 그라데이션, 좁은 다중 컬럼, 같은 영역의 콘텐츠 겹침, 이미지 가림을 검사한다. 이미지 픽셀은 문구 영역의 5×5 지점을 샘플링한다. 모든 픽셀에 대한 완전한 시각 검증을 의미하지 않는다. 외부 이미지의 CORS 등으로 읽을 수 없는 경우 통과로 간주하지 않는다.
4. 서버 전용 `repair-quality` 작업이 등록된 호환 색상·줄 높이로 보정하고, 좁거나 겹친 배치를 정상 흐름으로 조정한다. 불완전한 선택 보더는 제거하고, 보더 속성이 부족한 장식 구분선은 제거할 수 있다. 미등록 CSS·색·선 종류를 만들지 않는다.
5. 이미지가 가려지거나 등록 색상으로 이미지 위 문구의 대비를 확보하지 못하면 완료 이미지를 보존해 콘텐츠 이미지로 분리한다. 컬럼·이미지 배치·구분선 제거 등 구조가 바뀌면 구조 지문을 갱신하고 기존 페이지 미리보기·구성 승인 절차로 돌아간다. 스타일만 바뀌면 승인 구조를 유지한다.
6. 보정은 한 검사 실행에서 최대 두 번 저장·재검사한다. 현재 Revision이 통과해야 새 창 보기·출력을 활성화한다. 진행·실패·차단 원인·CTA 안내는 채팅에 표시한다. 원인 없이 비활성 버튼만 남기지 않는다.
7. CTA URL이 없으면 동작 없는 안내 문구로 렌더링하고 버튼 배경·보더·패딩을 적용하지 않는다. 경고를 표시하되 이 미정 항목만으로 페이지 출력을 차단하지 않는다. 실제 링크·submit 동작의 검증은 유지한다.
8. 보더 경고는 대상별 누락 속성을 구체적으로 안내하며, 선택 후보·자동 매핑은 원본의 `--border-width-sm`을 인식한다. 색상·두께·선 종류가 모두 등록된 경우에만 보더를 사용한다.

## 저장과 안전

- 서버가 현재 소유 문서와 Revision을 확인하고 원본에서 보정을 계산한다. 클라이언트가 보내는 임의 CSS·문구·URL·PageSchema 교체를 보정으로 허용하지 않는다.
- 사실 콘텐츠, source ID, 완료 asset ID·URL 및 mediaBindings를 보존한다. 이미지 분리 때문에 다시 생성하거나 유료 이미지 요청을 반복하지 않는다.
- 저장 시 요청 요약 Revision을 같은 SQL 작업에서 잠가, 도중에 변경된 요약에 오래된 보정을 저장하지 않는다.
- 기준 폭이나 사용 정책이 누락된 경우 잘못된 캔버스 측정치를 근거로 구조를 보정하지 않는다. 기존 등록 토큰 재연결 경로와 구체적인 오류 안내를 유지한다.
- 이 변경에 새 DB migration은 없다. borderStyle 저장에는 기존 090이 필요하다. 운영 토큰 데이터나 활성 정책을 외부 DB에서 수정하지 않았다.

## 검증과 배포 상태

- Admin, visual-editor, Nuxt runtime 빌드 성공.
- 범위 한정 검사 25개 통과: 계약·보안·등록 토큰·API·브라우저·PGlite SQL·Nuxt SSR/하이드레이션 포함.
- 새 회귀 사례: 실제 원본 토큰으로 1440/720/38px 계산, 등록 색상 대비 보정, 불완전 보더/구분선 처리, CTA 정적 문구, 불투명 카드에 가린 이미지 분리 → 재승인 → 품질 통과, 이미지 재생성 없음, 요약 변경 시 보정 저장 차단.
- 실제 LLM·Neon·Blob·Vercel Preview 통합 검증은 미실행이다. 전체 저장소 테스트 통과를 의미하지 않는다. 기존에 기록한 레거시 fixture 실패는 별도다.
- Production 미반영. 기존 예외 승인은 이 수정의 Production 반영 승인으로 확대하지 않았다.
