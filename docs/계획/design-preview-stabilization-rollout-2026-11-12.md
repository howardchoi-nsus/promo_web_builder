# 디자인 미리보기 안정화 구현·검증·배포 기록

기준일: 2026-11-12. 이 문서는 코드·로컬 검증 결과와 미검증 운영 항목을 구분한다.

## 구현 범위

| 범위 | 구현 |
| --- | --- |
| 타이포그래피·컬러 | 활성 라이브러리의 대상·속성·상태·참조가 호환되는 등록 토큰 후보를 제공. 제목·본문 크기 두 가지로 제한하던 선택 경로 확장 |
| 공통 계약 | 생성 스키마·서버 검증·렌더러가 공통 스타일 역할 정의를 사용. 허용 대상이 아닌 역할과 미등록 값 차단 |
| 보더 | 등록된 색상·두께·선 종류 조합 사용. 빠진 속성은 같은 대상에 허용된 등록 후보로만 보완. 조합 자체가 없으면 생성 후보에서 제한하고 경고 |
| 등록 유형 | `borderStyle`, `gradient` 및 `svh`·`dvh` 길이 지원. 등록한 높이 토큰을 height/min-height에 연결 |
| 이미지 | 구성 승인 후 순차 자동 준비. DB 실행 lease와 입력 해시로 중복 호출 제한. 결과와 작업 완료를 원자적으로 저장 |
| 복구 | 진행 중 작업은 202로 조회. 완료 결과 응답 유실 시 재사용. 실패한 요청부터 채팅에서 재시도 |
| 추가 수정 | 의도·비율·참조 콘텐츠가 같으면 기존 이미지를 재사용. AI가 명시한 regenerate 요청은 재사용하지 않음 |
| 변경 충돌 | 생성 중 구조·요청·기준 요구사항이 바뀌면 결과를 적용하지 않고 업로드 파일 정리 시도 |
| 키비주얼 | 범용 image 노드의 background 표현과 container의 등록 gradient overlay 지원. 전용 고정 히어로 DOM 템플릿 없음 |
| 아이콘 | 활성 컴포넌트의 등록 에셋을 카탈로그로 제공. 이미지 URL 또는 짧은 문자 기호를 안전하게 렌더링. 기존 4개 아이콘 ID 호환 유지 |
| UI | 추가 폼 없이 기존 채팅으로 안내·수정·재시도. 에셋 준비 중에는 최종 품질 검사 자동 실행 보류 |
| 출력 | 새 styleChoices 컨텍스트의 rendererVersion 2를 HTML/Nuxt 경로가 지원. 기존 version 1 문서 호환 유지 |
| 저장 | 품질 검사 저장의 내용 비교도 JSON 속성 순서에 무관하게 처리 |
| SSR 스타일 | 서버의 style 텍스트 이스케이프로 선택자가 깨지던 경로 수정. 검증된 컴파일러 CSS만 원문 출력하고 사용자 텍스트는 계속 이스케이프 |
| 후보·기존 문서 | 생성 후보 수 제한과 기존 역할 해석을 분리. 토큰 추가 후 기존 선택을 유지하고 수정 시 기존 선택 역할을 모델 계약에 포함 |
| 회귀 검사 | `qa:design-preview`와 GitHub Actions의 범위 한정 계약·브라우저·PGlite 검사 추가 |

기존 문서는 등록 토큰 선택 확장 버전 표시가 없으면 기존 역할 해석을 유지한다. 새 생성 문서와 편집 컨텍스트에서 등록 후보 선택을 활성화한다. 미등록 CSS 대체값을 추가하지 않는다.

## 운영 선행 조건

1. 기존 DB migration 086·088이 적용되어 있어야 한다. 이미지 준비 전에 저장소 연결과 테이블을 확인한다.
2. `090_design_token_border_style.sql`을 테스트 DB에 적용한다. `borderStyle` 저장 전에 이 migration의 적용 여부를 확인한다.
3. 실제 활성 디자인 토큰과 사용 정책을 대조한다. 이번 환경에서는 Production 등록 목록을 조회하지 못했다.
4. 보더를 그리려면 해당 대상에 맞는 색상·두께·선 종류 토큰이 모두 있어야 한다. gradient·전체 화면 높이도 해당 등록 토큰이 있어야 사용한다.
5. 이미지 공급자 모델과 활성 `component_image` 프롬프트를 확인한다. 배경 이미지에는 등록 배경색이 기존 계약의 6자리 hex 형식일 때 `section_background_image`를 사용하며, 그 외에는 배경색을 컨텍스트로 전달하는 일반 이미지 프롬프트를 사용한다.
6. Preview용 모델 자격 증명과 `BLOB_READ_WRITE_TOKEN`, 테스트 DB를 환경 비밀 설정에 연결한다. 이 환경에는 현재 연결되어 있지 않다.
7. 코드·DB·활성 프롬프트·모델·토큰 정책 버전을 함께 기록한 실제 Preview 검증 후 Production에 반영한다.

### 관리자 등록

컴포넌트 관리에서 Draft를 열고 **AI 페이지용 등록 이미지·아이콘**에 종류와 URL 또는 기호를 입력한다. 저장 후 활성 버전으로 전환해야 AI 카탈로그에 포함된다. 컴포넌트 목록의 장식용 iconKey와 고객 페이지에 사용할 실제 아이콘 에셋은 구분한다.

토큰 관리에는 Border Style과 Gradient 유형을 추가했다. 예를 들어 `--border-style-solid = solid`를 쓰려면 먼저 Admin에 실제로 등록해야 한다. 이 예시 값을 시스템이 자동 등록하거나 미등록 대체값으로 사용하지 않는다.

gradient는 안전한 linear-gradient와 제한된 색상 정지점을 지원한다. 임의 CSS·URL·스크립트 표현을 받지 않는다. 영상 자동 재생, 모바일 메뉴 상호작용, 등록되지 않은 웹폰트 파일 로딩은 이번 범위에 포함하지 않는다.

### 상한과 제한

- 스타일 후보는 대상·속성별 대표 등록값으로 제한한다. 중복 값은 제거하고 가족별로 분산한다. 모든 토큰을 무제한 enum으로 전달하지 않는다.
- 등록 이미지 카탈로그는 최대 32개, 기본 아이콘을 포함한 아이콘 카탈로그는 최대 36개를 노출한다.
- 모델의 구조화 출력 enum 예산을 초과하면 공급자 호출 전에 명시적인 한도 오류로 처리한다.
- 실제 사진 배경의 대비와 디자인 품질은 fixture 검사만으로 보장하지 않는다. 실제 모델·시각 검증이 남아 있다.
- 오류가 잡힌 업로드·저장 실패에서는 파일 정리를 시도한다. 프로세스 강제 종료나 정리 API 자체 실패로 남은 파일은 운영 저장소 대조가 필요하다. 저장 문서에 연결된 파일을 자동 삭제하는 GC는 추가하지 않았다.
- 폰트 토큰의 이름만으로 웹폰트 파일을 다운로드하지 않는다. 해당 폰트 자원이 별도로 제공되어야 실제 글꼴로 표시된다.

## 로컬 검증

현재 로컬 결과: Admin·미리보기·Nuxt 빌드 성공, 범위 한정 24개 검사 통과. 이미지 실패 후 새로고침·채팅 재시도와 완료 에셋 보존도 추가 검증했다. 실제 공급자·Neon·Blob·Vercel Preview 검증 결과는 아니다.

다음을 실행해 계약·등록 토큰·승인·추가 대화·자동 이미지 준비·실패 재시도·반응형 출력의 회귀를 확인한다.

```bash
pnpm run build:token-policy
pnpm run build:admin
pnpm run build:visual-editor
pnpm run build:nuxt-runtime
PGLITE_TEST_MODULE=/path/to/@electric-sql/pglite/dist/index.js \
CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium pnpm run qa:design-preview
```

- 신규 브라우저 사례: 와이어프레임 → 승인 → 이미지 공급자 실패 → 채팅 재시도 → 이미지·배경·gradient·아이콘·보더·크기·색상 → 3개 화면 품질 검사.
- 승인 전후 동일한 노드의 너비·컬럼·간격·padding을 비교한다.
- renderer 버전 1·2의 공개 계약과 CJS/ESM 레지스트리 일치를 검사하고, 새 토큰 스타일을 SSR·hydration·JavaScript 비활성 상태에서 확인한다.
- 등록 후보 수가 늘어나도 기존 문서의 토큰 역할이 무효화되지 않는지 확인한다.
- PGlite 0.5.16에서는 실제 SQL과 jsonb 저장·재조회, 작업 완료 원자성, migration 090 반복 적용을 확인한다. Neon 실환경 검증과는 구분한다.
- GitHub Actions 파일은 추가했지만 원격 실행 결과와 main의 필수 체크·보호 설정은 확인하지 못했다. 이 워크플로가 Vercel Production 배포를 직접 차단한다고 주장하지 않는다.

### 기존 실패와 구분

`test-item-components-design-tokens-contract.js`는 `--promo-accent`의 AI 선택 가능 여부에서 실패한다. 변경 전 기준 커밋 ac6acde를 별도 디렉터리에서 실행해 동일한 실패를 확인했다. 이 구식 fixture 문제를 이번 코드의 회귀로 보고하지 않으며, 전체 저장소 테스트가 통과했다고도 표현하지 않는다.

## 배포 상태

- 실제 LLM·Neon·Blob·Vercel Preview 통합 검증: 미실행. 연결 불가라는 사용자 답변을 받음.
- 사용자 한시적 예외 승인(2026-11-12): 이번 개선본 `e952f3d`는 실제 Preview 통합 검증을 생략하고 Production 반영을 진행한다. 이후 배포에는 기존 검증 정책을 유지한다.
- Production: main 반영을 통한 자동 배포 요청 예정. 실제 Vercel Ready 상태는 별도 확인해야 하며, 이 기록은 배포 완료를 의미하지 않는다.
- 운영 DB migration 090 적용 여부, 활성 프롬프트·모델·토큰 정책의 실환경 호환성은 미검증 상태다.
- 새 이미지 준비를 끄는 설정: `PAGE_SCHEMA_MEDIA_PREPARATION_ENABLED=false`. 기존 연결 이미지와 문서는 보존되며, 미연결 이미지가 있는 문서의 출력 검증을 우회하지 않는다.
- 롤백은 먼저 새 실행 기능을 끄는 방식으로 진행한다. 새 rendererVersion 2와 등록 역할을 해석할 수 없는 이전 코드로 단순 복귀하면 새 문서를 읽지 못할 수 있다.

운영 검증을 완료하면 실제 기준 커밋, Preview URL, DB·프롬프트·모델·토큰 버전, 공급자 지연·사용량, 검사 결과, Production Ready 상태를 이 문서에 추가한다.

## 이미지 미생성 후속 점검 (2026-11-12)

- 로컬 재현: 승인된 미연결 이미지 문서를 요청 요약 탭에서 복원한 뒤 디자인 미리보기로 전환해도 media API가 호출되지 않았다. 이미지 준비 중 새로고침하면 승인된 문서가 render_ready로 복원되지 않아 자동 준비가 멈췄다.
- 원인: 자동 준비 watcher가 실제 실행 조건 대신 문서·revision·stage 등 일부 값만 감시했다. 탭 전환·채팅 애니메이션 종료·초기화 완료 등 잠금 해제는 재평가를 보장하지 않았다.
- 수정: 실행 가능 여부의 모든 반응형 조건을 감시하고, 초기화가 끝난 후에 실행한다. 서버의 승인 상태로 작업 단계를 복원하여 대기 이미지 요청을 재개한다.
- 로컬 브라우저 회귀 사례: 탭 전환 후 자동 준비, 준비 도중 새로고침과 환영 채팅 애니메이션 종료 후 자동 재개, API 오류 후 채팅 재시도, 완료된 이미지의 유지. 실제 운영 장애 원인의 확정 또는 실제 LLM·Blob 검증 결과로 간주하지 않는다.
- 운영 확인 필요: 배포 커밋, pageSchema.mediaRequests 내용, PAGE_SCHEMA_MEDIA_PREPARATION_ENABLED, media API 응답, BLOB_READ_WRITE_TOKEN, 이미지 프롬프트·모델 활성 설정. migration 090은 borderStyle 허용만 담당하며 이미지 생성 기능을 활성화하지 않는다.
