## 확인한 핵심 사례

- 측정상 차단 오류가 없는 페이지도 모델 어댑터를 호출하고, 허용 수정안을 적용한 뒤 브라우저 재검사를 거쳐 인증한다.
- 수정안의 미등록 토큰, 문구 변경 필드, 알 수 없는 노드, 중복 수정, 보정 종류와 맞지 않는 필드를 거부한다. 잘못된 결과로 원본을 덮어쓰지 않는다.
- 관련 수정 없이 모델이 해결됐다고 주장한 차단 항목은 미해결 상태로 남긴다. 미정 사실·CTA URL은 안내 항목으로 유지한다.
- 문구·사실·source·완료 이미지와 자산 ID를 보존한다. 구조 변경은 기존 구성 승인으로 돌아가며, 승인 후 저장된 검토와 이미지를 재사용한다.
- 같은 문서의 진행 작업 polling과 저장 결과 재사용을 확인했다. 오래된 로컬 응답이나 검토 도중 발생한 다른 수정을 덮어쓰지 않는다.
- PGlite에서 092 반복 적용, Draft 단일 생성, 활성 기획 모델 설정 복사, 스킬 자동 연결 없음, 실제 프롬프트 조합, 작업/검토 Revision 원자 저장과 jsonb 왕복을 검증했다.
- 검토 대상이 바뀐 뒤 이전 검토로 출력 인증을 시도하면 거부한다. 동시 수정 충돌 후 실행 잠금이 남지 않는 것도 확인했다.
- 모델 설정 미완료 시 통과로 표시하지 않고 채팅 오류와 재검사를 제공한다. 설정 복구 후 재검사가 진행된다.
- 기존 이미지 준비·실패 재시도, 토큰 재연결, 자연어 수정, 구성 승인, 반응형 렌더링과 SSR 검사가 통과했다.

## 외부 통합 검증의 한계

- 현재 클라우드 실행 환경 상태를 새로 조회했다. 연결 비밀 설정과 runtime variable은 각각 0개다. Vercel 프로젝트의 환경 변수 유무를 의미하지 않는다.
- 운영 URL에 새 연결을 시도했으나 환경 프록시의 CONNECT 403으로 접속하지 못했다.
- 모델 응답은 fixture/어댑터로 검증했다. OpenAI 실제 응답, 비용·지연, 운영 모델의 스키마 수락과 실제 디자인 개선 품질은 확인하지 못했다.
- SQL 검사는 실제 PostgreSQL 호환 엔진인 PGlite에서 실행했다. 운영 Neon의 migration/프롬프트 활성 상태를 확인하거나 수정하지 않았다.
- 전체 저장소 테스트 통과 또는 Production/Preview 배포 완료를 의미하지 않는다. 이 결과만으로 AGENTS.md의 실제 Preview 통합 검증 조건을 충족했다고 처리하지 않는다.
