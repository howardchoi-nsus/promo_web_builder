# 채팅 경험 개선 계획

## 범위와 구현
1. 이전 CTA를 표시하고 클릭에 응답한다. 과거 요청은 재실행하지 않고 현재 결과 및 다음 가능한 행동을 안내한다. 자동 제작에는 단계 승인을 추가하지 않으며 기존 수동/레거시 승인 흐름만 호환 유지한다.
2. 상태 메시지에 여정 단계와 CSS mask reveal을 표시한다. 모션 감소 설정을 존중하고 표시 애니메이션은 생성·입력을 잠그지 않는다.
3. 자동 제작은 총4개 서비스 단계와 현재 작업 설명을 표시한다. 단계에 처음 진입하면 새 메시지를 추가하고 같은 단계의 상태/설명은 기존 표시 행에서 갱신한다. 저장 이벤트는 보존하고 재열람 시 같은 단계 키와 안정된 ID로 조립한다. 종료된 단계는 마지막 설명과 완료/실패 상태를 유지한다. 내부 호출/재시도 횟수로 총 단계를 늘리거나 임의 진행률/ETA를 만들지 않는다.2026-11-25 확정 세부 기준은 통합 계획41절이 우선한다.
4. 일반 채팅 입력창을 내용에 맞춰 최대 180px까지 위로 확장하고 이후 내부 스크롤한다. 전송 시 축소하고 한글 조합 Enter는 전송하지 않는다.
5. 발송된 사용자 메시지의 텍스트를 오른쪽 정렬하며 문자 방향은 변경하지 않는다.
6. 사용자 말풍선은 내용 폭과 최대 폭을 사용한다. 긴 문장은 줄바꿈한다.

## 검증
- 순수 함수 회귀: 단계별 행 추가·동일 단계 갱신·중복/지연 억제·과거 CTA 판별. 기존 수동 흐름의 측정 ETA 계약은 보존한다.
- Visual editor 빌드 및 기존 페이지 생성/승인 브라우저 회귀.
- 실제 LLM·운영 DB·Preview 연결은 별도로 검증하며 모의 테스트로 대체 완료 처리하지 않는다.
- 이번 요청은 개발 범위이며 Production 배포는 포함하지 않는다.

## 검증 결과
- Visual editor 빌드 통과.
- 채팅 경험 계약, 채팅 workspace 핸들러·계약 통과.
- PageSchema 여정 브라우저: 과거 CTA 무중복 실행, 진행 이력 추가, 입력창 확장, 한글 조합 보호, 말풍선 폭·정렬, reduced motion 확인.
- Hallmark 대화 여정 및 디자인 미리보기 이미지 재시도·자동 품질검사 브라우저 회귀 통과.
- ETA 관측치는 기존 수동 흐름의 앱 실행 중에 수집한다. 메타데이터는 보존하지만 자동 제작 화면에는 계산 중/추정 ETA를 표시하지 않는다. 사용자 세션 간 평균을 산출하는 운영 통계 기능은 포함하지 않는다.
- 실제 LLM·Neon·Blob 및 배포 환경은 미검증. Production 배포하지 않음.

## 2026-11-25 후속 구현

총4단계/현재 단계와 실제 작업 설명, 같은 단계의 안정된 표시 ID·문구 갱신, 현재 설명의1.8초 Mask Reveal 연속 재생을 구현했다. 단계별 기존 메시지를 보존하며 실패/복구 UI는 별도로 유지한다. 기존 서버 API의 최상위 메타데이터 형식과 로컬 캐시의 중첩 형식을 모두 읽고 긴 대화에서 최초 사용자 메시지가 캐시 범위를 벗어나도 단계 ID를 복원한다. 원본 이벤트 저장·관리자 로그·생성/품질/출력 게이트는 유지한다. 검증 상세와 최종 회귀 결과는 통합 계획41절에 기록한다.

후속 디버깅에서 최신500개 이력 복원·기능 설정 조회 전 원본 상태 비노출·동일 밀리초 이벤트의 발생 순서 복원을 보강했다. 재현 근거와 검증 범위는 통합 계획42절을 따른다. 원본 상태 기록은 삭제하지 않고 신규 DB migration이나 운영 프롬프트 변경은 없다.

최종 빌드와86개 로컬 회귀 통과 후 사용자 배포 요청으로 Production 대상 main에 반영한다. 운영 실연동/실제 Vercel Ready 확인은 소스 반영과 별도로 보고한다.
