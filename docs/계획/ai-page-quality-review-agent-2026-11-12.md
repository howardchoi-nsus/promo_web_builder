# AI 자동 품질 검토·수정 에이전트

## 처리 흐름

페이지 구성 승인 → 이미지 준비 → 화면별 브라우저 검사 → 필요한 코드 기반 보정 → LLM 품질 검토·허용 수정안 적용 → 브라우저 재검사 → 통과 시 새 창 보기·출력 활성화.

- 코드 검사에서 문제가 없어도 아직 검토되지 않은 페이지는 LLM이 검토한다.
- 동일 PageSchema·콘텐츠·토큰·미디어 맥락의 저장된 검토는 재사용한다. 재승인·새로고침 때문에 LLM을 중복 호출하거나 이미지를 다시 생성하지 않는다.
- 코드 보정 최대 2회, 성공적으로 저장되는 AI 검토 라운드는 한 생성 여정에 최대 2회다. 오류 응답은 현재 실행을 중단하고 채팅에서 재시도할 수 있게 표시한다. 클라이언트 검사 루프도 유한 횟수로 제한한다.
- 구조가 달라지면 기존 페이지 미리보기·구성 승인으로 돌아간다. 별도 품질 승인 폼을 만들지 않는다. 스타일 변경은 자동 적용 후 재검사한다.

## 에이전트의 입력과 수정 권한

- 현재 PageSchema, 등록 토큰·중앙 사용 정책·허용 노드, 실제 브라우저의 viewport별 크기 측정과 진단, 이전 검토 내역을 전달한다.
- 이 버전은 스크린샷을 모델에 전달하지 않는다. 구조·측정값에 대한 LLM 검토와 브라우저 픽셀/대비 검사를 구분한다. 모델이 실제 브라우저나 보지 않은 이미지를 검사했다고 주장하지 않도록 프롬프트에 명시한다.
- 구조화 JSON Schema로 기존 노드의 스타일 역할, 등록 spacing, 허용 layout, 이미지 content/background 표시, 등록 overlay만 제안한다. 수정 이유와 미해결 항목을 함께 받는다.
- 문구·사실·source ID·노드 ID/순서/중첩·자산 ID/파일·URL·동작·폼 바인딩은 수정할 수 없다. HTML/CSS, 새 토큰, 새 노드, 임의 크기 값도 받지 않는다.
- 서버가 모델 응답 형태·중복 보정·대상별 역할과 토큰·수정 후 전체 PageSchema를 검증한다. 관련 수정 없이 차단 항목을 해결했다고 표시해도 서버가 미해결로 보존한다.
- 누락된 사실·CTA URL은 안내 항목으로 유지한다. 이 정보만으로 새 생성 조건을 만들거나 모델이 URL을 창작하지 않는다.

## Admin과 운영 적용

1. 기존 문서/작업 DB migration 086·088이 필요하다. 스킬 연결에는 별도로 091이 필요하다.
2. `db/migrations/092_page_quality_review_prompt.sql`을 적용한다. 활성 `promo_page_schema_planner`가 없으면 오류로 중단한다. 현재 등록 모델·provider 설정을 복사해 `promo_page_quality_reviewer` **Draft 한 개**를 생성한다. 이미 이 유형이 있으면 추가 생성하지 않는다.
3. Admin → 프롬프트 관리 → **10단계 AI 품질 검토·수정**에서 검토하고 기존 검증·활성화 절차로 활성화한다. 기본 모델을 코드에 하드코딩하지 않았다. 마이그레이션은 기존 프롬프트나 스킬 연결을 자동 교체·복사·활성화하지 않는다.
4. 필요하면 검토용 MD 스킬 버전을 이 프롬프트에 명시적으로 연결한다. 스킬의 실행/내용 해시도 검토 기록에 포함된다.
5. `PAGE_QUALITY_REVIEW_AGENT_ENABLED` 기본값은 true다. 새 프롬프트 미설정/비활성/모델 오류 시 고객 화면은 원인을 안내하고 통과로 처리하지 않는다. Production 반영 전에 migration·활성 프롬프트 준비를 함께 완료해야 한다.
6. false는 새 실행을 코드 기반 검사로 되돌리는 스위치다. 이미 AI 검토 필수로 저장된 문서의 미해결/오래된 검토를 우회해 출력하도록 만들지는 않는다. 해당 문서는 검토 완료 또는 명시적인 새 생성이 필요하다.

## 저장·중복 방지

- 소유 문서·Revision·요청 요약 버전을 확인하고, 기존 generation job의 임대/단일 실행 잠금을 재사용한다.
- 검토 내용·수정안·프롬프트/모델/스킬 버전·요금 사용량과 검토 결과를 DB Revision 및 작업 완료 상태와 원자적으로 저장한다. 사실 콘텐츠와 완료 자산은 보존한다.
- 검토 대상 지문은 PageSchema와 pageContext를 함께 포함한다. jsonb 정렬에 영향을 받지 않는다. 저장 후 페이지가 변경되면 이전 검토로 품질 통과/출력을 인증할 수 없다.
- 클라이언트는 진행 중인 작업을 polling하고, 문서나 로컬 Revision이 바뀌면 이전 응답을 덮어쓰지 않는다. 늦게 도착한 서버 결과도 DB CAS에서 거부한다.

## 검증

- Admin·visual-editor·Nuxt 빌드 성공.
- 범위 한정 검사 29개 통과. 별도 worker 프롬프트 계약, 후보 실행, Admin 그룹 및 런타임 프롬프트 관리 검사도 통과했다.
- 새 계약/서비스 검사: 불허 토큰·문구 필드·노드·중복 수정 거절, 미해결 보존, 사실 정보 안내 처리, 소유권·CAS·재사용·진행 중 polling·잘못된 응답 보존·구조 재승인·최대 라운드.
- PGlite 검사: 092 반복 적용과 Draft 생성, 현재 모델 설정 복사, 스킬 자동 연결 없음, 실제 프롬프트 조합, 작업/검토 Revision의 원자 저장, jsonb 왕복 후 재사용, 변경된 검토의 출력 거부, 검토 중 다른 수정 발생 시 저장 거부.
- 브라우저 검사: 측정상 오류가 없는 페이지도 모델 어댑터 호출 → 제한된 수정 → 실제 재검사 → 통과; 미설정 오류에서 차단 후 복구; AI 구조 수정 → 기존 구성 승인 → 검토 재사용과 완료 이미지 보존.
- 모델 어댑터는 fixture 응답으로 검증했다. 실제 LLM·Neon·Blob·Vercel Preview 검증이나 Production 배포 완료를 의미하지 않는다. 운영 migration/프롬프트 활성화 및 실제 모델 검증은 미실행이다.
